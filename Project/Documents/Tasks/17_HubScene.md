## 1. 世界観の決まりごと

神秘と機構は「機械仕掛けの天使」として両立させる（参考：ウイングガンダムゼロ EW・天空の城ラピュタ・原神の遺跡守衛・ゼノブレイドの機神界・エヴァの格納庫）。

1. **素材は大理石と金**（タイトルの扉と同じ）。機体も白い装甲に金の縁取り。配管・錆・油汚れのような工業的なものは出さない
2. **機構は時計・天球儀のような機構**（回る金の輪・精密な歯車・継ぎ目を走る光の線）。工場の機械にしない
3. **機械は古代の遺物**として扱う（「神殿に眠る機械仕掛けの天使」）
4. **自然と同じ画面に置く**（水・雲・空・羽根・植物）。機械だけの絵にしない
5. **光の色**：**外の世界（神殿・空）は白と金**、**機体の中（コクピット・UI）は緑のネオン**。扉（胸の装甲）を境に神秘と機構が切り替わる対比にする。**神殿はパルテナの神殿に寄せた淡い虹色（薄紫・ピンク・水色）も使う**（2026-10-14 ユーザー決定。窓・垂れ幕・大階段・床の黄道の帯・大理石の筋）

扉が境目（パルテナの出撃と同じ考え方）：

| 扉 | 境目 |
|---|---|
| タイトルの扉 | 現実 → 神殿 |
| 機体の胸の装甲 | 神殿 → 機体の中 |
| （来週）カタパルトの先 | 機体の中 → 戦場 |

### 2.1 D で作ったもの（2026-10-14 作り直し。ビルド・実機未確認）

**床（H2）**：`WaterSurface` を「磨いた大理石」として使う（エンジンの変更なし）。水深 0.002m・屈折率 1.0（模様がずれない）・波とノイズは 0。模様（`HubFloor_BaseColor`、4096²：中央の紫紺の円と羅針・淡い虹色の黄道の 12 区画と八芒星・24 分割の薄紫の市松・星）は原点がテクスチャの角に来るように描いてあり、`floorTiling = 1/44` で中心がそろう。映り込みは `WaterReflection`（解像度 0.5 で少しぼかす）に神殿・門と動く部分・輪・扉・機体の 3 つを登録。映らなかった所は神殿の IBL を引く。

**IBL**：機体を除いた神殿を機体の胸の位置 (0, 12, 0) から Cycles の正距円筒で撮り（1024×512）、平均の明るさを 0.45 にそろえて `Assets/hub_temple_ibl.hdr` → `Resources/Cubemaps/hub_temple_ibl.dds`。カメラの向きはタイトルの空（`gen_title_sky.py`）と同じ。**方位がエンジンとそろっているかは実機の映り込みで確かめる**。dds が無ければタイトルの空の IBL を使う。

**エンジン側**：`Game/Scene/Hub/HubTemple`（殻・時計の門と動く部分・輪・扉・鏡の床・IBL のパス）。`HubScene` は仮の石畳の板 3 枚をやめて `HubTemple` を置き、表示板の RT の後に反射 RT を描く。調整値は `Hub.json` の `"temple"`（扉の位置と大きさ・門の針と歯車の速さの倍率・床の反射率（既定 0.2）と環境光・輪の傾きと回転の速さ）。乗り込み・降りるのカメラのキーの既定値も足場に合わせて直した（`HubBoardingSequence` / `HubDisembarkSequence`。手元の `Hub.json` にキーを保存していたらそちらが使われる）、ImGui は Hub Tuning →「Temple (17 H1/H2)」。`HubMechModel::GetBody()` を足した（床に映すため）。

罠・注意：
- 足場の上面と回廊の床が同じ高さで重なると z ファイティングで黒い線が出た（プレビューで発見）。今は足場の上面を踊り場より 5mm 高くしている
- **タイトルの扉が HUB で見えなかった**（2026-10-14 実機）：扉のモデルはファイル名でタイトルと共有し、マテリアルにタイトルのディゾルブ（タイトルの水面の高さ基準で「ここより上は消す」）が残っていた。踊り場の上に置くと全部消える。`HubTemple::ApplyDoor` で `dissolveEnable = kDissolveOff`・`cloudReflection = 0` に戻す。また表の面を神殿へ向けるため yaw を π にした
- 扉の環境光の強さもタイトルの値（大理石 0.25・金 0.56）が共有のマテリアルに残り、太陽を背にした HUB の扉が暗い灰色になった。`ApplyDoor` で HUB の値（`Hub.json` の `"temple"` の `doorMarbleEnv` / `doorGoldEnv`、既定 1.0）に戻す
- **配布の exe で HUB が暗く青かった**（2026-10-14）：IBL の有無を `std::filesystem::exists` で確かめていたため、pack の中にしか無い配布物ではタイトルの空の IBL に落ちていた。`AssetLocator::Exists` に直した
- **さらに扉は `Update()` を初期化時の 1 回しか呼んでいなかった**（`Object3DInstance` は Update の時のカメラで WVP を作るので、初期化時の行列のまま画面の外に描かれていた）。動かない物も毎フレーム `Update()` する
- 前の版の機体の手の位置の数値（指先 z 5.6）は誤りで、実際の手のいちばん前は z 3.69（glTF の頂点から測った）
- cook は glTF の V を反転するので、書き出し後に `flip_texcoord_v`（本の UV がずれないように）。そのため `--with-mech` のプレビューは機体の UV が逆になり迷彩模様に見える（プレビューだけの問題）
- 光の柱（丸窓から差す光）は未実装（`LightShaftEffect` は画面上に光源が要るので真上の丸窓には使えない。作るなら加算の半透明の板）

### 5.1 HUB 用の機体（2026-10-13 完成・書き出し済み）

罠：
- Tripo の部位番号は左右で対応していない（左右で分割のされ方が違う）。左右の一覧は目で見て決めた
- 腕が短い（肩から手首まで全高の約 18%）。前腕は開口部の縁の下を通れないので、前腕は開口部の横に置き、手を縁の下へ横向きに渡している
- 内枠を平らな板にするとハッチ（曲面）と当たる。内枠は軸が後ろの大きい円柱の一部にして、ハッチはその裏を回る
- **cook は glTF の V を必ず反転する**（`v = 1 - v`。自作スクリプトは逆向きの UV を書いて打ち消している）。Blender の glTF の UV はもともと正しい向きなので、そのままだとアトラスの島が別の場所を拾って迷彩のようになる。`rig_hub_mech.py` は書き出した直後に TEXCOORD_0 を `1 - v` に書き換える（`flip_texcoord_v`、2026-10-13）。Blender から書き出す他のアトラスのモデルも同じ対処が要る
- **エンジンは metallicRoughnessTexture を読まない**。Tripo の glTF は係数を書かないので、cook が glTF 既定の金属度 1.0・ラフネス 1.0 を `.mat` に入れ、機体が暗く青灰色にくすんだ（完全な金属は色が映り込みだけになる）。`rig_hub_mech.py` が書き出し時に `HubMech_rm.png` の中央値（アトラスの空きを除く）を `metallicFactor` / `roughnessFactor` に書く（`write_pbr_factors`、2026-10-13。今は金属度 0.043・ラフネス 0.671）。部位ごとの金属の差は出ないので、要るならエンジンに金属度・ラフネスのテクスチャ対応を足す（別作業）
- **機体の色がくすんでいた本当の原因は cook（2026-10-14）**：このプロジェクトの PNG は sRGB チャンクを持たないので、`texconv -f BC7_UNORM_SRGB` が中身を線形とみなして sRGB へもう一度変換していた（色の平均が PNG (92,100,112) → DDS (153,160,170)。紺が明るい灰色・金が薄い黄色に）。`cook_assets.py` の `SRGB_INPUT_HINTS`（今は `"HubMech"` だけ）に当たるパスは `-srgbi` を付けて変換する。**ほかのテクスチャも全部同じく持ち上がっている**が、今の見た目はその色で調整してあるので提出までは触らない（直すならヒントを外して全部に効かせ、見た目を調整し直す）。光沢は `Hub.json` の `"mech"`（`bodyRoughness` 既定 0.35・`bodyMetallic` 0.05）で本体の .mat の値を上書きする
- cook は `.glb` を扱わない（`UNKNOWN`）。必ず `--export` で glTF＋PNG にしてから。cook を全体で回すと関係ないシーンの layout まで作り直すので、今回は HubMech の 6 ファイルだけ変換した
