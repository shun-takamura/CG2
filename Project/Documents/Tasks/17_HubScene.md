## 1. 世界観の決まりごと

神秘と機構は「機械仕掛けの天使」として両立させる（参考：ウイングガンダムゼロ EW・天空の城ラピュタ・原神の遺跡守衛・ゼノブレイドの機神界・エヴァの格納庫）。

1. **素材は大理石と金**（タイトルの扉と同じ）。機体も白い装甲に金の縁取り。配管・錆・油汚れのような工業的なものは出さない
2. **機構は時計・天球儀のような機構**（回る金の輪・精密な歯車・継ぎ目を走る光の線）。工場の機械にしない
3. **機械は古代の遺物**として扱う（「神殿に眠る機械仕掛けの天使」）
4. **自然と同じ画面に置く**（水・雲・空・羽根・植物）。機械だけの絵にしない
5. **光の色**：**外の世界（神殿・空）は白と金**、**機体の中（コクピット・UI）は緑のネオン**。扉（胸の装甲）を境に神秘と機構が切り替わる対比にする

扉が境目（パルテナの出撃と同じ考え方）：

| 扉 | 境目 |
|---|---|
| タイトルの扉 | 現実 → 神殿 |
| 機体の胸の装甲 | 神殿 → 機体の中 |
| （来週）カタパルトの先 | 機体の中 → 戦場 |

## 2. 神殿：天球儀の聖堂

- パンテオンのような**円形のドーム**。天井の丸窓から空の光の柱（`LightShaftEffect` を流用できるか確認）
- 床は**鏡のように映り込む大理石**（10 番の反射の仕組みを床に使い、少しぼかす）
- 中央に **HUB 用の機体が立ち**、右手の手のひらを胸の開口部の下へ差し出している（片膝立ちは不採用、§5.1）。胸のハッチは**開いて待っている**
- 整備用の足場の代わりに、**巨大な金の天球儀の輪**が機体のまわりをゆっくり回る（＝機構）
- 壁は天井まで届く**書庫の本棚**とらせん階段
- 後ろ（入ってきた方）に**タイトルの扉を内側から見たもの**
- 作り方：柱・本棚・ドームの区切り・輪は Blender スクリプトの手続き生成で部品にする（輪はトーラスを並べるだけ）。機体以外は AI 生成を使わない
- **作業場（格納庫）に見せない**。金属の足場は置かない。手のひら（地上 約10.6m）へは **2 階の回廊から渡る**（2026-10-13 決定。HUB の視点は最初から回廊の上。18 番 ①）。**回廊の縁から手のひらの手前へ石の足場（ブリッジ）を伸ばし、HUB の視点はその上**（2026-10-13 ユーザー決定。金属ではなく神殿と同じ石で作る。今は仮の石畳の板）

## 5. モデル

| モデル | 中身 | 使う所 | 状態 |
|---|---|---|---|
| ① HUB 用の機体 | Tripo で生成した全身（胸のハッチが開いた形）。立ったまま右手を開口部の下へ差し出したポーズを焼き込み、AI のコクピットは取り除いて、スクリプトで作ったコクピットとハッチに置き換える | HUB（神殿）、ステージ選択（コクピットの内側） | **書き出し・cook 済み（2026-10-13）**。エンジンでの表示は未確認 |

作り方（両方共通）:
- AI 生成（Tripo）。**Tripo の部位分割（パーツ数が多い版）を書き出し、部位をボーンごとのグループにまとめる**（自分で切らないので切り口の穴が出ない）。部品ごとに 1 本のボーンへウェイト 1.0（リジッドスキニング）。自動リグのウェイトは使わない
- 「部位 → ボーン」の対応はスクリプトの表で持ち、作り直せる形にする
- **ウイングゼロに似せすぎない**（動画は公開される）／**AI 生成物のライセンス**（商用の扱い）を確認してから使う
- ポリゴン数の目安：自機 3〜5万・ボーン 64 本以内（8 番 §4.3 のアニメの CPU 負荷がボーン数に比例するため。施策 A を入れれば気にしなくてよい）。HUB 用は今のまま（約 47万）で可（2026-10-13 ユーザー決定）

### 5.1 HUB 用の機体（2026-10-13 完成・書き出し済み）

スクリプト：`tools/BlenderPipeline/rig_hub_mech.py`（Blender 4.4 を `-b --factory-startup -P` で。`--preview <フォルダ>` / `--export <フォルダ>` / `--save <.blend>`）

```
blender -b --factory-startup -P tools/BlenderPipeline/rig_hub_mech.py -- --export Assets/Models/HubMech/Export
```

| 項目 | 内容 |
|---|---|
| 元のモデル | `Assets/Models/HubMech/HubMech.glb`（Tripo、部位 126 個、約 47万三角形、4K テクスチャ） |
| ポーズ | **二本足で立ったまま**、右手（モデルの右＝ -X 側）の手のひらを上へ向けて**胸の開口部の下の縁のすぐ手前**へ差し出す。手は止まったまま（アニメーションなし）。片膝立ちは脚の開き方が不自然で不採用 |
| 大きさ | **翼と翼の後ろの板を除いた体の高さ＝18m**（元の 1 単位＝19.75m）。翼の先は約 19.3m |
| 取り除いた部位 | AI のコクピット（21・40・47・62・93）、開口部の左右のとがった飾り（74・82） |
| ボーン | 腕・脚・翼・翼の後ろの板の 17 本で組んでポーズを付け、**書き出し時にメッシュへ焼き込む**（書き出すのは静的なメッシュ。`.skel` なし） |
| コクピット | 横に倒した円柱（直径 2.2m・幅 2.0m）。内側はモニターの板、左右の壁は切り欠きの輪、座席・ひじ掛けと操縦桿（緑の輪）・ペダル 2 枚と光の帯・左右の操作盤。出入り口は幅 1.4m×高さ 1.8m。AI の開口部（幅 約2.2m×高さ 約3.1m、前へ膨らむ曲面）の裏に沿う紺の**内枠**と、その裏を囲う箱（後ろが透けないように） |
| ハッチ | コクピットと同じ軸の円柱の一部の**なめらかな曲面の板**。下の縁は台形の切り欠きで、**動かない下の板**（同じ半径・上の縁に台形の出っ張り）にはまる（ユーザーのスケッチ）。合わせ目の両側に金の帯 |
| 書き出し | `Assets/Models/HubMech/Export/` に glTF 3 つ＋テクスチャ PNG 3 枚（**2K に縮小**。4K だと push できない）→ cook で `Resources/Models/HubMech/Export/` |
| ポリゴン数 | 本体 約 45万三角形（`.mesh` 19MB）、コクピット＋ハッチ 約 2.7万 |
| 質感 | 本体は 4K→2K の色・法線（`HubMech_NormalMap`、PBR）・ラフネス。コクピットとハッチは単色（紺・金・暗い金属・座席・緑・白）。**エンジンのマテリアルに発光が無いので、緑は明るい色なだけ**（光らせるなら cook で glTF の extras から「ライティングなし」を指定できるようにするか、エンジンに発光を足す。別作業） |

**エンジンで使うときの数値**（cook は glTF の X を反転するだけ。Blender の (x, y, z) はエンジンで (−x, z, −y)、正面はエンジンの +Z）:

| 項目 | 値 |
|---|---|
| 3 つのモデルの置き方 | `HubMech` と `HubMech_Cockpit` は**同じ位置・回転**に置く（原点＝足元の中央） |
| ハッチ | `HubMech_Hatch` は**原点＝回転の軸**。本体の原点からの位置はエンジン座標で **(0, 12.343, 1.165) m**（Blender の (0, −1.165, 12.343)） |
| 開け閉め | 閉じた形で書き出してある。**X 軸まわりに −115°（Blender での値）で開いた状態**。エンジンでの回転の向き（符号）は実機で確認すること |
| 座ったパイロットの目 | コクピットの軸から Blender で (0, 0.18, 0.20) m（エンジンでは (0, 0.20, −0.18)） |
| 手のひら | 元のモデルの (0, −0.150, 0.535)＝18m 換算で Blender (0, −2.96, 10.57) m 付近 |

罠：
- Tripo の部位番号は左右で対応していない（左右で分割のされ方が違う）。左右の一覧は目で見て決めた
- 腕が短い（肩から手首まで全高の約 18%）。前腕は開口部の縁の下を通れないので、前腕は開口部の横に置き、手を縁の下へ横向きに渡している
- 内枠を平らな板にするとハッチ（曲面）と当たる。内枠は軸が後ろの大きい円柱の一部にして、ハッチはその裏を回る
- **cook は glTF の V を必ず反転する**（`v = 1 - v`。自作スクリプトは逆向きの UV を書いて打ち消している）。Blender の glTF の UV はもともと正しい向きなので、そのままだとアトラスの島が別の場所を拾って迷彩のようになる。`rig_hub_mech.py` は書き出した直後に TEXCOORD_0 を `1 - v` に書き換える（`flip_texcoord_v`、2026-10-13）。Blender から書き出す他のアトラスのモデルも同じ対処が要る
- **エンジンは metallicRoughnessTexture を読まない**。Tripo の glTF は係数を書かないので、cook が glTF 既定の金属度 1.0・ラフネス 1.0 を `.mat` に入れ、機体が暗く青灰色にくすんだ（完全な金属は色が映り込みだけになる）。`rig_hub_mech.py` が書き出し時に `HubMech_rm.png` の中央値（アトラスの空きを除く）を `metallicFactor` / `roughnessFactor` に書く（`write_pbr_factors`、2026-10-13。今は金属度 0.043・ラフネス 0.671）。部位ごとの金属の差は出ないので、要るならエンジンに金属度・ラフネスのテクスチャ対応を足す（別作業）
- cook は `.glb` を扱わない（`UNKNOWN`）。必ず `--export` で glTF＋PNG にしてから。cook を全体で回すと関係ないシーンの layout まで作り直すので、今回は HubMech の 6 ファイルだけ変換した
