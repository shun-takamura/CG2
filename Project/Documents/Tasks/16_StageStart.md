## 1. 決まったこと（2026-10-15 ユーザー決定）

| 項目 | 決定 |
|---|---|
| スタート演出 | カタパルト発進。カタパルトに着いてから発進までに、マウスやキーで機体確認をして UI を出し、発進 OK になったら SPACE で推進システムを吹かして発進（没入感） |
| ③（HUB → ステージ） | 機体に乗ったまま、機体の足元の神殿の床（リフト）が下がってカタパルトの位置まで行く。その途中でシーンを切り替える |
| リフトの形 | **円ではなく、角を落とした四角形（正方形に近い八角形）**。縦穴の断面も同じ形（参考：縦穴を真上から見た図） |
| 切れ目 | 真っ暗にしない。降下している感じを出すため縦穴の側面の板が見えたまま。**シームレスにつなぎ、後々マルチスレッドで StagePlay のロードを裏で進める**（§4） |
| 機体確認 | 操作説明を兼ねる（マウスで照準、WASD で翼のスラスター、射撃キーで武装、など） |
| 発進のカメラ | 一人称なら、そのまま降りてきた視点でトンネルの先が迫ってくる。三人称に切り替えていれば、**機体の右下前方の床近くから見上げ始め、射出される機体を追って見送る**（2026-10-18 ユーザー決定。それまでの「後方・左下」から変更。参考はアニメのカタパルト発進：床すれすれのカメラ、機体が横を通り過ぎて奥へ遠ざかる・足元に火花） |
| 射出口 | 明るい白で、タイトルの扉のように光が漏れている |
| 射出の後 | 白フェード → 雲の上で機体の左上から見るカメラ → カメラ補間で機体の左側を回り込み、今のシューティングの画面へ |

**既定にしたもの（ユーザーが違うと言えば変える）**
- 視点の切り替えは **V キー**。カタパルトに着いたときは一人称（降下からの続き）
- S4 の回り込みの間もレールは t=0 から進める。操作を受け付けるのは回り込みが終わってから
- 機体確認・発進の入力は入力アクション（`KeyConfig`）に足し、キーを直書きしない

## 2. リフトと縦穴

- **形**：正方形の角を落とした八角形。パラメータは「半分の幅」と「角を落とす量」。リフト・床の穴・縦穴の断面で同じ値を使う（スクリプトとエンジンの両方が同じ値を読む）
- **神殿の床の穴**：床は `WaterSurface`（平面 1 枚）なので、PS で**八角形の距離関数（SDF）の内側を捨てる**設定を足す（エンジンの変更。既定は穴なし＝他の水面に影響しない。ArcanaEngine へ同期が要る）。リフトが床と同じ高さにある間は穴をリフトの上面がふさぐ
- **リフトの縁**：金の直線の縁（世界観：大理石と金・時計／天球儀風の機構）。飾りは F1 で決める
- **縦穴**：同じ板の繰り返しで、照明の帯が一定の間隔で通り過ぎる。**カメラ（リフト）を止めたまま壁の模様を流す方式でも動かせる**ようにし、ロードが終わるまで何周でも降り続けられるようにする（§4）
- **大きさ**：HubMech は 18m（17 番 §5.1）。縦穴とカタパルトは HubMech の大きさに合わせる

決まったこと（2026-10-15 ユーザー）：
- 色は**まずグレーの「いかにもカタパルト」**で作る。外（神殿）と合わなければ白と金で作り直す
- 左右に**ネオンの板**。出撃できない（チェック未完了）間は HUB のハッチが開いている時と同じ赤ピンク、チェック完了で緑。**形はユーザーのスケッチで決定**：壁に縦長の板が奥へ並び、天井に横長の板が渡る（一人称／三人称の図）。全部同じマテリアル `Neon` なので、エンジンは 1 か所で色を変えれば全部が変わる（JSON は `neonMaterial`）
- **断面と射出口は八角形**（台形から変更）。斜めの面に台形のネオン（前の辺が短い）、左右の縦の壁に液晶の帯（発進不可「LAUNCH UNABLE」赤ピンク／発進可能「LAUNCH READY」緑、進行方向へ流れる）（2026-10-15 ユーザーのスケッチ）。形は `TUN_*`・`LCD_*`・`TUN_NEON_*` で変える
- 給電ワイヤーの付け根は**機体の後ろでカメラに映らない所**。今は後ろの壁の高い所 (±3, 21, −12.8)（JSON の `cableAnchors`）

罠・注意（F2 以降へ）：
- **リフトが床の高さにある間は床に穴を開けない方がよい**。八角形は直径 20m で床の中央の大半を占めるので、穴を開けるとその中の機体の映り込みが消える。上面は床と同じ模様なので、降り始めに穴を開けても違いは映り込みだけ
- リフトの上面は Object3D の PBR、床は WaterSurface の PS なので、明るさがそろうかは実機で確かめる（そろわなければ上面のマテリアルの値をエンジンで上書き）

- 板のモデル（logo_plane.mesh）は確認パネル・タコメーター・タイトル・HatchSign で共有。テクスチャは描く直前に貼る（描くときに引かれる）
- 雲の上の場面は F6。今は CloudTop に入った次のフレームでレールへ渡る（スキップの白フェードはレールに入っても開き切るまで StageStartPart が描く）
- WhiteOut は「パッと切り替える」区切りとして残っている（今は 1 フレームで CloudTop へ）

## 3. カタパルト

- 施設は Blender のスクリプトで作る（扉・神殿と同じ流儀。仮名 `gen_catapult.py`、**GUI から書き出さない**）。スケッチ：床の中央にレール、両側の壁に縦長のパネルが並び、天井に梁（給電ワイヤーを垂らすアームを付けるか決める）、先に射出口
- 参考画像の紫の窓明かりは使ってよいが、色は世界観（外は白と金、機体の中の UI は緑のネオン）と合わせて F1 で決める
- 雲の上（レール t=0）とは白で区切られるので、**ワールドの離れた所に置いてよい**（雲・フォグ・地形のロードの範囲に入らない所）

### 3.1 機体確認（S1）

- 表示板は**緑のネオン**（黄・赤を差し色に。参考画像の LAUNCH CONTROL の表示板）。C で作った `TextRenderer` の発光の層・発光パスを使う
- 項目（2026-10-19 決定、§2.4）：照準（マウス）／スラスター（W/A/S/D の 4 方向。翼には付けない。噴く場所とエフェクトは F5）／武装（射撃）＋ POWER CABLE ON-LINE（表示だけ）
- 各項目は操作すると CLEAR（白地）に変わる。全部 CLEAR → COURSE CLEAR → カタパルトのネオンが機体の位置から射出口へ緑で点き直す → LAUNCH READY / [SPACE] BOOST で SPACE を受け付ける
- 一人称のときはコクピットの中の宙に浮く板、三人称のときは画面の UI に出す（2026-10-19 決定）

### 3.2 発進（S2・S3）

- SPACE → スラスター・エンジンの点火（エフェクトは EffectEditor／`/effectgen`）→ カタパルトで加速 → 射出口へ
- 一人称：コクピットのまま、トンネルの先（射出口の白）が迫ってくる
- 三人称：カメラは右下前方の床近くに残り、向きだけ機体を追う（前から来て横を通り過ぎ、射出口の光へ遠ざかるのを見送る）。足元のレールとの間に火花（雷と一緒に F5）
- 射出口の光：タイトルの扉の `LightShaftEffect`（ID マスクの放射サンプリング）＋ポイントライト → 白フェード（`FadeTransition::SetNextFade(白)` と同じ見た目を StagePlay の中で出す）

#### 電磁カタパルトの雷（2026-10-15 追加）

- カタパルトは**電磁カタパルト**のイメージ。発進のとき、レールと機体の足元（射出台）のあいだに**雷のエフェクト**を走らせる
- 加速に合わせて、雷が射出台について走る／レールの両側に沿って光が先へ伸びる、など（形は F5 で決める）。点火の前から細かい放電を出し、SPACE で一気に強くすると「溜めて撃つ」感じになる
- 作り方の候補：EffectEditor（`/effectgen`）のパーティクル。雷の線を折れ線のメッシュ（毎フレーム頂点をずらす）で出すかは F5 で決める。発光（ブルーム）に乗せる

#### 給電ワイヤーと切り離し（2026-10-15 追加）

参考（ユーザー提供の画像）：機体の背中に赤・緑のケーブルが何本もつながり、発進の瞬間に外れてしなりながら後ろへ残る／天井のアームから垂れたケーブルが機体につながっている。

- カタパルトにいる間、**エネルギーを供給するワイヤー**が機体（背中など）につながっている。床か天井のアームから何本か（色は F1・F5 で決める）
- **発進のギリギリまで給電し、切り離す**。切り離したワイヤーは、しなりながら落ちて揺れる（機体は前へ、ワイヤーは後ろへ残る）
- 機体確認（§3.1）の項目「POWER CABLE ON-LINE」とつなげる。たとえば SPACE を押すと「POWER CABLE → 切り離し」の表示 → ワイヤーが外れる → 雷 → 加速、の順
- 作り方の候補：ワイヤーは**点を並べた簡単なひもの物理（Verlet）**で動かし、点をつないだ筒のメッシュを毎フレーム作り直す（Primitive の拡張か新しい小さな部品。置き場所は F5 で相談）。つながっている間は両端を固定、切り離しで機体側の端を離す。一人称では見えにくいので、三人称のときの見せ場にする
- つなぐ位置（機体のボーン）・本数・長さ・硬さは調整値 JSON

### 3.3 雲の上（S4）

- 白が開けると、雲の上で機体の左上から見下ろすカメラ（機体は進行方向を向いている）
- そこから機体の左側を回り込むように補間して、今のレールのカメラ（TPS）へ合わせる
- カタパルトの場面では自機を HubMech と同じ大きさで描き、**白が開けたらゲームの大きさに戻す**（白で区切られるので見えない）

## 4. 解き方（2026-10-15 検討）

### 4.1 一人称のときのモデルの食い違い

**問題**：HUB の機体（HubMech）は、コクピットがむき出しで外が見えるように胸が開いたモデル。設定では胸は閉じていて、コクピットの中のモニターに外が映っている。StagePlay で使う自機は胸が閉じたモデルで、別のボーンが入っている。

**解き方：一人称のときは機体の外側を描かず、コクピットの内装だけを独立した部品として描く**（FPS の一人称専用の描画と同じ考え方）。
- **一人称**：自機は描かない。カメラの位置にコクピットの内装（HubMech_Cockpit の円柱＋コンソールの UI）だけを描く。壁は C で作った**六角形が晴れた状態**にし、全天周のモニターに外が映っている扱いにする（六角形の継ぎ目をうっすら残すとモニターらしい）
- **三人称**：自機を描き、コクピットの内装は描かない
- 一人称の間は機体の外が一度も映らないので、HUB と StagePlay でモデルが違っても見えない。設定とも合う
- コクピットの内装・灯り（今は `Game/Scene/Hub/` の `CockpitLighting` / `CockpitConsole` など）を **HubScene と StagePlay の両方から使える共通の部品**にする（置き場所は F3 のチャットで相談）
- 一人称の目の位置：StagePlay では「自機の胸のボーン＋オフセット」。**リフトの床から目までの高さは HUB（17 番 §5.1 の目の位置）と同じ値**にする（切れ目で縦穴の見え方がずれないように）

### 4.2 シームレスな切れ目

**HubScene と StagePlay に同じ縦穴を置き、同じ見え方になるフレームでトランジションなしに差し替える。**
- 縦穴は同じ板の繰り返しなので、HubScene は**ロードが終わるまで何周でも降り続けられる**（壁の模様を流す）
- HubScene は差し替えのときに「壁の模様の位相・降下の速さ・コクピットの灯りの状態」を StagePlay に渡す。StagePlay はその値から降下を続け、カタパルトの階で減速して止まる
- 段階を分ける：
  1. **同期ロードで差し替える**（ロードの間は画面が一瞬止まるが、暗くならず流れはつながる）。組み合わせ表は `HUB` / `STAGESELECT` → `STAGEPLAY` を「覆う＝シーンに任せる・開く＝シーンに任せる」にする
  2. **裏で StagePlay をロードする**（F7）。川のマップを別スレッドで読む仕組み（13 番）・L9 のストリーミングが土台になるが、シーン全体の Initialize（各マネージャーの登録・SRV ヒープの確保・アップロード）をスレッドに対応させる必要があり、一番重い。**コンテストに間に合わなくても 1 で見せられるよう、最後に回す**

## 5. 以前の案（廃止）

2026-10-11 の案「瞼が閉じた黒（FPS）→ 目を開ける → 走って光る扉へ → 扉に入って真っ白 → TPS」は、HUB を神殿に、自機を翼のロボットにした（17 番）ので廃止した。墨 → 瞼の取り決めも無い。残すもの：リトライは飛ばす／扉の光（5 番 A-9）を射出口に流用する。
