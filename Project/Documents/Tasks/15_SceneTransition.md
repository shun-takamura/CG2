## 1. 今のトランジションの問題

### 1.1 ストライプが開くと変な絵が出て、少しすると直る

ストライプが開いている間、**StagePlay の `Draw` は動いているのに `Update` が一度も動いていない**。

1. `StagePlayScene::Initialize` の後、カメラは仮置きのまま。`SetTranslate({0,0,-20})` や `SetFarClip` を呼んでいるが、行列を作り直す `camera_->Update()` を呼んでいないので、描画に使う行列は Camera のコンストラクタの既定値（位置 (0,0,-10)・far=100m）
2. `StagePlayScene::Update` の冒頭が `if (SceneManager::GetInstance()->IsTransitioning()) return;` なので、トランジション中は次の処理が一度も走らない
   - レールカメラの配置（`railStage_->UpdateCamera`）
   - `camera_->Update()`（行列の作り直し）
   - `skybox_->Update()`（Skybox の定数バッファにカメラ行列を書く）
   - `UpdateDynamicObjects / Animated / Primitives`（物体の行列を書く）
3. `SceneManager::Draw` はトランジション中も今のシーンを描く
4. ストライプが去って `IsTransitioning()` が false になったフレームで初めて Update が回り、正しい絵になる

白い板・右下の黒い形が何かは未特定（仕組みはこれで説明できる）。

### 1.2 なぜ起きたか（3つの重なり）

| どこ | 問題 |
|---|---|
| トランジション | 外から聞けるのが `IsTransitioning()` の true/false だけ。覆っている最中か開いている最中かをシーンが区別できないので、StagePlay は両方で止まっていた。Hold も固定の秒数 |
| シーン | `Initialize` の後、そのまま1枚正しく描ける状態になっていない（最初の Update で初めて行列が入る）。**シーン側の不具合** |
| Camera | `SetTranslate` 等を呼んでも `Update()` までは行列が古いまま。気づきにくい落とし穴（全体に関わるので今回は触らない） |

※ 他のシーンにも「トランジション中は Update を止める」書き方がある可能性がある。T1 のときに確認する。

### 1.3 計測結果（2026-10-10、`SceneManager` の scene_change 計測）

```
[LOAD] scene_change HUB->STAGEPLAY total=1337.4ms (transition=1117.1 / finalize=0.0 / create=0.0 / init=214.2 / first_update=0.0 / first_draw_present=6.0) load_only=220.2ms cpu=62.5ms
```

| 区間 | 時間 | 読み方 |
|---|---|---|
| transition | 1117.1ms | ストライプが閉じ切るまで（演出の時間） |
| init | 214.2ms | StagePlay の Initialize ＋ DStorage 待ち。実ロードはほぼここ |
| first_update | 0.0ms | トランジション中は Update が早めに return するので 0 |
| first_draw_present | 6.0ms | 最初の描画＋Present＋GPU 完了。雲はこのフレームで描き終わっている（ストライプに隠れているだけ） |
| load_only | 220.2ms | 演出を除いた実ロード |

計測の出力先: 出力ウィンドウの `[LOAD] scene_change ...` と profile.log の `LOAD kind=scene_change ...`（シーンを切り替えるたびに1行）。

## 2. 仕組みの拡張

今のトランジションは内部に3つの段階を持っている（`StripeTransition::Update` の `TransitionState`）。

| 段階 | 今の名前 | 起きていること |
|---|---|---|
| 覆う | `FadeIn` | 画面を隠す |
| 隠したまま | `Hold` | シーンを差し替える（ロード）。決まった秒数だけ待つ |
| 開く | `FadeOut` | 新しいシーンが見える |

### 2.1 段階を外に見せる

`TransitionManager`（と `SceneManager`）から「今は覆っている / 隠したまま / 開いている / 何もしていない」を聞けるようにする。シーンは**開いている間は動く**（入力だけ止める）と判断できるようになる。1.1 の根本対策。

### 2.2 隠したままの時間を「最低秒数＋ロード完了」にする

Hold を「最低の秒数を過ぎた」かつ「シーンの差し替え（ロード）が終わった」で抜けるようにする。ロードは今も Hold の中で同期して行うので、実際は最低秒数を守るだけになるが、ロードが長くなってもそのまま対応できる形にしておく。

注意: ロードのフレームは dt が 200ms 以上になる。Hold の秒数を dt で数えると、ロードの直後に Hold が一気に終わる。秒数の数え方は T2 で決める。

### 2.3 覆う側と開く側を別の種類にできるようにする

今は1つのトランジションが覆うのも開くのも担当している。これを「覆うのは墨・開くのはストライプ」のように**別々に組み合わせられる**ようにする。

- 今週: 墨（覆う）＋ 黒いストライプ（開く）、羽毛（覆う）＋ 羽毛（開く）
- 来週: 墨（覆う）＋ **行き先のシーンに任せる**（StagePlay の瞼が開く）。16 番 §2 の取り決め。今週は作るだけで使わない

### T3 墨（覆う）＝今回の核

画面を「上から見下ろした水面」として扱い、全画面のシェーダで次の3層を重ねる。

| 層 | 作り方 | 流用 |
|---|---|---|
| 画面の取り込み | 遷移の開始時に、前のシーンの最終画面をテクスチャに1回コピーする | 新規 |
| 水面の揺れ | 雫が落ちた点に衝撃を入れて波紋を走らせ、高さの傾きで取り込んだ画面を読む UV をずらす（屈折）。波の山にうっすらハイライト | `RippleSimulation`（エンジン `Graphics/Water`、GPU 波動方程式 512²）。ワールドの XZ（`AddImpulse(Vector3)`・`SetCenter`）で作られているので、画面の UV を仮の XZ の範囲に対応させて使えるか確認する |
| 墨 | 落ちた点からの距離を時間で変化するノイズで歪ませて濃さを決める。縁は筋状にちぎれ、芯は濃い。半径が広がり切ると全面が黒 | `cloud_noise.dds` |

時間の目安（HUB → ステージ）:

| 時刻 | 起きること |
|---|---|
| 0.0〜0.25s | 墨の雫が上から近づく（小さな黒い点が大きくなる） |
| 0.25s | 着水。波紋が走って画面が揺れる |
| 0.25〜1.2s | 墨が筋を引きながら広がる。波紋は残りつつ減衰 |
| 1.2s〜 | 真っ黒（隠したまま、ロード）。最低 0.2s |
| → | 黒いストライプが去って開く |

#### 羽根の着水（死亡 → ゲームオーバー）

**2026-10-11 作り直し（ユーザーの2枚目のスケッチ）**。最初の版（真上から見下ろす・羽根が手前へ向かってくる）は間違い。

| 段階 | 何が起きるか | 仮想カメラ |
|---|---|---|
| ① 小さい羽根が降る（覆う） | ステージの上に小さい羽根が**上から下へ降るだけ**（手前に飛んでくる動きはなし）。**瞼が閉じる**ようにステージの絵が上下から閉じていく（円形のヴィネットではない。来週のスタート演出で逆再生して使い回す） | 正面で固定 |
| ② 大きい一枚を追う（覆う） | 雨の中に**モデルの大きい一枚**が現れる。**他の羽根より速く落ち**、左右に振れながら滑るように落ちる（落ち葉の落ち方）。カメラが追って下がるので、小さい羽根は相対的に上へ流れて画面から消える。瞼は閉じ切り、背景は暗闇 | 横から見たまま下へ追う |
| （ロード） | 小さい羽根が消えた後、大きい一枚が**左右の振れの端で一瞬止まりかけた瞬間**に合わせる | 同上 |
| ③ 水面に着地（開く） | カメラが斜めに見下ろす角度（まず 35°）へ傾き、暗い水面が画面全体に広がる（水平線は見せない）。大きい一枚が着地して、遠近の付いた波紋が**画面全体に広がる** | 正面 → 35° 見下ろし |
| ④ ディゾルブ（開く） | 大きい一枚はディゾルブで消える（死んだ感） | 同上 |
| ⑤ リトライ画面が浮かび上がる（開く） | 画面全体に広がった波紋の揺らぎの中から、ゲームオーバー画面が浮かび上がる | 同上 |

作り方：
- **水面は3Dの平面**として全画面のシェーダで描く（仮想カメラの視線と水平な面の交点。雲のレイマーチと同じ考え方）。波紋は `RippleSimulation` を水面のワールド XZ で解く（もともと XZ 前提なので画面への置き換えが要らない）。水は暗く、波紋は光の照り返しで見せる。浮かび上がるゲームオーバー画面は、交点の波紋の傾きで歪ませる
- **瞼**は `Eyelid.hlsli` に切り出す（上下のまぶたの縁の形・閉じ具合・ぼかし）。スタート演出で逆再生して使う
- ロードで画面が止まるのが気になれば、ゲームオーバー画面のロード時間を scene_change 計測で測ってからマルチスレッド化を考える（重いのは STAGEPLAY のロード＝羽根の飛翔の真っ白の間なので見えない）

#### 羽根の飛翔（リトライ → ステージ）

- 覆う：選んだ瞬間、羽根が消えた着水点から羽根が一斉に舞い上がり、**右下から左上へ吹き上がる風**に乗って手前へ飛び、画面を覆って白になる（消えた羽根がよみがえって飛び立つ＝再起）
- 開く：今週は白が晴れて残りの羽根が抜ける。**来週はスタート演出の「白から始まる後半」に任せる**（16 番 §2）
