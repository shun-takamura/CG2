## 1. 死亡演出（2026-10-21 ユーザー決定）

**爆発はしない**。機体が光り、分解されて天に回収される。参考はゼルダの伝説 BotW のワープ（光の筋が立ち上り、体が光の粒になって昇る）の**逆**＝ワープで出てくる方を逆に再生したような見え方。**足元の魔法陣は要らない**（ユーザー決定）。

### 1.1 シューティング

- **羽根の焼け落ち**と**機体のエーテル化**を**同時に**進める
  - 羽根の焼け落ち：羽根のパーティクルを出し、**オレンジっぽい縁を付けたディゾルブ**で消す＝焼け落ちている感じ
  - エーテル化：機体がエーテルの色で光り、分解されて天へ昇る（回収）
- 周りから「ロボットなので爆発でいいのでは」という意見があったが、爆発は採らない（世界観＝古代の遺物・天使の機械翼に合わない、リトライでよみがえる理屈とつながらない）

### 1.2 ボス戦（地上戦。**羽根は無い**）

- **膝をつくアニメーション**と並行して、**スラスターが咳き込むように弱まり、止まる**
- その後、シューティングと同じく**エーテル化して回収**
- 羽根のパーティクルは出さない（ボス戦では羽根は収納済み＝16 番 §2.6）

### 1.3 見た目をそろえる所

| 所 | そろえ方 |
|---|---|
| 焼け落ちる縁 | 死亡演出の羽根・トランジションの舞う羽根・中央の一枚に、**同じオレンジの縁のディゾルブ**。`FeatherRenderer` には既に `edgeColor` / `edgeWidth`（今は青白）があるので色を変えて流用できる |
| エーテルの色 | 機体のエーテル化の光・**機体の六角形のディゾルブ（HUB の胸の入口 `kDissolveHexHole`）**・器の液体・難易度の明るさを、すべて**同じエーテルの色**にする（ユーザー決定）。色は**水色 (0, 0.641, 1.0)**（2026-10-24 決定、§4.3） |

### 1.4 作るのに要りそうなもの（見込み。着手するチャットで確かめる）

- **下から上へほどけるディゾルブ**：今あるのはノイズ・六角形・球の距離。「高さの面」の方式を 1 つ足す（エンジンの変更 → ArcanaEngine へ同期）。罠：影のパスはディゾルブを見ない（17 番 §2 の罠と同じ）
- **天へ昇る光の粒**：エフェクト（EffectDef）。`/effectgen` で作れる
- **膝をつくクリップ**：自機の新モデルに Kneel 系のクリップは無い。Blender で作って書き出す（`player_mech_model` のクリップと同じ流れ）
- **スラスターの咳き込み**：ゲーム中のスラスター（16 番 §2.7 の MechThrusters）の出力を時間で揺らして 0 へ
- **死亡中の操作・当たり判定・HUD**：操作を受け付けない、無敵、HUD は消すか実機で

**罠・注意（G2・G3 へ）**
- **影のパスはディゾルブを見ない**（17 番 §2 と同じ）。ほどけている途中も影は体全体のまま。ほどけ切ったら `SetVisible(false)` で影ごと消している。ボス戦（地面に影が出る）で気になるなら G3 で対策
- **粒子（EffectDef）はバースト 1 回**（`burstFired`）。出し続けたい粒は `loop:true`＋短い `totalDuration` で毎周バーストし、`Stop` で止める（`PlayerEtherAscend`）。また、放った粒はワールドに残る（エミッタだけが自機を追う）ので、レールではカメラと一緒に進む自機から粒が後ろへ流れて見えるはず → G2 でレールを止めるか・カメラをどうするかと一緒に決める。糸（EtherStrands）は自機について動く
- 粒子の重力は無い。焼けた羽根は放射の初速で漂うだけ（落としたいならエンジンに重力を足す話になる）
- エフェクトの塗り替えは displayName の頭が `Ether` の部品だけ。新しく部品を足すときは名前に注意
- ID パス（アウトライン）のスキニング版はディゾルブを見ない（球の方式と同じ）
- 羽根のモデル自体は Glow の始めに**すぐ隠す**だけ（焼け落ちの粒子と入れ替え）。羽根のモデルにもオレンジの縁のディゾルブを掛けるか・トランジションの羽根（`FeatherRenderer` の `edgeColor` は今は青白。Transition.json の値を替えるだけで流用できる）をそろえるのは G2
- HUD は演出中もそのまま（§6 で未決）

**G2 向けの作り方の案（2026-10-22、G1 のチャットで調べた。ユーザー「その辺の演出は G2 でやろう」）**

G1 の実機でユーザー：「ほどける感じは良かった」。残りの 2 つは G2 で：

1. **羽根が燃えるように焼け落ちる**（今は Glow の始めに羽根のモデルを即 `Hide`）
   - `PlayerWingUnit` に状態 `Burning` を足す。収納（`Stowing`）と同じ「付け根中心の球が縮む＝先から消える」ディゾルブ（`ApplyDissolve(radiusRatio)`・`kDissolveSphereGrow`）を流用し、縁はオレンジ (1.0, 0.45, 0.08)×明るさ・幅太め・ゆらぎ（noiseAmplitude）大きめ。たたまず開いた形のまま焼く（Stow のクリップを流さない）。縁は今の `DrawBloom` でブルームに乗る
   - 秒数は既定 1.6s 程度、Glow の始めから。機体のエーテル化と並行（§1.1「同時に」）
   - 羽根の粒子は背中から 1 回のバーストをやめ、**燃えている縁にある羽根の骨**（PlayerWings の骨 41 本。Spine2 中心からの距離が今の半径の近く）の位置から数枚ずつ何度も出す → 小さいエフェクト `PlayerFeatherBurnBit.json`（`PlayerFeatherBurn` の小型版）を新設
   - ホストの IF は `HidePlayerWings` を `BurnPlayerWings(秒)` と `CollectWingBurnPoints(std::vector<Vector3>&)` に差し替える案（羽根の関節は `wings_` の `GetSkeleton()`＋`GetJointWorldMatrix`）
   - 羽根の表示は体の `GetVisible` に従う（`PlayerWingUnit::Update`）ので、焼け落ちは Linger（体を隠す）より前に終える
   - 調整値は `"playerDeath"` に（秒数・縁の色・幅・粒子の間隔）。縁の色は `PlayerFeatherBurn.json` の `dissolveEdgeColor` とそろえる
2. **シューティングで死んだらレールカメラと自機の進行を止める**（今は進み続ける）
   - `StagePlayScene::Update` のレールの所で `railDt` を `IsPlayerDying()` なら 0 にする（`benchHoldSec_` と同じやり方。`railStage_->UpdateCamera(actions, 0, ...)` でポーズは保たれる）。経過秒が止まるので次のウェーブ・環境セクションも止まる。カメラの揺れ（ApplyCameraIdleSway）はそのまま
   - これで粒（ワールドに残る）が後ろへ流れる問題も消える
   - 出ている敵・敵弾は動き続ける（自機は無敵）。止めたいなら World の時間を止めるが、その場合はエーテルの粒も World なので止まる → 粒子の `timeGroup` を 3（Effect）に移す
   - カメラ（自機へ寄る・見上げる等）は G2 で決める

**罠・注意（G3 へ）**
- **レールでは自機がカメラ基準で置かれる**（`playerLocalOffset_` をカメラのワールド行列で変換）。カメラをレールの直後で動かすと自機もついて動いて寄れない → 自機を置いた後（ジャスト回避・必殺技・雲の上のカメラと同じ所）で上書きしている
- **自機の向きは画面基準のレティクルを追う**ので、カメラを動かすと向きがつられる → 死亡中は `SetRotate` しない分岐を足した
- 死亡カメラは Rail/Landing の配置の中だけ。ボス戦（G3）のカメラは別に要る
- 羽根の焼け落ちのノイズはワールド座標。自機は止まるのでよいが、動く物に使うと模様が流れる
- 羽根は体の `GetVisible` に従うので、焼け落ち（1.6s）は Linger（Glow 0.6＋Unravel 2.0 の後）より前に終わるようにしてある。秒数を伸ばすときは注意

## 2. 通貨：エーテル（2026-10-21 ユーザー決定）

### 2.1 世界観での意味

- ここでのエーテルは化学の物質ではなく、古代ギリシャ・中世の宇宙論で**天上の世界を満たす第五の元素**（天球はエーテルでできているとされた）。HUB の天球儀の聖堂とつながる
- **光る液体**。古代の機械（機体）を動かす源
- 死ぬと機体はエーテルに還って天に回収され、リトライでは**賭けていたエーテルから機体を組み直す**。つまり減ったエーテルは「失った」のではなく「戻ってくるために使った」

### 2.2 液体にした理由（ユーザー）

- タイトルで作ったコンピュートシェーダの流体（`RippleSimulation`）や反射が使える
- 目で見てどれくらい残っているかがわかるが、**実際の数字は出ない**（§3 の原則に合う）
- 減らし方を表しやすい：容器を倒す・容器にひびが入って漏れる、など
- 多く入れて難易度を上げると光が強くなり、強そうに見える。回収のときの機体の光と同じ色なので「エーテルで機体を強化する」と理屈が通る

### 2.3 稼ぐ・使う

- **稼ぐ**：ゲームのご褒美として与える（敵の撃破・クリアの報酬など。基礎の報酬額に難易度の倍率を掛ける＝§5）
- **使う**：**装備**（メイン武器・盾・飛行ユニット）を買う・強くする。2026-10-23 決定、正本は [20_Loadout.md](20_Loadout.md)。ステータス強化は装備の効果にまとめた
- 企画当初の **SP（スキル購入）はエーテルにまとめる**（2026-10-23 決定。コスト上限で組むスキルは廃止）
- **セーブデータ**：進行（通貨・強化）を保存する仕組みはまだ無い（今あるのは設定だけ）。JSON は自作（外部ライブラリ禁止）

## 3. リトライ画面の原則（2026-10-21 ユーザー決定。**必ず守る**）

悪魔の窯が優れているのは、失敗したプレイヤーに過剰な「やらかした感」や「強制感」を与えないところ。

| 原則 | 内容 |
|---|---|
| **失った量は見せない** | 「失った 12」のように失ったものを数えさせない。やらかした感を過剰に感じさせる |
| **残っているもの（守れているもの）を見せる** | 「失敗したけど、まだ守り切れている掛け金」として見せる。まだこれくらい残っているからもう一度やってみよう／これくらいなら捨ててもいいか、をプレイヤーが自分で決める |
| **損を突きつけない** | 「あきらめると 48 を失う」のような出し方は、リトライの強制に感じられるので**絶対にやらない** |
| **言い回し・表現で委ねる** | 数字より液体の量で見せる。選択肢は対等に並べ、「あきらめる」のような負けを感じさせる言葉を避ける（例：「引き上げる」。文言は画面のチャットで決める） |
| **難易度を下げるか聞かない** | 死んだら黙って少し下がる（悪魔の窯と同じ）。「難易度を下げますか？」とは聞かない |

## 4. エーテルの器（悪魔の窯の代わり。2026-10-23〜24 ユーザーと決定）

ほかの AI（Dola・Gemini・GPT）の案も比べた。3 社とも「金の杯＋天球の輪・青白いエーテル」を推したが、ユーザーの判断で**透明なガラス**にした。

### 4.1 形と素材

- **天球儀**。中心は**密閉したガラスの球**で、中にエーテル。まわりを土星の輪のような水平の輪の台座が囲み、北極に**針（矢印）**、球の後ろに**縦に立つ文字盤**（メトロノームのように針が数字を指す）。下に土台（青いテーブル）と支柱
- 素材は**金＋深い群青のエナメル**（機体の青）。外の世界の色（白と金）に、機体の鮮やかな青を足す
- 不採用にした物と理由

| 案 | 理由 |
|---|---|
| 不透明な金の杯（液面を上から見せる） | **減った感じが見えない**。もったいない感は減るが、難易度が下がった実感も無いと「またやっても無理」と思う人が出る（ユーザー）。減ったことは感じつつ、量は目測でぼんやりがよい |
| 球に注ぎ口を開ける | エーテルは架空の物なので**ガラスをすり抜けて出入りしてよい**（ユーザー）→ 密閉にした |
| 文字盤を Tripo のテキストで「上半分だけ帯がある円盤」と頼む | 皿・扇が出てきてスケッチと違った。その後、輪の形で作り直して成功（§4.2） |
| 球の下の軸で振る | 水平の輪が赤道を囲むので、下を支点に傾けると球が横へずれて輪に当たる → **球の中心で回す** |

| 物 | 場所 | 中身 |

**罠・注意（G6 へ）**
- **エンジンの Z 回転は + で上が −X へ倒れる**（`MakeRotateZMatrix`）。G4 の決まりは「I へ＝針の先を +X」なので、Swing の回転は**傾きの符号を逆**にする（`EtherVesselGlass::GetRotationZ()` を使う）。液面の揺れも同じ回転を渡すこと（符号がずれると液面が逆へ傾く）
- `RippleSimulation` は 512 テクセルで、波が範囲を渡り切る刻みの数は範囲の大きさによらない（クーラン数の上限 0.45）。数十 cm の球に範囲を合わせると波がとても遅いので、**範囲を球より広く取り（直径の 1/0.3 倍）、刻みを 240/s** にしている。範囲の外の縁で吸収されるので、球の壁での反射は無い
- 波源の深さは [m]、PS の傾きは m あたりに直している（`rippleNormalScale` 1 で素直な大きさ）
- ガラスは深度を書かない。G6 で球の手前に半透明の物（選択肢の板など）を置くなら、描く順に注意
- 発光パスはシーンの `HasBloomSources` / `DrawBloomSources`。**トランジション中は false にする**（発光はトランジションの絵の上に足されるので、着水の羽根・波紋が光る球に隠れた。HubScene の `IsGlowAllowed` と同じ）
- **空を描かない画面はシーン RT を不透明な色で塗る**。既定のクリア色は (0,0,0,0) で、Debug のビューポートでは α=0 の所に ImGui の背景（グレー）が透け、モデルのある所だけ描かれて見えた（Release は黒に見えるので気づきにくい）。`ClearRenderTargetView` で別の色に塗ると、作成時のクリア値と違うという D3D12 の警告（#820）で Debug が止まる → GameOverScene は画面いっぱいのスプライト（`vesselBackground_`）で塗り、スプライトが書いた深度を 1.0 で消してから器を描く
- sRGB の RT は 1 を超えると白く飛ぶ。最初の既定値（Glow 1.2・液面 0.6）では球が真っ白の玉に見えた → 下げた後、2026-10-24 ユーザーが ImGui で決めた値を JSON と既定値に入れた：液体の色 (0, 0.641, 1.0)・Glow 0.3（難易度 0.5 のとき。`glowAtMin/Max` 0.15〜0.45）・液面 0.6・ブルーム 0.8、ガラスは Glass Alpha 0.3・Back Rim 0.5・Lens IOR 1.0（曲げない）・Rim Bloom 1.3・Specular Power 128
- 屈折（画面のコピーで後ろを曲げる）は入れていない。液体だけは `lensIor` で少し曲げて見ている。後ろの文字盤も曲げたくなったら `ScreenWaterSurface` の画面のコピーを流用する
- **カメラ（2026-10-24 ユーザー決定）**：トランジション（着水の波紋）の間は**液面のすぐ上**（器の原点から (0, 2.979, 0.483)・回転 (15°, 180°, 0)）に置き、明けたら 0.3s 後から 2.5s（smootherstep）で**引いて** (0, 3.801, 2.801)・同じ角度＝文字盤の I・V・IX・針・球が収まる所へ。着水の波紋から液面の波紋へつながる。値は GameOverScene のメンバ（ImGui で調整、`Near/Far <- Debug Cam` でデバッグカメラの位置を写せる）。G6 で JSON へ
- **液面の静かな波紋は中央だけ**（ユーザー）：`ambientRippleSpread` 0＝中央に同心円。1 で液面全体にランダム

| 5a もう一度 | — | 球の光が強まり、エーテルが光の柱になって昇る → 今の**羽根の飛翔**へ（賭けたエーテルで機体を組み直す） |
| 5b 引き上げる | — | 残ったエーテルが支柱を伝って泉へ下りていく（＝手元に戻る）→ 今の行き先へ |

- 「失った瞬間は静かに、立ち上がる瞬間は力強く」（GPT の案から）
- **選択肢の文言**：ボス戦のチェックポイントがあるとき「ボス戦から」／「はじめから」／「引き上げる」、無いとき「もう一度」／「引き上げる」。「引き上げる」は賭け分を手元に引き上げる、の文字どおりの意味になる
- 選択肢の文字は外の世界の画面なので**白に金の縁**（緑のネオンはコクピットだけ）

### 4.7 賭ける画面（コンテストの後）

- 場所はステージ選択（コクピット）。同じ器を使う。コクピットの中にどう置くか（モニタ越しか）は未定
- スティックを倒している間、上げると泉から昇って液面が上がり・針が右へ、下げると泉へ下りて液面が下がり・針が左へ。値は 0.5 刻みなど、液面と針は少し遅れてなめらかに追う
- 上から注ぐ演出は入れてもよい（流れが液面を打つ所に波紋）。パルテナは注ぐ動きなしで量が変わるだけなので、省いてもよい

### 4.8 コンテストまでの最小の仕組み

- **エーテルの状態**：手元・賭け分・難易度の 3 つだけ、シングルトンに持つ（`BossRetryState` と同じ置き方）。**セーブはしない**
- **ImGui** で賭け分と難易度を決めて始める（賭ける画面の代わり）
- 死んだら賭け分が少し減り、難易度が少し下がる（割合・下がる幅は JSON）。引き上げたら賭け分を手元へ
- 敵の強さへの倍率（§5 の `DifficultyProfile`）は後回し。値だけはあり、針が指す

### 4.9 Tripo のプロンプトとコツ（2026-10-24）

- **日本語で書く**（ユーザー：英語だと思ったものと違うときに直しにくい）。末尾に共通のスタイル文：「磨かれた金と深い群青のエナメル、バロック調の唐草模様、古代の天球儀の機械、文字や数字は入れない、単体のオブジェクト、ゲーム用アセット」
- 出してほしくない物はネガティブプロンプトの欄へ（本文に「〜なし」と書くとかえって引っ張られる）。台座に「浅い受け」と書いたら盃が付いてきた
- テキストからの生成は**上下・左右で違う形が苦手**（「上半分だけ帯」が無視されて同心円の皿になった）。「丸く平たい円盤」は飾り皿と取られる
- 形が違ったら、最初の一文（何の部品か）を言い換える

## 5. 難易度（2026-10-21 考え方は決定、数値は仮）

- **敵の基礎ステータスと基礎の報酬額に、難易度による倍率を掛ける**（ユーザー OK）
- 変わるもの：敵の**攻撃頻度**・**攻撃力**・**体力**、と**報酬額**
- 倍率は 1 か所（仮名 `DifficultyProfile`）にまとめ、敵のスポーン（体力）・敵弾のダメージ・射撃の間隔・ボスの攻撃のクールタイム・報酬がそこを読む。値は JSON＋ImGui で持ち、ハードコードしない
- 目盛りの範囲（0.0〜9.0 など）と倍率の式は仮。賭けの UI ができるまでは既定の目盛り固定で動かせるようにする
- ボス戦からのリトライ（`BossRetryState`）では、下がった難易度でボス戦を始める
