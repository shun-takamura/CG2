## 1. メイン武器（右手）

- **5 つくらい**。買い替えで強くなる。攻撃の性能（威力・連射の間隔・チャージ時間など）と見た目が違う
- 弾の撃ち方まで変えると武器の数だけ作る手間が増えるので、まずは**性能と見た目の違いだけ**
- 付け方：今の武器は `WeaponParams`（追従ボーン `mixamorig:RightHand`＋モデルのファイル。プレハブの `weaponModelDir` / `weaponModelFile` / `weaponBone`）で持っている（今は球を引き延ばしたモデル）。**モデルのファイルを差し替えるだけ**で替えられる。モデルは Tripo

### 1.1 コンテストの 3 種（2026-11-01 ユーザー決定、ビルド・実機 OK）

- **得意が違う 3 種**（上下関係ではなく選び方）。**コンテストでは全部最初から選べる**（購入・段階なし）
- **コンテストの後**：敵が落とす素材＋エーテルで**作る・強くする**（モンハン式）にして長く遊べるようにする。`price` は予約の欄だけ置いてある
- 変える性能：攻撃力の加算（射撃・近接で分けない）・連射の間隔・チャージ時間・弾の速さ／大きさ（判定と見た目）／ホーミング（通常弾とチャージ弾で別の倍率）

| | 標準（Standard） | 重い（Heavy） | 軽い（Light） |
|---|---|---|---|
| 攻撃力の加算 | +4 | +10 | +0 |
| 連射の間隔 | 0.30 秒 | 0.45 秒 | 0.18 秒 |
| チャージ（1 段／2 段） | 3／6 秒 | 4.5／8 秒 | 2／4 秒 |
| 通常弾 速さ・大きさ・ホーミング | ×1・×1・×1 | ×0.6・×1.5・×2 | ×1.4・×0.7・×0.4 |
| チャージ弾 速さ・大きさ・ホーミング | ×1・×1・×1 | ×2.5（ビーム並み）・×1.6・×1 | ×1.4（通常弾と同じ）・×0.7・×0.4 |
| 見た目（Tripo まで） | 今の細長い球 | 太く長く | 細く短く |

- 狙い：重い＝一発が大きく当てやすいが遅い。軽い＝弾は小さく曲がりにくいが、チャージが速いので貫通するチャージ 2 段目を何度も撃てる（貫通が効く所で強い）
- 実装：
  - 値は `Resources/Json/Tuning/MainWeapon.json`（`weapons[]` と `default`）。読むのは `Score/MainWeaponCatalog`（一覧・`GetDef(i)`・`Find(id)`）。**装備画面は JSON を読まずこれを呼ぶ**（呼び方は共有ノート `loadout_main_weapon.md`）
  - 付けている武器は `LoadoutState` の id（`Get/SetMainWeaponId`・`GetMainWeapon`）。Debug は ImGui「Main Weapon (20 1)」で切り替え・JSON の読み直し
  - 攻撃力は `ScaledPlayerAttack`＝(プレハブ 10＋加算)×攻撃系の補正。チャージ時間・連射は武器の値（一覧が空ならプレハブの `ChargeParams`）。弾の倍率は射撃の所で掛け、大きさは `SpawnPlayerBullet` の `sizeScale`（判定・見た目・判定の広がり）
  - **プレハブの部品（`ChargeParams` / `WeaponParams`）には書き込まない**（Save as Prefab で武器の値が player.json に入ってしまうため）
  - 右手のモデル：武器に `model` があればそれと `grip`（ずらし）を使い、無ければプレハブの weapon。付け替えは `Object3DInstance::SetModel` でモデルだけ差し替える（作り直さない）。**ModelManager はファイル名で引くので、Tripo のモデルは武器ごとに別のファイル名にする**
  - 飛行ユニットの支援射撃・ファンネルには武器の弾の倍率を掛けない（攻撃力の加算は効く）

### 1.2 モデルとビームの刃（2026-11-02、ビルド・実機 OK。握り・刃の位置はユーザーが ImGui で合わせて保存済み）

- **モデル**：Tripo の銃 3 丁（`Assets/Models/Weapons/MainWeapons/<MiddlePower|HightPower|LowPower>/*.glb`）。標準＝MiddlePower、重い＝HightPower、軽い＝LowPower
  - `tools/BlenderPipeline/prep_main_weapons.py`（`prep_shields.py` と同じ流れ）：Tripo は銃が**床に寝て水平面の斜め**を向いて出るので、水平面の主成分で銃身の向きを出し、**銃口＝エンジンの +Z・上＝+Y・中心が原点**にそろえる。銃口の側は「端の背が低い方」で決め、外れたものは `FLIP_MUZZLE`（LowPower が外れた）。金属度・粗さは係数に、色と法線は PNG → cook。`cook_assets.py` の `SRGB_INPUT_HINTS` に `MainWeapons`
  - 握り（grip）は ImGui「Main Weapon (20 1)」で合わせて Save（`MainWeapon.json`）
- **ビームの刃**：画像（プラモデルの銃の下の刃）のように、**銃身の下から前へ伸びる刃を近接のときだけ出す**。盾のビームと違い、**揺らぎのない、実体に近い安定した刃**（ユーザー指定）
  - エンジンの `BeamBladeRenderer`（`GameEngine/Graphics/Effect/`、シェーダー `Resources/Shaders/Effect/BeamBlade.*.hlsl`）。板ではなく**立体**：菱形の断面（中央に稜線）を根元・肩・先の 3 か所でつなぎ、先はとがる。頂点は形の係数だけで、寸法は VS が作る（ImGui で形を変えても作り直さない）。面は ddx/ddy の法線で角ばらせ、縁と稜線を明るく・斜めの面ほど明るく。乗算済み α＋発光 RT
  - **形は片刃・刃が下向き**（2026-11-02 ユーザー）：稜線を上へ寄せ（`ridgeOffset` 0.75）、峰を真っすぐ保ち（`backAnchor` 1）、先を峰の線に（`tipOffset` 1）。ImGui の「Single Edge (down)」／「Double Edge」で切り替え
  - 出し入れ：近接の発生〜後隙とコンボの受付（`meleeComboTimer_`）の間だけ伸び（0.08 秒）、切れたら縮む（0.15 秒）。付け替えるとすぐ消す
  - 値は `MainWeapon.json` の各武器の `blade`（`offset` / `rotate` / `scale`＝モデルのローカル。刃は +Z へ伸び、幅は Y・厚みは X）。ImGui の「Preview Blade」で近接なしで出し、「Main Weapon (20 1)」の Blade の欄（位置・向き・大きさ・長さ・幅。細かい形と色は「Blade Look」）で調整 → Save

## 2. 盾（左手）

- **5 つくらい**。買い替えで強くなる。防御の性能（被ダメージの軽減など）と見た目が違う
- 付け方：`WeaponParams` と同じ仕組みを `mixamorig:LeftHand` にもう 1 つ。エンジンの追加は要らない見込み
- 腕ごとのモデルは作らない（武器と盾のモデルだけで済む）

### 2.1 コンテストの 3 種（2026-11-01 ユーザー決定、ビルド・実機 OK）

上位互換にせず、役割の違う 3 種（装備画面で比べる意味を出す）。値は仮。

| id | 表示名（仮） | モデル | HP 上限 | 被ダメージ軽減 | 移動速度 |
|---|---|---|---|---|---|
| Standard（初期） | ハロー・バックラー | 中 | +0 | 0% | ±0 |
| Heavy | サンクチュアリ・タワー | 大 | +40 | 0% | −10% |
| Mirror | アイギス・ビーム | 小（ビームシールド） | +10 | 20% | ±0 |

- **計算**：HP 上限＝（プレハブの 100＋盾）× 防御系の補正（付け替えても残り HP の割合を保つ）。軽減は**通常の被弾だけ**に、難易度の倍率 → 防御系の常時の軽減 → 盾の軽減の順（防御系の RB のバリアには掛けない。0 より大きいダメージは 1 未満にしない）。移動は攻撃中の 0.6 倍・機動系の補正と掛け算
- **購入・段階は無し**（コンテストでは全開放）。コンテスト後は敵が落とす素材＋エーテルで作成・強化するモンハン式にする（ユーザー決定。そのとき値段・段階を足す）
- **データ**：`Resources/Json/Tuning/Shield.json`＋`Game/Score/ShieldCatalog`（メイン武器の `MainWeaponCatalog` と同じ作り）。付けている盾は `LoadoutState` が id で持つ（起動中だけ）。Debug の ImGui「Shield (20 2)」で切り替え・握り（grip）・ビームの調整・Save。装備画面が呼ぶ口は `GetCount` / `GetDef` / `GetStatLines`（右下の性能 3 行）・`GetShield()->maxHpAdd`（フレームの合計の HP 上限）
- **モデル**：Tripo（`Assets/Models/Weapons/Shields/<Big|Middle|Small>/*.glb`）→ `tools/BlenderPipeline/prep_shields.py`（中心を原点・金属度と粗さを係数に・PNG で glTF 書き出し）→ cook。`cook_assets.py` の `SRGB_INPUT_HINTS` に `Shields`。左手 `mixamorig:LeftHand` に `BoneSocket` で付ける（ボーンの拡大は除くので grip の scale がそのまま大きさ）。握りはユーザーが ImGui で合わせた値
- **ビームシールド**：小のモデルは発生装置だけで、本体はエンジンの `BeamShieldRenderer`（`GameEngine/Graphics/Effect/`、シェーダー `Resources/Shaders/Effect/BeamShield.*.hlsl`）。板 1 枚に PS で
  - 形＝縦長で上下がとがった六角形の距離。縁は発生装置から見た角度のノイズ（角度で一周する周期・時間方向へ滑らかに変える）で出し入れ＝**大まかな形は変えず縁だけ細かく変わる**
  - 集中線＝同じく角度のノイズを鋭くした放射状の筋（細い筋とまばらな太い筋の 2 層）。発生装置を囲む小さな六角形も描く
  - 透け＝発生装置の近く・小さな六角形・縁の帯は不透明に近く、間は透ける。乗算済み α＋発光 RT（ブルーム）
  - **被弾の瞬間だけ強く光る**（明るさ＋縁のゆらぎを大きく、指数で引く）。常に出しておく（展開・収納の演出は後で足せる）
  - 値は `Shield.json` の Mirror の `beam`（`offset`＝発生装置の位置、盾のモデルのローカル）。参考はユーザーのプラモデルの写真（透ける・芯と縁が濃い・集中線）

## 3. 飛行ユニット（サブ武器を兼ねる）

| 種類 | 入手 | シューティング | ボス戦 |
|---|---|---|---|
| **初期の羽根** | 最初から | 機動力を上げるだけ（攻撃しない） | 使わない（今の実装どおり収納） |
| **攻撃系** | 購入 | 使える | **使える** |
| **防御系** | 購入 | 使える | **使える** |
| **機動系** | 購入 | 使える | **使える** |

- 系統ごとに **1 つずつ**。**段階を上げて強くなる**
- **普段は自動で動き、RB でクールタイム付きの技**を出す
- 羽根の板（`Wing_<列><行>`）が外れてビットになる見せ方が機体に合う（攻撃系・防御系）

### 3.1 攻撃系

- **自動（2026-10-29 決定）**：レティクルの位置へ一定間隔で支援射撃（レティクルが敵に重なっていればその敵へ強ホーミング）
- 段階：支援射撃・ファンネルの攻撃力
- **RB の技（2026-10-29 決定）**：ファンネルを数秒展開。ファンネルは**レティクルが合っている敵を優先**して撃ち、合っていないときは**画面上の敵**を撃つ。**ロックはしない**＝必殺技（傲慢サンダー＝全画面ロック → 一斉）とかぶらない
  - 旧案（ビットを集めてマルチロック一斉射撃＋廃熱）は必殺技とかぶるので不採用

### 3.2 防御系

- **自動（2026-10-29 決定）**：クールタイム付きで被ダメージを軽減する（弾は消さない＝ジャスト回避は普段どおり起きる）
- 段階：バリアの耐久力・軽減のクールタイム
- **RB の技（2026-10-29 決定）**：**耐久力付きのバリア**（耐久力＝自機の HP 上限 × 割合）。バリアの間は敵弾をバリアで消し、**ジャスト回避は起きない**。耐久力が尽きるか制限時間で消える。「ジャスト回避をしなくてよい」という選び方として置く

### 3.3 機動系（ジャスト回避を軸にする）

- 常に効くもの：**移動が速くなる**・**ジャスト回避のときの必殺技ゲージの回収が増える**。判定を直接広げはしない（「多少はしやすくなってもよい」ので、段階の上の方で少しだけ広げる余地は残す）
- **RB の技：数秒だけ世界をスローにし、自分は普通の速さで動ける**。その間にジャスト回避を狙ってもいいし、射撃などで攻めてもいい。エンジンの `TimeGroup` が使える。時計・天球儀のモチーフにも合う
  - ジャスト回避のスロー（ご褒美・分身カウンター付き）との違い：好きなときに使えるが、短く、カウンターは無い
- 不採用：回避の距離を伸ばす（逆に使いづらい）、短いブースト移動（回避とかぶる）
- **RB のスロー中にジャスト回避が起きたら（2026-10-29 決定）**：RB のスローはそこで終わり、ジャスト回避の演出に切り替わる。必殺技を出したときも同じ
- **スロー中も自機の移動・連射・チャージ・自機の弾は普通の速さ（2026-10-30 ユーザー）**。敵・敵弾・レールは遅くなる。ジャスト回避のスローは今までどおり（自機の弾も遅い）

### 3.4 実装（2026-10-30 ビルド・実機 OK）

- 置き場所：`Game/Scene/FlightUnit/`。共通の部分＝`FlightUnitPart`（RB の入力・クールタイム・常時の効果の問い合わせ口・クールタイムのバー）、系統ごと＝`FlightUnitSkill` を継承した `FlightUnitAssault` / `FlightUnitGuard` / `FlightUnitMobility`。シーンの機能は狭い窓口 `IFlightUnitHost` 経由だけ（`RailStagePart` と同じ流儀）
- 付けている系統と段階（1〜3）は `Score/LoadoutState`（シングルトン・起動中だけ・セーブなし）。**HUB の装備画面・セーブはここを書き換えるだけで差し替わる**。今は Debug の ImGui「Flight Unit (20 3)」で切り替え。既定は Wings（初期の羽根＝RB なし）
- 値：`Resources/Json/Tuning/FlightUnit.json`（配列は [段階1, 段階2, 段階3]、秒は実時間）。仮の値：機動系＝移動 +10/20/30%・ジャスト回避のゲージ +4/6/8・World 0.35 倍を 3/3.5/4 秒・クールタイム 25/22/20 秒。攻撃系＝支援射撃 0.8/0.65/0.5 秒ごと（攻撃力 ×0.3/0.4/0.5）・ファンネル 4 基 6/7/8 秒（×0.5/0.65/0.8）・クールタイム 25/23/20 秒。防御系＝軽減 50%（クールタイム 8/6/5 秒）・バリアの耐久力 HP 上限の 50/75/100%・8 秒・クールタイム 30/27/24 秒
- クールタイムは**技が終わってから**数える。時間はすべて実時間（UI グループ）。フェーズが変わると技を止めてクールタイムを 0 に戻す
- ボタン：`Action::FlightSkill`＝RB／キーボード C
- 被弾：防御系のバリアが先に受ける（回避中でも。被弾無敵・必殺技の無敵の間は減らさない）→ ジャスト回避の判定 → 通常の被弾で常時の軽減。敵弾のダメージには難易度の倍率を掛けてから耐久力を減らす
- 自機の弾の速さ：`GameScene::UpdateBullets` の 2 つ目の引数で、機動系のスロー中だけ自機の弾を Player の時間で進める
- **仮のまま**：RB の効果音はチャージショットの音を借りている／ファンネルは小さな箱（羽根の板が外れて飛ぶ見せ方は後で）／機動系のスロー中の画面の演出は無い

### 3.5 ステータス補正・移動状態（2026-10-30 ユーザー決定、ビルド未確認）

- **系統ごとのステータス補正（常時、段階 1/2/3）**：攻撃系＝攻撃力 +5/10/15%（射撃・近接・支援射撃）／防御系＝HP の上限 +5/10/15%（付け替えても残り HP の割合を保つ）／機動系＝移動速度 +5/10/15%（前の +10/20/30% から下げた）。`FlightUnit.json` の `attackScale` / `maxHpScale` / `moveSpeedScale`
- **機動系はジャスト回避の受付を延ばす**：+0.01/0.025/0.05 秒（`justDodgeWindowBonus`）。受付の元の値は `StagePlay.json` の `dodge.justWindow`（0.15 秒。ヘッダーの初期値も 0.15 にそろえた）で、判定の所で足す
- **移動状態**：最後に撃つ／近接を出してから 1 秒（`StagePlay.json` の `player.moveStateDelay`）たつと移動状態。チャージは射撃ボタンを離している間に進むので数えない＝チャージしながら移動状態で動ける
  - それまでは「チャージ中も攻撃中」扱いで、ほぼずっと移動が 0.6 倍だった（不具合）
  - 移動状態：移動 1.0 倍（攻撃中は `attackMoveSpeedScale` 0.6 倍のまま）。STG では当たり判定のカプセルを飛ぶ姿勢のモデルと同じ角度に前へ傾ける（`player.moveStateLeanDeg`、初期 55°。大きさは変えない）
  - 姿勢は今の飛行姿勢が前傾なのでそのまま。射撃姿勢・近接のアニメは後で入れる（攻撃中に切り替える）
- **敵弾の当たり判定**：足元中心の半径 1 の球 → プレハブのカプセル（中心＝足元＋当たり判定のオフセットを自機の回転で回した点）
- **判定の姿勢を 1 か所に**（2026-10-30 追加）：エンジン共通の `TryGetWorldData` は offset を回さず、回転順も Rz·Ry·Rx で自機（Rx·Ry·Rz）と逆。降下中に判定と描画がずれたので、`StagePlayScene::UpdatePlayerColliderPose` が中心・軸を決めて `Gameplay::SetColliderPose` に入れ、`CollisionManager::GetWorldData`（総当たり・デバッグ描画）、敵弾、突進・ボス近接の判定、`GetShotAimPoint` がすべてそれを使う。姿勢は `UpdateDynamicAnimated` の直後（描く行列と同じ translate / rotate）で作る。体の中心まわりに回すずらしも、照準で回した後では描画に乗らないので、レールの位置を作るときにその時点の回転で掛ける
- **敵弾の狙い**：偏差射撃の狙いとホーミングの目標を、足元から体の中心（`GameScene::GetShotAimPoint`）へ。止まっていると当たり、移動に専念すれば抜けられる
- **STG の自機の向き**：上の基準をカメラの上にし（雲の中の降下で真下を向いてもヨーが暴れない）、体の中心まわりに回るように位置をずらす（`ApplyRailAimRotation`）
