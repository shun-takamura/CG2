## 2. クラスとロードの流れ

### 2.1 役割分担

| クラス | 場所 | 役割 |
|---|---|---|
| `WaterSurface` | エンジン `Graphics/Water` | 水面の描画。大河モード（α ブレンドの PSO・t10 の川のマップ・大河用のパラメータ）を**追加**する。タイトル・ボス戦は従来の PSO のまま |
| `RiverWater` | ゲーム `Game/Scene` | ステージの大河の水面。`WaterSurface` を大河モードで持ち、ロードの時期・描く条件・シークを管理する。`IImGuiEditable` なので Hierarchy に「RiverWater」として出て、Inspector で調整・保存する（シーン JSON には保存しない。コードで生成） |
| `StagePlayScene` | ゲーム | `RiverWater` を生成し、Update / Draw / Seek / ImGui を呼ぶだけ |

### 2.2 ロード

DirectStorage 自体は非同期で動かせるが、今のエンジンの `TextureManager` の GPU フェーズは `DStorageManager::SubmitAndWait` で完了を待つ。待たない API（`SubmitAsync` → `IsComplete`）は **L9 の作業**なので、L3 は今の API で作り、できたら差し替える（11 番 §3.4 で L9 へ依頼）。

| 時期 | スレッド | 内容 |
|---|---|---|
| シーン初期化 | メイン | `WaterSurface` の生成（ルートシグネチャ・PSO 2 本・CB・頂点バッファ・代わりのテクスチャ）。シェーダを実行時に DXC でコンパイルするので、**重い処理は全部ここ** |
| 雲の中（既定 51秒、ImGui で変更可） | 別スレッド | `RiverTerrain.json` の読み込み、川のマップの CPU フェーズ（`TextureManager::LoadTextureCPU`） |
| CPU フェーズの完了後の最初の Update | メイン | 川のマップの GPU フェーズ（`LoadTextureGPU`。1MB なので待ちは小さい）→ `WaterSurface::SetRiverMap` → 水面を有効にする |
| シーク | メイン | ロード開始時刻より後へ飛んだら、その場で同期ロード。ロード中なら完了を待つ |

- ロードしたデータは捨てない（川のマップは 1MB。低空の破棄 ≈126秒は L9 が決める物で、水面は対象外）。
- 別スレッドは `RiverWater` が持ち、破棄時に必ず join する。

### 2.3 描く条件

次をすべて満たすときだけ描く。

1. 川のデータのロードが終わっている
2. フェーズが Rail
3. **カメラの Y が水面より上**

雲の中（51〜66秒）でロードが終わってすぐ描き始めても、フォグ（far 220m）で見えない。

## 3. 大河モードの水面（段階1）

### 3.1 PSO

- 大河モード用に **α ブレンドの PSO をもう1本**作る（シェーダは同じ）。ブレンドは**乗算済み α**（`SrcBlend = ONE`、`DestBlend = INV_SRC_ALPHA`）。
- 深度は書く（水面より奥の霧・パーティクルを正しく隠すため）。discard した所は書かない。
- 両面描画のまま（谷では §2.3 の条件で描かない）。

### 3.2 PS（大河モードの分岐）

1. ワールド XZ → 川のマップの UV。**範囲外なら discard**。
2. 水深 = R × maxDepth。**しきい値（既定 0.03m）未満なら discard**。
3. 不透明度：水深と見る角度から `T = exp(-k × 水深 / max(cos, 下限))`（T = 透過率）。浅い所はほぼ透明、深い所はほぼ不透明。
4. 水の色：浅い色と深い色を水深で混ぜ、太陽の光（影込み）＋環境光で照らす。
5. 反射：今と同じ（空の cubemap ＋遠景の雲。段階2 から反射 RT も）。
6. 合成（乗算済み）：
   - `rgb = 水の色 × (1 − T) × (1 − F) + 反射 × F`
   - `a = 1 − T × (1 − F)`
   - 下の地形は `dst × (1 − a) = dst × T × (1 − F)` で残る。透明な所でも反射は足される。
7. フォグ：α を掛ける前の色（`rgb / a`）にフォグを掛け、`a` を掛け直す。

### 3.3 波（段階1 は仮）

- 同心円の波は止める（`ambientRingScale = 0`）。
- 今の値ノイズの揺らぎをそのまま使う。**一方向の不規則な波は §6 の未決事項**。

### 3.4 調整値

- 保存先は **`Resources/Json/Tuning/RiverWater.json`**（L3 の所有。`Tuning/StagePlay.json` は L5 の所有なので混ぜない）。
- ImGui（StagePlay の「River Water」見出し）で変えて保存できるようにする。
- 波の時間は **World 時間**（スロー中は流れも遅くなる。ボス戦の水と同じ）。

## 4. 反射（段階2〜4）

> 反射の重さ（峡谷の地形が反射に入る件など）は **14番（`14_Optimization.md`）§4.4** で扱う。

### 4.1 共通

- ステージに `WaterReflection` を1つ置き、`RiverWater` が持つ。シーン描画の最初（本編の不透明物より前）に `Render` する。
- **解像度の倍率 0.5** から始める（流れで揺らぐので見分けがつかない。ぼかしの代わりにもなる）。細くて明るい物がちらついたら倍率を上げる。
- 歪みの強さ（`distortion`）はタイトルと同じ値から。
- **カメラの高さで足切り**：カメラの Y が `しきい値`（既定 100m、ImGui）より上なら反射のパスを飛ばす。手前の幅（既定 30m）で反射の強さを 0→1 に上げ、切り替わりを見せない。
- 鏡側は Y=0 より下を描かない（今のクリップ。オフセット 0.01）。地形の大半は水面より下なので、これで落ちる。

### 4.2 反射 RT の合成を乗算済み α に変える

今の水面は「反射 RT の α = 0 が空」として `lerp(空, RT.rgb, RT.a)` で混ぜている。加算のエフェクトは α を書かないので、このままでは映らない。

- 反射 RT を**乗算済み α** として扱う：`反射 = 空 × (1 − RT.a) + RT.rgb`。
- RT は (0,0,0,0) でクリアする。不透明のモデルは a=1 を書く（従来どおり）→ 結果は従来と同じ。
- 加算のエフェクト：rgb だけ足す（a は変えない）→ 空の上に光が足される。
- 半透明のエフェクト：rgb は通常の α ブレンド、**a は `ONE / INV_SRC_ALPHA`** で積む → 乗算済みとして正しく重なる。
- タイトルの見た目は変わらない（タイトルで映すのは不透明のモデルだけなので）。

### 4.3 距離判定：包む球

- 今は「物の原点までの距離 ≤ farClip」で判定している。地形は原点 (0,0,0) の 2000m 四方の1つの物なので、低空のカメラ（Z 1420〜2500）からは原点が 1400m 以上離れ、**一度も映らない**。
- **包む球（中心＋半径）**に変える：`中心までの距離 − 半径 ≤ farClip` なら描く。
- 球は **`.mesh` v4 のヘッダに持たせる**（2026-10-09 決定）。pack モード（Release）では頂点を CPU に持たず DirectStorage で VRAM へ直行するので、読み込み時に頂点から計算できないため。
  - `cook_assets.py` がクック時に計算（中心 = AABB の中心、半径 = そこから一番遠い頂点まで）。ヘッダ 296B の直後に center(3f)＋radius(1f) の 16B。データの位置は各 offset で引くので、読み手は v3 と同じ手順で読める。
  - エンジンは v3 も読める。v3 は頂点が CPU にあれば計算し、無ければ「分からない＝常に映す」。
  - スキニングモデルはバインドポーズの球（段階3 で余白を足す）。
  - 形式を上げた時の作り直しは `python tools/Python/cook_assets.py --meshes-only`（今ある .mesh だけを作り直す）。
- 描く時は `Object3DInstance::GetWorldBoundingSphere` で World 行列で中心を動かし、半径に最大のスケールを掛ける。
- 例：地形は 中心 (0, −22, 1750)・半径 1319m。低空のカメラは球の中にいるので必ず映る。
- farClip の既定は 2500m（LowAltitude のフォグの far。それより遠い物は霧で見えない）。

### 4.4 登録：タグで毎フレーム登録し直す

- 敵や弾は出たり消えたりするので、**毎フレーム `ClearTargets` → 映すタグを持つ物を追加**する（消えた物を指したまま残らない）。
- 映すタグの一覧の初期値：**`Terrain` / `Player` / `Enemy` / `Boss`**（JSON＋ImGui で変更可）。L6 の岩・L10 の木は、その章でタグを付けて一覧に足す。
- エフェクトはタグを持たないので**全部映す**。`EffectDef` に `"reflect"`（既定 true）を足し、false で外す。エフェクトは広がる範囲が事前に分からないので距離判定はしない。

### 4.6 映った物の揺らぎ（2026-10-09、L2 のチャットでユーザーの許可を得て変更。実機確認済み）
- **問題**（実機）：映った山が揺らがず、周りの水面（空の映り込み）と合わない。
- **原因**：空と反射 RT は同じ波の法線を使うが、効かせ方が違った。空は「波で傾いた反射の向き」で cubemap を引く（法線 0.1 の傾きで向きが約 11° 動く）。反射 RT は UV を `normal.xz × distortion(0.03)` ずらすだけ（画面の 0.3% 程度）。
- **却下した案**：空も反射 RT に描いてからまとめて揺らす。空のパス（雲込みで 2.6〜2.9ms）を反射用にもう一度描くことになるうえ、揺らし方は弱い UV ずらしの側に寄るため。
- **採用**：反射 RT も「波で傾いた反射の向き」で引く。反射の向きの鏡像（Y を反転）へ想定距離 `reflectionDistance` だけ進んだ点を、反射を作った視点の ViewProj で投影して UV にする。波が無ければ鏡像の向き＝視線の向きなので、従来の UV と一致する。距離を大きくするほど空（無限遠）と同じ揺れ方に近づく。近くの物（自機など）は実際より少し大きく揺れるが、低空ではほぼ映らない（11 番 §5.3）。追加コストは行列の掛け算 1 回。
- 調整値：`WaterSurface::Params::reflectionDistance`（既定 0 ＝従来。**タイトルの水面は 0 のままで不変**）。大河は `RiverWater` が 300m を入れ、`Tuning/RiverWater.json` の `surface.reflectionDistance`、ImGui の "Reflection Distance [m]" で変える。従来の `distortion` の UV ずらしはその後に足される（併用）。

### 段階3: アニメーションするモデルを映す（2026-10-09 実装・実機確認済み。影も映る）

- `AnimatedObject3DInstance::DrawReflection`：反射のパスの中で `DispatchSkinning`（1 フレーム 1 回のフラグがあるので本編で二重に回らない）→ 反射用 PSO → `DrawSkinning`。
- `AnimatedObject3DInstance::GetWorldBoundingSphere`：バインドポーズの球 × 1.5（ポーズで外に出る分の余白）。ワールド行列は Update で CPU 側に控える（転送用 CB は読まない）。
- `WaterReflection::AddTarget(AnimatedObject3DInstance*)`、`RiverWater::RenderReflection` にシーンの `dynamicAnimated_` を渡す。
- 今の敵（プレハブの kind = Object3D）は段階2 から映っている。アニメーションする敵は `dynamicAnimated_` に入るので、タグが合えば映る。
- 映らない物：武器（`weapon_`。シーンの一覧の外で描いている）。必要になったら別に登録する。

### 段階4: エフェクトを映す（2026-10-09 実装・実機確認済み）
- `WaterReflection::SetDrawEffects(true)`（大河だけ。タイトルは false のまま）。不透明の物を描いた後、`EffectManager::DrawReflection` で GPU パーティクル → エフェクトの Primitive の順に描く。ビルボードに View が要るので `Render(const Camera&)` の時だけ描く。
- 鏡像の View = 鏡像行列 × 本編の View。ビルボードをこれで組むと、反射の中でも粒子が画面を向く。
- GPU パーティクル：グループごとに反射用の PerView CB を足し、`DrawReflection` は**シミュレーションせずに描くだけ**（反射のパスはシーン描画の最初＝今フレームの Draw の前なので、前フレームに進めた粒子を描く。1 フレーム遅れは見分けられない）。未初期化のグループは描かない（粒子バッファが COMMON 状態のため。ブルームと同じ扱い）。
- Primitive：`PrimitiveMesh` に反射用の Transform CB と `DrawReflection` を足す。鏡像で巻きが反転するので裏面カリングは切る。
- `EffectDef::reflect`（JSON の `"reflect"`、既定 true。true の時は書き出さない）。false ならそのエフェクトの Primitive と粒子グループを映さない。
- **今の制限（必要なら後で直す）**
  - 加算のエフェクトの α：本編用の PSO をそのまま使っているので、α は `ONE / INV_SRC_ALPHA` で積まれる。§4.2 の「加算は a を変えない」にはならず、反射の中では加算の光が下の空を少し隠す（普通の半透明に近い見え方）。直すなら反射用に α の積み方だけ違う PSO を作る。
  - 水面より下に出たエフェクトも鏡像にして描く（Primitive / 粒子の VS はクリップ面を持たない）。水面すれすれの爆発で、水中に入った部分が反射に出ることがある。
- 確認用：Hierarchy の None グループの `[Water] RiverWater` → Inspector「Reflection → Test Effect」で `Death_Drone` をカメラの前方（既定 80m 先・水面から 3m）に出す。Auto Repeat で一定間隔に出し続ける（Debug のみ）。

**完了条件**：水面に地形・自機・敵・エフェクトが映る／高度が高いと反射のパスが飛ぶ（PEPPER で確認）／タイトルの見た目が変わらない。

## 8. 自機の航跡（2026-10-25 方針決定）

水面すれすれを飛ぶ自機の後ろに、船の航跡のように左右へ広がる波を立てる。

### 8.1 方針
- 条件は 11 番 §3.4（L4 → L7、ユーザー追記）のとおり：**水面に触れた時ではなく、水面からの距離（目安 2〜3m 以内）で、高速で近くを通った風で水面が波立つ**。既定の自機の高さは水面から約 1.7m。
- 今ある **`RippleSimulation`（2 次元の波動方程式を GPU で解く）** を流用する。大河モードの水面 PS はもとからこの高さマップを法線に足している（`WaveGradient`）ので、水面側の描画の変更は要らない。
- 動く波源が波の速さより速いと、後ろに V 字の波ができる。半分の角度は `asin(波の速さ ÷ 自機の速さ)`。波 8m/s・自機 26m/s で約 18° になり、船の航跡（ケルビン波 約 19.5°）とほぼ同じ形になる。自機が上下左右に動けば波も曲がり、重なった所は干渉する。
- **却下した案**：軌跡の点を数十個シェーダに渡して輪を式で重ねる（`EmitRing` の拡張）。水面の全ピクセルで数十回の繰り返しが要るうえ、干渉もしない。
- 見え方：カメラは自機の 12m 後ろで、水面は 11m 先から映る（11 番 §5.1）。見える航跡は「自機の真下から左右へ広がっていく所」が中心になる。

### 8.2 範囲を自機について動かす（スクロール）
- `RippleSimulation::SetScrollWithCenter(true)` で、**波はワールドに残し、範囲だけ中心について動かす**。範囲の中心はテクセルの格子にそろえ、動いた分（整数テクセル）だけ最初の刻みで読む位置をずらす（CS の `gShift`）。端数は次のフレームへ持ち越す。新しく入ってくる所は平らな水。
- 刻みを回さないフレームはずらさず、`GetCenter()`（PS が UV を出す中心）も前のまま。中身と範囲が食い違わない。
- 範囲より大きく飛んだ時（シーク等）は消してそこから始める。
- 波源は AddImpulse の時点ではワールド座標で溜め、Dispatch でずらした後の範囲の UV にする。
- **既定はオフ**（今までどおり、中心を動かすと波も一緒に動く）。ガラス球の液面（`LiquidGlassSphere`）は球が振れても波が器についていくのが正しいので、オフのまま。タイトル・ボス戦・画面の水（`ScreenWaterSurface`）も変わらない。

### 8.3 実装ステップ
| 段階 | 内容 | 状態 |
|---|---|---|
| 段階1 | `RippleSimulation` のスクロール（§8.2）。エンジンの変更（ArcanaEngine の同期対象） | 2026-10-25 ビルド OK |
| 段階2 | `RiverWater` が自機の位置を受け取り（`StagePlayScene` から）、スクロールをオンにして範囲（64m 四方＝1 テクセル 0.125m、中心は自機より少し後ろ）を自機について動かす。前のフレームの位置との間を細かく分けて波源を入れる（点線にならないように。タイトルのマウスの波紋と同じ手順）。強さは「水面からの高さ（3m→1m で 0→1）× 速さ」。`DispatchSimulation` をシーン描画の最初に呼ぶ。シーク・ロード前は消す。調整値は `Tuning/RiverWater.json` の `wake`（波の速さ・減衰・強さ・しきい値）と ImGui | 2026-10-25 ビルド・実機 OK（§8.4。値はユーザーが実機で決定） |
| 段階3（任意） | 白い泡の筋：波の山・急な傾きの所を白く寄せる（大河モードの分岐だけ。テクスチャは増やさない）。低いカメラから浅い角度で見ると、法線だけでは反射のゆがみにしか出ず弱く見える恐れがあるため | **削除（2026-10-25、ユーザー判断「あまりいい感じにならないから泡無しでいい」）**。試した方式と教訓は §8.5 |

- 波の速さの上限：CFL 条件 `k = (c·Δt/Δx)² < 0.5`（コードは 0.45 で止める）。64m 四方・毎秒 60 刻みなら c ≈ 5m/s まで。→ 段階2 で**毎秒 120 刻み**にした（上限 約 10m/s）。
- 実機で決める値：波の速さ（V 字の開き具合）、波が消えるまでの長さ（減衰）。

### 8.4 段階2 の作り（2026-10-25）
- `StagePlayScene` が Rail フェーズの Update で `RiverWater::Update(秒, World の dt, &自機の位置)` を呼び、Draw の最初（反射 RT の前）に `RiverWater::DispatchSimulation()` を呼ぶ。
- `RiverWater::UpdateWake`（水面のロード後だけ）：
  - 範囲の中心＝自機の位置から、水平の進む向きの後ろへ `backOffset`（12m）。カメラは自機の 12m 後ろなので、見える所（自機の真下〜カメラの手前の左右）が範囲に入る。
  - 強さ＝`(1 − smoothstep(fullHeight 0.5m, maxHeight 2m, 水面からの高さ)) × smoothstep(minSpeed 5, fullSpeed 25m/s, 水平の速さ)`。高さは自機の位置（Translate）の Y − 水面の Y。
  - 前のフレームの位置から今の位置までを `spacing`（0.25m）おきに分けて波源を置く（1 フレーム最大 32 個）。1 つの深さは `min(strengthPerMeter × 進んだ距離 ÷ 個数, maxStrength)` × 強さ（strengthPerMeter 0.2・maxStrength 0.4・半径 0.6m）。タイトルのマウスの波紋と同じ手順。

- 調整：Hierarchy の None グループの `[Water] RiverWater` → Inspector「Wake」。今の高さ・速さ・強さ・V 字の角度・CFL の上限を表示。Save River Water で `Tuning/RiverWater.json` の `wake` に保存（波の伝わり方もここに入れる。水面の「Ripple Simulation (GPU)」の欄と同じ値）。
- **値の決定（2026-10-25、ユーザーが実機で）**：maxHeight 2 / fullHeight 0.5 / minSpeed 5 / fullSpeed 25 / radius 0.6 / strengthPerMeter 0.2 / maxStrength 0.4 / spacing 0.25 / backOffset 12 / teleportDistance 30。JSON には保存されていなかったので、コードの既定値（`RiverWater::WakeTuning`）をこの値にした。

4 つの方式を実機で試し、ユーザー判断で**泡は無し**にした。コードはすべて取り除いた（`WaterSurface::Params` の泡・きらめき・航跡の折れ線、水面 PS の泡・セルノイズ・きらめき、`RippleSimulation` の泡の B と帯の A、`RiverWater` の通った線と調整値）。

## 9. 画面の水滴（2026-10-25、ユーザーの参考：エースコンバット8 のキャノピーの水滴＋スケッチ）

水面すれすれを飛ぶと、水しぶきが画面（レンズ）に付く。

| 自機 | 水滴 |
|---|---|
| 水面から高い | 画面の下の方に小さな水滴が付き、垂れずに乾いて消えていく |
| 水面に低い | 水滴が大きく増え、上の方まで付き、一部は下へ垂れて筋を引く |

### 9.1 作り
- **ポストエフェクト `ScreenDropletEffect`**（エンジン、`GameEngine/Graphics/OffscreenRendering/FilterEffect/`、シェーダ `Resources/Shaders/PostEffect/Filters/ScreenDroplet.PS.hlsl`）。`PostEffect` に `screenDroplet` として登録し、並びはビネットの前（ブルームはチェーンの先頭）。
- **水滴は状態を持たない**：画面を格子に分け、マスごとの乱数で位置・大きさ・現れる時刻を決める。
  - 止まっている水滴：2 段の格子（`density` とその 2.3 倍の小さい粒）。周期（`lifetime` の 0.6〜1.4 倍）ごとに現れ、ゆっくり縮んで乾く。付く割合は画面の高さで決め（`coverageTopDry`→`coverageTopWet` より下）、マスの中心の高さで判定する（水滴の途中で欠けないように）。
  - 垂れる水滴：縦の列（`dripColumns`）ごとに 1 粒が滑り落ち（`dripSpeed`、左右に少し揺れる）、通った跡に上ほど細い筋（`trailLength`）を残す。列の割合は `dripChance × smoothstep(0.3, 1, 濡れ具合)`。
  - 見た目：水滴の中はレンズとして、丸みの分だけ逆向きにずらした位置の景色を映す（`refraction`）。重さで下側が少しふくらむ形。ふちを暗く（`rimDarkness`）、左上を光らせる（`highlight`）。
- **濡れ具合（0..1）だけで動かす**：数・大きさ（`dryScale`→1）・垂れる割合・付く高さが濡れ具合で変わる。濡れ具合は目標へ指数で追いかけ、濡れるのは速く（`wetTime` 0.3 秒）、乾くのはゆっくり（`dryTime` 2.5 秒）。0 に戻ると自分で無効になり、パスを飛ばす。
- **濡れ具合の目標は `RiverWater` が決める**：航跡と同じ「水面に近く、速いほど強い」形で、高さは `dropletFullHeight` 1m → `dropletMaxHeight` 6m（航跡より高い所から濡れ始める）、速さは航跡と共通（5→25m/s）。川のロード前は 0。
- 着陸・ボス戦では `RiverWater::UpdateOutsideRail` で乾かす。シーンを抜ける時は `RiverWater` の破棄で消す（PostEffect はシーンをまたいで残るため）。

### 9.2 調整
- Hierarchy の None グループの `[Water] RiverWater` → Inspector「Screen Droplets」。高さのしきい値、今の目標、水滴の見た目の値すべて。`Preview` にチェックすると濡れ具合を手で動かせる（Rail フェーズ中）。PostEffect の窓は有効な時しか値を出さないので、こちらから触る。
- 保存は `Tuning/RiverWater.json` の `droplets`（見た目）と `wake.dropletMaxHeight` / `dropletFullHeight`。シーン開始の `ResetEffects` で既定値に戻るので、`RiverWater` の初期化（雲の上の後回しの初期化）で入れ直す。

### 9.3 形・入れ替わり・範囲の直し（2026-10-25、実機の指摘）
- **指摘**：水滴が丸すぎる。入れ替わりが全然なく、画面の下半分くらいまで来てしまう。上限は下半分、水面から離れるほど付く範囲は少なく画面の下の方に。水面から離れた後は消えやすく。**水滴のライティング（ふちの暗さと光）は良い**。
- **形**：水滴ごとの乱数で向き・縦横の伸び（0.8〜1.25）・ふちのでこぼこ（3 と 5 の山）を変える。重さで下がふくらむ形と光はそのまま。
- **入れ替わり**：これまでマスごとに位置が固定で、乾いても同じ所に同じ水滴が現れていた → **周期ごとに位置・大きさ・形・出るかを引き直す**。寿命 3 → **1.6 秒**、すぐ現れて 35% から縮み始める。付く割合も少し下げた（濡れ具合 0→1 で 0.25→0.7）。
- **範囲**：`coverageTopWet` 0.3 → **0.5**（濡れきっても画面の下半分まで）、`coverageTopDry` 0.75 → **0.88**（水面から離れるほど下端へ寄る）、`coverageFade` 0.15。垂れる水滴も付き始めの高さより下から始まる。
- **乾き**：`dryTime` 2.5 → **0.8 秒**。

### 9.4 並び・合体・大きさの直し（2026-10-25、実機の指摘）
- **指摘**：まだ格子に並んで見える。最低高度なのに水滴が大きくならず点ばかり。落ちていく水滴が全然無い。大きめの水滴は垂れてほかの水滴と合体し、垂れる速さが速くなるように。小さすぎる水滴は白い点にしか見えない。
- **並び**：§9.3 で、はみ出して切れないようマスの中のずれを 0.1 にしていたため、ほぼ格子の中心に並んでいた → **周りのマス（3×3）も調べ、マスのどこにでも置く**（0.1〜0.9）。水滴が付かない上の方は調べずに飛ばす。
- **大きさ**：半径の散らばりを 2 乗（小さい方に偏る）から均等に。格子 12 → **9** マス、`sizeMin` 0.08 → **0.15**、`sizeMax` 上限 0.35、`dryScale` 0.6、2 段目は 1.7 倍・0.85 倍。小さな水滴（半径 0.004〜0.012）は光を弱める（白い点の正体は光）。濡れきる高さ `dropletFullHeight` 1 → **2m**（自機の既定の高さ 約 1.7m で 1m では濡れきっていなかった）。
- **垂れる水滴**：止まっては滑るを繰り返し（`dripStepRate` 3 回/s）、合体して重くなる分だけ加速（`dripAccel` 0.8）、進むほど大きくなる（`dripGrow` 0.8）。**通り道の止まっている水滴は消す**（吸い込んで合体したように見える）。`dripChance` 0.35 → **0.6**、`dripColumns` 10 → **14**、濡れ具合 0.2 から垂れ始める。

### 9.5 波と同期（2026-10-25、ユーザー指示）
- **指示**：波と同期させて、波の出る最高高度で小さい水滴が出始めるように。
- 濡れ具合の目標を**航跡の波の強さ（Wake の Factor）そのもの**にした。波が出始める高さ（`maxHeight` 2m）で小さな水滴が付き始め、波が最大になる高さ（`fullHeight` 0.5m）で濡れきる。速さのしきい値も波と同じ。
- 水滴専用の高さのしきい値（§9.1 の `dropletMaxHeight` / `dropletFullHeight`、§9.4 の 2m）は取り除いた。高さを変えるときは「Wake」の `Max Height` / `Full Height` を触る（波と水滴が一緒に動く）。

### 9.6 つながり・滑る水滴・高さで大きさ（2026-10-25、ユーザー指示）
- **指示**：水滴同士がつながって大きくなって垂れるように。付く範囲の上の方は小さい水滴が出やすく、下の方は大きい水滴が出やすく。
- **つながり（メタボール）**：これまでは重なった水滴のうち一番覆っている 1 粒を選んでいたので、くっついても境目が残った → 水滴ごとの「広がり」（形の距離 d を半径の 1.4 倍で割り、`(1 − d²)³`）を足し合わせ、1 粒だけの時に半径の所になるしきい値（0.1176）を越えた所を水滴にする。近い水滴同士は橋でつながって 1 つに見える。大小 2 段と垂れる水滴の先頭も同じ足し合わせに入れる（互いにつながる）。レンズのずらしは広がりで重み付けした平均、光は一番強い物。筋は足し合わせず、覆いの強い方を使う。
- **滑る水滴**（※ §9.7 で垂れる水滴に統合して取り除いた）：大きさの乱数が `slideThreshold`（0.75）以上で、濡れ具合 0.3 より上の水滴は、寿命の 25% から下へ滑り始めて加速する（`slideDistance` 0.18、少し左右に揺れる）。乾いて縮むのは寿命の 85% から。出た所から今の位置まで細い筋を引く。滑る分を見込んで、上のマスは 2 つまで調べる（4×3 マス × 2 段）。
- **高さで大きさ**：付く範囲の中の深さ（上端 0 → 下端 1）で、大きさの倍率（上端で `topSizeScale` 0.5 倍）と散らばり方（大きさの乱数を上は 2 乗＝小さい方へ、下は 0.6 乗＝大きい方へ偏らせる）を変える。
- **重さ**：調べるマスが 9 → 12（× 2 段）に増えた。水滴が付かない上の方は飛ばしている。気になったら PEPPER で測る。

### 9.7 垂れ方と跡の作り直し（2026-10-25、実機の指摘）
- **指摘**：垂れる時にカクカク左右に動く。しきい値を超えた（大きい）水滴は乾いて消えるのではなく、垂れ切って消したい。垂れた軌跡がリアルじゃない。
- **カクカク**：横の揺れの周波数が高く（23・57）、そこへ「止まっては滑る」の急な進みが重なって横が跳んでいた → 揺れはゆるく小さく（7・15、幅の 6%・2.5%、膨らんだ所ではまっすぐ）、進み方は止まらない加速＋少しのためらい（`速さ × (t + 加速 × t² − 0.35 × sin(ためらい × t) / ためらい)`。0.35 < 1 なので後戻りも停止もしない）。
- **垂れ切って消す**：§9.6 の「止まっている水滴が滑る」（格子 2 マス分しか動けず、途中で消えていた）を取り除き、**大きい水滴はすべて垂れる水滴の仕組みで扱う**（列ごとの 1 粒なので画面の下まで動ける）。1 粒の流れは「その場でつながりながら膨らむ（`dripGrowTime` 0.8 秒、半径 0.35 → 1 倍）→ 滑り始めて加速 → 下端の先へ抜けて消える → 間を空けて次」。周期は一番上から抜けきるまでの時間で決め（粒ごとに変えると時刻が飛ぶ）、膨らむ場所は 1 粒ごとに列の中・付く範囲の中で引き直す（列に並んで見えないように）。止まっている水滴は小さい物だけで、乾いて消える。
- **跡**：これまでの「先頭から上へ細くなるなめらかな 1 本線」をやめ、
  - 薄い濡れた筋（半径の 0.22 倍、覆い 0.55）。半径 1.2 倍ごとの区切りで乱数により途切れる（水が切れて乾いた所）
  - 取り残された小さな粒（`trailBeadSpacing` 0.025 おき・半分ほどの所に、半径の 0.15〜0.35 倍）。**画面上の位置に留まる**（先頭と一緒に動かない）。メタボールでほかの水滴とつながる
  - 筋も粒も、先頭から遠い（古い）ほど薄れ・縮み、`trailLength`（0.25 → 0.35）で消える
- **値の入れ替え**：`slideThreshold` / `slideDistance` を取り除き、`dripGrowTime` / `trailBeadSpacing` を足した（定数バッファの同じ場所）。

### 9.8 縮めずに薄くして消す（2026-10-25、実機の指摘）
- **指摘**：水滴のサイズが小さくなってフェードすると違和感がある。どんどん薄くしていく感じで消したい。
- **止まっている水滴**：寿命と付く割合（濡れ具合が下がった所）は**大きさではなく不透明度**に掛ける（すぐ現れ、35% から薄れ始める）。大きさは現れてから消えるまで変えない。
- **跡に残る粒**：古い方から縮むのをやめ、薄れて消える。
- **つながりと不透明度**：メタボールの広がりは形だけを決め、不透明度は「水滴ごとの不透明度を広がりで重み付けした平均」（`DropSum::opacity / field`）を覆いに掛ける。光も不透明度で弱める。
- **乾く時に縮まない**：大きさは濡れ具合で変わる（`dryScale`→1）ので、乾く間（`dryTime` 0.8 秒）に見えている水滴が縮んでいた → 大きさには別の濡れ具合 `sizeWetness`（上がる時は `wetTime`、下がる時は `sizeDryTime` 3 秒でゆっくり）を使う。定数バッファの末尾に 1 行足した。

### 9.9 雲の縦穴の水滴（放射モード）（2026-10-25、ユーザー承認）
- **指示**：雲の縦穴を抜ける所でも使う。ビネットを応用して画面の周りに付ける。水滴は水面近くより小さく、霧雨のように小さい雨がいっぱい付いて合体して大きくなる。すべての水滴が画面の外側へ放射状に移動する。

| | 重力（Gravity・水面すれすれ） | 放射（Radial・雲の縦穴） |
|---|---|---|
| 付く場所 | 画面の下の方（画面の高さで測る） | 画面の周り（中心からの距離をビネットと同じく測る：0=中心・辺の中央 0.71・角 1） |
| 止まっている水滴 | 正方形の格子。動かない | **対数極座標の格子を外へ流す**（`flowSpeed` 0.5：中心からの距離が毎秒 e^0.5 倍）。マスは外ほど大きい正方形で、格子ごと流れるので水滴はマスをまたいでも切れない。外ほど速く・大きく見える |
| 大きい水滴 | 下へ垂れる | 外へ向かって加速し、画面の外へ抜ける（列は角度で分け、1 周で `dripColumns × 2.5` 列） |
| 既定の値 | クラスの既定 | 霧雨向け：格子 22（細かい）、垂れる水滴の半径 0.012、`dripGrow` 1.2、付く範囲 0.85→0.55 など（`ScreenDropletEffect::DefaultSettings`） |

- **流れの座標**：シェーダは「u = 流れに直交、v = 流れる向き」で動かす。重力 (x, y)、放射（画面を正方形に直した中での角度, 中心からの距離）。垂れる水滴の v と付く範囲の値がそろう。水滴の形・レンズ・光は画面の座標で作る（流れの座標でゆがまない）。水滴の重い側（ふくらむ側）も流れる向き。
- **合体**：メタボール（§9.6）がそのまま効く。霧雨の小さい水滴が密に付くと、近い物同士がつながって大きく見える。垂れる水滴の通り道の水滴は消える（吸い込み）。
- **モードの切り替え**：水滴が見えている間に切り替えると跳ぶので、**乾ききった時（濡れ具合 0）だけ**切り替える。違うモードを求められたら、まず今のモードで乾かす。縦穴（54〜66 秒）と低空の川（72 秒〜）の間に乾く時間がある。
- **濡れ具合**：
  - 川：`RiverWater::GetDropletTarget()`（＝航跡の波の強さ。§9.5）
  - 雲：`StageEnvironment::GetCloudDropletTarget(視点)`。視点が雲の層（`CloudRaymarcher` の下面 300m〜最高点 850m）の中で 1、上下の端 60m（`kCloudDropletEdge`）で 0→1、雲の不透明度を掛ける。雲が無効なら 0。時刻ではなく高さで決めるので、雲の層の値を変えても合う
  - **`StagePlayScene` が 1 か所で大きい方を選び、モード（雲の方が大きければ放射）と一緒にフィルタへ渡す**（2 か所から動かすと打ち消し合う）。Rail 以外は 0（乾く）。シーンの `Finalize` で消す。
- **値の置き場所**：`Resources/Json/Tuning/ScreenDroplet.json` の `gravity` / `radial`（フィルタ自身が読み書きする。`StagePlayScene::Initialize` の `ResetEffects` の後に読む）。`RiverWater.json` の `droplets` は取り除いた（一度も保存されていなかった）。
- **調整**：Inspector の `[Water] RiverWater` →「Screen Droplets」。`Edit` で触るモードを選ぶ、`Preview (edit mode)` で濡れ具合とモードを手で動かせる、Save / Reload。
- **重さ**：放射は格子が細かく、マスごとに exp / cos / sin を引く。気になったら PEPPER で測る。

### 9.10 大きさで速さを変える（2026-10-25、ユーザー指示）
- **指示**：もう少し合体して垂れる水滴を増やしたい。全水滴が同じ速さで外へ動くとただの泡に見えるので、大きい水滴ほど速く移動させて速さを変え、それがほかの水滴と合体して垂れる水滴を増やす。
- **大きさで速さ**：止まっている水滴は格子の流れ（`flowSpeed`）に加えて、寿命の間に `sizeSpeed × 大きさの乱数² × (寿命の割合)²` マス余分に流れる向きへ滑る（大きいほど速く、加速する）。滑る分を見込んで、流れの上流は 2 マスまで調べる（4×3 マス）。`sizeSpeed` は 1.8 まで。放射の既定 1.6、重力は 0（今のまま）。
- **合体して垂れる**：速く滑る大きい水滴は途中の小さい水滴とメタボールでつながる。0.2 マス以上滑った水滴は、出た所から今の所まで細い筋を引く（古い方ほど細く薄い）。
- **垂れる水滴を増やす**：放射の既定 `dripChance` 0.5 → 0.8、`dripColumns` 16 → 22（1 周 55 列）。
- 定数バッファの空き（padding）を `sizeSpeed` に使った。

### 9.11 流れを遅く（2026-10-25、実機の指摘）
- **指摘**：入れ替わりが多すぎて炭酸ジュースのようになり、合体や垂れが見づらい。画面の外へ行く速さを少し落としたい。
- 放射の既定：`flowSpeed` 0.5 → **0.25**（中心からの距離が 4 秒で約 2.7 倍）、`lifetime` 2.0 → **3.2 秒**（入れ替わりを減らす）、`dripSpeed` 0.25 → **0.18**。
