## 2. クラスとロードの流れ

### 2.1 役割分担

| クラス | 場所 | 役割 |
|---|---|---|
| `WaterSurface` | エンジン `Graphics/Water` | 水面の描画。大河モード（α ブレンドの PSO・t10 の川のマップ・大河用のパラメータ）を**追加**する。タイトル・ボス戦は従来の PSO のまま |
| `RiverWater` | ゲーム `Game/Scene` | ステージの大河の水面。`WaterSurface` を大河モードで持ち、ロードの時期・描く条件・シークを管理する。`IImGuiEditable` なので Hierarchy に「RiverWater」として出て、Inspector で調整・保存する（シーン JSON には保存しない。コードで生成） |
| `StagePlayScene` | ゲーム | `RiverWater` を生成し、Update / Draw / Seek / ImGui を呼ぶだけ |

### 2.2 ロード

DirectStorage 自体は非同期で動かせるが、今のエンジンの `TextureManager` の GPU フェーズは `DStorageManager::SubmitAndWait` で完了を待つ。待たない API（`SubmitAsync` → `IsComplete`）は **L9 の作業**なので、L3 は今の API で作り、できたら差し替える（11 番 §3.4 で L9 へ依頼）。

| 時期 | スレッド | 内容 |
|---|---|---|
| シーン初期化 | メイン | `WaterSurface` の生成（ルートシグネチャ・PSO 2 本・CB・頂点バッファ・代わりのテクスチャ）。シェーダを実行時に DXC でコンパイルするので、**重い処理は全部ここ** |
| 雲の中（既定 51秒、ImGui で変更可） | 別スレッド | `RiverTerrain.json` の読み込み、川のマップの CPU フェーズ（`TextureManager::LoadTextureCPU`） |
| CPU フェーズの完了後の最初の Update | メイン | 川のマップの GPU フェーズ（`LoadTextureGPU`。1MB なので待ちは小さい）→ `WaterSurface::SetRiverMap` → 水面を有効にする |
| シーク | メイン | ロード開始時刻より後へ飛んだら、その場で同期ロード。ロード中なら完了を待つ |

- ロードしたデータは捨てない（川のマップは 1MB。低空の破棄 ≈126秒は L9 が決める物で、水面は対象外）。
- 別スレッドは `RiverWater` が持ち、破棄時に必ず join する。

### 2.3 描く条件

次をすべて満たすときだけ描く。

1. 川のデータのロードが終わっている
2. フェーズが Rail
3. **カメラの Y が水面より上**

雲の中（51〜66秒）でロードが終わってすぐ描き始めても、フォグ（far 220m）で見えない。

## 3. 大河モードの水面（段階1）

### 3.1 PSO

- 大河モード用に **α ブレンドの PSO をもう1本**作る（シェーダは同じ）。ブレンドは**乗算済み α**（`SrcBlend = ONE`、`DestBlend = INV_SRC_ALPHA`）。
- 深度は書く（水面より奥の霧・パーティクルを正しく隠すため）。discard した所は書かない。
- 両面描画のまま（谷では §2.3 の条件で描かない）。

### 3.2 PS（大河モードの分岐）

1. ワールド XZ → 川のマップの UV。**範囲外なら discard**。
2. 水深 = R × maxDepth。**しきい値（既定 0.03m）未満なら discard**。
3. 不透明度：水深と見る角度から `T = exp(-k × 水深 / max(cos, 下限))`（T = 透過率）。浅い所はほぼ透明、深い所はほぼ不透明。
4. 水の色：浅い色と深い色を水深で混ぜ、太陽の光（影込み）＋環境光で照らす。
5. 反射：今と同じ（空の cubemap ＋遠景の雲。段階2 から反射 RT も）。
6. 合成（乗算済み）：
   - `rgb = 水の色 × (1 − T) × (1 − F) + 反射 × F`
   - `a = 1 − T × (1 − F)`
   - 下の地形は `dst × (1 − a) = dst × T × (1 − F)` で残る。透明な所でも反射は足される。
7. フォグ：α を掛ける前の色（`rgb / a`）にフォグを掛け、`a` を掛け直す。

### 3.3 波（段階1 は仮）

- 同心円の波は止める（`ambientRingScale = 0`）。
- 今の値ノイズの揺らぎをそのまま使う。**一方向の不規則な波は §6 の未決事項**。

### 3.4 調整値

- 保存先は **`Resources/Json/Tuning/RiverWater.json`**（L3 の所有。`Tuning/StagePlay.json` は L5 の所有なので混ぜない）。
- ImGui（StagePlay の「River Water」見出し）で変えて保存できるようにする。
- 波の時間は **World 時間**（スロー中は流れも遅くなる。ボス戦の水と同じ）。

## 4. 反射（段階2〜4）

> 反射の重さ（峡谷の地形が反射に入る件など）は **14番（`14_Optimization.md`）§4.4** で扱う。

### 4.1 共通

- ステージに `WaterReflection` を1つ置き、`RiverWater` が持つ。シーン描画の最初（本編の不透明物より前）に `Render` する。
- **解像度の倍率 0.5** から始める（流れで揺らぐので見分けがつかない。ぼかしの代わりにもなる）。細くて明るい物がちらついたら倍率を上げる。
- 歪みの強さ（`distortion`）はタイトルと同じ値から。
- **カメラの高さで足切り**：カメラの Y が `しきい値`（既定 100m、ImGui）より上なら反射のパスを飛ばす。手前の幅（既定 30m）で反射の強さを 0→1 に上げ、切り替わりを見せない。
- 鏡側は Y=0 より下を描かない（今のクリップ。オフセット 0.01）。地形の大半は水面より下なので、これで落ちる。

### 4.2 反射 RT の合成を乗算済み α に変える

今の水面は「反射 RT の α = 0 が空」として `lerp(空, RT.rgb, RT.a)` で混ぜている。加算のエフェクトは α を書かないので、このままでは映らない。

- 反射 RT を**乗算済み α** として扱う：`反射 = 空 × (1 − RT.a) + RT.rgb`。
- RT は (0,0,0,0) でクリアする。不透明のモデルは a=1 を書く（従来どおり）→ 結果は従来と同じ。
- 加算のエフェクト：rgb だけ足す（a は変えない）→ 空の上に光が足される。
- 半透明のエフェクト：rgb は通常の α ブレンド、**a は `ONE / INV_SRC_ALPHA`** で積む → 乗算済みとして正しく重なる。
- タイトルの見た目は変わらない（タイトルで映すのは不透明のモデルだけなので）。

### 4.3 距離判定：包む球

- 今は「物の原点までの距離 ≤ farClip」で判定している。地形は原点 (0,0,0) の 2000m 四方の1つの物なので、低空のカメラ（Z 1420〜2500）からは原点が 1400m 以上離れ、**一度も映らない**。
- **包む球（中心＋半径）**に変える：`中心までの距離 − 半径 ≤ farClip` なら描く。
- 球は **`.mesh` v4 のヘッダに持たせる**（2026-10-09 決定）。pack モード（Release）では頂点を CPU に持たず DirectStorage で VRAM へ直行するので、読み込み時に頂点から計算できないため。
  - `cook_assets.py` がクック時に計算（中心 = AABB の中心、半径 = そこから一番遠い頂点まで）。ヘッダ 296B の直後に center(3f)＋radius(1f) の 16B。データの位置は各 offset で引くので、読み手は v3 と同じ手順で読める。
  - エンジンは v3 も読める。v3 は頂点が CPU にあれば計算し、無ければ「分からない＝常に映す」。
  - スキニングモデルはバインドポーズの球（段階3 で余白を足す）。
  - 形式を上げた時の作り直しは `python tools/Python/cook_assets.py --meshes-only`（今ある .mesh だけを作り直す）。
- 描く時は `Object3DInstance::GetWorldBoundingSphere` で World 行列で中心を動かし、半径に最大のスケールを掛ける。
- 例：地形は 中心 (0, −22, 1750)・半径 1319m。低空のカメラは球の中にいるので必ず映る。
- farClip の既定は 2500m（LowAltitude のフォグの far。それより遠い物は霧で見えない）。

### 4.4 登録：タグで毎フレーム登録し直す

- 敵や弾は出たり消えたりするので、**毎フレーム `ClearTargets` → 映すタグを持つ物を追加**する（消えた物を指したまま残らない）。
- 映すタグの一覧の初期値：**`Terrain` / `Player` / `Enemy` / `Boss`**（JSON＋ImGui で変更可）。L6 の岩・L10 の木は、その章でタグを付けて一覧に足す。
- エフェクトはタグを持たないので**全部映す**。`EffectDef` に `"reflect"`（既定 true）を足し、false で外す。エフェクトは広がる範囲が事前に分からないので距離判定はしない。

### 4.6 映った物の揺らぎ（2026-10-09、L2 のチャットでユーザーの許可を得て変更。実機確認済み）
- **問題**（実機）：映った山が揺らがず、周りの水面（空の映り込み）と合わない。
- **原因**：空と反射 RT は同じ波の法線を使うが、効かせ方が違った。空は「波で傾いた反射の向き」で cubemap を引く（法線 0.1 の傾きで向きが約 11° 動く）。反射 RT は UV を `normal.xz × distortion(0.03)` ずらすだけ（画面の 0.3% 程度）。
- **却下した案**：空も反射 RT に描いてからまとめて揺らす。空のパス（雲込みで 2.6〜2.9ms）を反射用にもう一度描くことになるうえ、揺らし方は弱い UV ずらしの側に寄るため。
- **採用**：反射 RT も「波で傾いた反射の向き」で引く。反射の向きの鏡像（Y を反転）へ想定距離 `reflectionDistance` だけ進んだ点を、反射を作った視点の ViewProj で投影して UV にする。波が無ければ鏡像の向き＝視線の向きなので、従来の UV と一致する。距離を大きくするほど空（無限遠）と同じ揺れ方に近づく。近くの物（自機など）は実際より少し大きく揺れるが、低空ではほぼ映らない（11 番 §5.3）。追加コストは行列の掛け算 1 回。
- 調整値：`WaterSurface::Params::reflectionDistance`（既定 0 ＝従来。**タイトルの水面は 0 のままで不変**）。大河は `RiverWater` が 300m を入れ、`Tuning/RiverWater.json` の `surface.reflectionDistance`、ImGui の "Reflection Distance [m]" で変える。従来の `distortion` の UV ずらしはその後に足される（併用）。

## 7. 実装ステップ

### 段階1: 水面の大河モード（反射なし）（2026-10-09 実装・実機確認済み）
- `WaterSurface`：α ブレンドの PSO、t10、大河用のパラメータ（`Params` の末尾）、`SetRiverMap`、ImGui。
- `WaterSurface.PS.hlsl`：大河モードの分岐（§3.2）。フラグ 0 の経路は従来と同じ。
- `RiverWater`（新規）：§2 のロードと描く条件、`Tuning/RiverWater.json`。
- `StagePlayScene`：生成・Update・Draw（`DrawDynamicAnimated` の後、Primitive の前）・Seek・ImGui。
- `StageEnvironment`：`GetCloudLayer()` を足す（L5 のファイル。ユーザーの許可済み。11 番 §3.4 に連絡）。

**完了条件**：低空で水面の端が見えない／岸の近くが薄く地形が透ける／滝の縁の先に水面が無い／谷から見上げて水面が見えない／タイトルとボス戦の見た目が変わらない。

### 段階2: 地形を映す（2026-10-09 実装・実機確認済み）
- `.mesh` v4（§4.3）：`cook_assets.py`、`ModelInstance` / `AnimatedModelInstance` の読み手、`Object3DInstance::GetWorldBoundingSphere`。全 .mesh を再クック済み（`Scenes/StagePlay_layout.mesh` はもともとクックに失敗する＝v3 のまま、`_ClaudeTurretScene_layout.mesh` は元の glTF が無い＝v3 のまま。どちらも v3 として読める）。
- `WaterReflection`：球で距離判定。
- 水面 PS：反射 RT を乗算済み α で合成（§4.2）、`reflectionRtWeight`（高さの足切りのフェード）。
- `RiverWater`：`WaterReflection` を持つ（倍率 0.5・farClip 2500）、`RenderReflection` で毎フレームタグで登録し直し、高さ 100m で足切り（30m でフェード）。調整値は `RiverWater.json` の `reflection`。
- `StagePlayScene::Draw`：最初に `RenderReflection`（シーン RT を貼る前）。

### 段階3: アニメーションするモデルを映す（2026-10-09 実装・実機確認済み。影も映る）
- スキニングは CS で済ませた頂点バッファ（モデル空間）を描くだけなので、**反射用の VS は静的モデルと共通**（新しいシェーダは不要だった）。
- `AnimatedObject3DInstance::DrawReflection`：反射のパスの中で `DispatchSkinning`（1 フレーム 1 回のフラグがあるので本編で二重に回らない）→ 反射用 PSO → `DrawSkinning`。
- `AnimatedObject3DInstance::GetWorldBoundingSphere`：バインドポーズの球 × 1.5（ポーズで外に出る分の余白）。ワールド行列は Update で CPU 側に控える（転送用 CB は読まない）。
- `WaterReflection::AddTarget(AnimatedObject3DInstance*)`、`RiverWater::RenderReflection` にシーンの `dynamicAnimated_` を渡す。
- 今の敵（プレハブの kind = Object3D）は段階2 から映っている。アニメーションする敵は `dynamicAnimated_` に入るので、タグが合えば映る。
- 映らない物：武器（`weapon_`。シーンの一覧の外で描いている）。必要になったら別に登録する。

### 段階4: エフェクトを映す（2026-10-09 実装・実機確認済み）
- `WaterReflection::SetDrawEffects(true)`（大河だけ。タイトルは false のまま）。不透明の物を描いた後、`EffectManager::DrawReflection` で GPU パーティクル → エフェクトの Primitive の順に描く。ビルボードに View が要るので `Render(const Camera&)` の時だけ描く。
- 鏡像の View = 鏡像行列 × 本編の View。ビルボードをこれで組むと、反射の中でも粒子が画面を向く。
- GPU パーティクル：グループごとに反射用の PerView CB を足し、`DrawReflection` は**シミュレーションせずに描くだけ**（反射のパスはシーン描画の最初＝今フレームの Draw の前なので、前フレームに進めた粒子を描く。1 フレーム遅れは見分けられない）。未初期化のグループは描かない（粒子バッファが COMMON 状態のため。ブルームと同じ扱い）。
- Primitive：`PrimitiveMesh` に反射用の Transform CB と `DrawReflection` を足す。鏡像で巻きが反転するので裏面カリングは切る。
- `EffectDef::reflect`（JSON の `"reflect"`、既定 true。true の時は書き出さない）。false ならそのエフェクトの Primitive と粒子グループを映さない。
- **今の制限（必要なら後で直す）**
  - 加算のエフェクトの α：本編用の PSO をそのまま使っているので、α は `ONE / INV_SRC_ALPHA` で積まれる。§4.2 の「加算は a を変えない」にはならず、反射の中では加算の光が下の空を少し隠す（普通の半透明に近い見え方）。直すなら反射用に α の積み方だけ違う PSO を作る。
  - 水面より下に出たエフェクトも鏡像にして描く（Primitive / 粒子の VS はクリップ面を持たない）。水面すれすれの爆発で、水中に入った部分が反射に出ることがある。
- 確認用：Hierarchy の None グループの `[Water] RiverWater` → Inspector「Reflection → Test Effect」で `Death_Drone` をカメラの前方（既定 80m 先・水面から 3m）に出す。Auto Repeat で一定間隔に出し続ける（Debug のみ）。

**完了条件**：水面に地形・自機・敵・エフェクトが映る／高度が高いと反射のパスが飛ぶ（PEPPER で確認）／タイトルの見た目が変わらない。
