### A で決まったこと・作ったもの（2026-10-13）

**`kCoverByScene`**
- 値は `kRevealByScene` と同じ `TransitionType::None`。「None ＝ その側はシーンが演じる」で、覆う側と開く側のどちらに書くかで区別する
- `BaseTransition::StartCovered(onSceneChange, playReveal)`：覆い切った見た目（`SetFullyCovered`）の Hold から始め、次のフレームでシーンを差し替え、Hold の秒数が経ったら開く（または開かずに終わる）
- `TransitionManager` の振り分け：覆う側が `kCoverByScene` で開く側がトランジションなら、**開く側を覆い切った所から始める**。開く側も `kRevealByScene`（①②の最終形）なら、**黒の Fade を「真っ暗のまま差し替える係」**にして開かずに終わる（ロードの1フレームと Hold の間を黒で押さえる）。履歴の覆う側の名前は `"(scene)"`
- 使い方：シーンは演じ終えて真っ暗になったフレームで `ChangeScene(行き先)` を呼ぶ（組み合わせ表の覆う側を `TransitionManager::kCoverByScene` にしておく）。`ChangeScene` を呼ぶまでは遷移中ではないので、演じている間の入力はシーンが自分で止める
- デバッグの Scene Switch の Cover に「None (scene covered)」を足した

**組み合わせ表（`SceneRoutes.h`）**
- 共通の定数 `kStageSelectReveal`（ステージ選択の開く側。HUB からとポーズからの両方）・`kHubReveal`（HUB の開く側。②・⑦）を置いた。**C が①の IN を、E が②の IN を作ったら、この定数を `kRevealByScene` に変える1行で全部の遷移が切り替わる**。B・C が①②の OUT を作ったら、その行の覆う側を `kCoverByScene` に変える
- `SceneRoutes.h` は `BaseTransition.h` しか include していないので、`kRevealByScene` / `kCoverByScene` を書くときは `TransitionType::None` と書くか `TransitionManager.h` を include する

## ① HUB → ステージ選択

参考：ガンダムの最新作の乗り込みの場面（胸部が開く → 一人称で乗り込む → 胸部が閉じる）。**最初から一人称、胸は開いた状態で待っていて、開く所は見せない**。

**モデルの前提（2026-10-13 確定、17 番 §5.1）**：機体は**二本足で立ったまま**で、右手の手のひらは**胸の開口部の下の縁のすぐ手前に止まっている**（手は動かない。ボーンも書き出していない）。開口部（＝手のひら）の高さは地上 約10.6m。動くのは**上のハッチだけ**（横に倒した円柱の一部の曲面の板、X 軸まわりに回る）で、**下の板は動かない**。ハッチの下の縁の台形の切り欠きが、下の板の台形の出っ張りにはまって閉じる。

### C で決まったこと（2026-10-13）

**シーンの構造：ステージ選択は HUB に統合する**（ユーザー決定）
- 理由：①の IN は「ハッチの表示板がそのまま残る」「六角形が晴れて神殿が透けて見える」「カメラは乗り込みの最後から続く」で、同じ空間が続くことが前提。別シーンだと神殿・機体・カメラ・表示板を二重に持つことになる（ロードの差は小さい。モデルとテクスチャはシーンをまたいで解放されない）。コンテストの要素は「画面遷移」なので、シーンを切り替えなくてよい
- `HubScene` は**状態だけを持つまとめ役**：神殿で待機 → 乗り込み（B）→ コクピット（ステージ選択）→ 降りる（E）。中身は部品のクラスに分ける（componentization_policy）
- 入口は 3 つ：タイトルから＝神殿で待機／ポーズの「ステージセレクトに戻る」（⑩）＝コクピットの中から（起動から）／ステージ・ゲームオーバー・リザルトから（⑦）＝コクピットの中から降りる（E）
- シーン名 `STAGESELECT` は残し、SceneFactory が「コクピットの中から始める HubScene」を作る（⑩・デバッグの切り替えがそのまま使える）。`StageSelectScene` クラスは消す
- `SceneRoutes.h` の `HUB → STAGESELECT` / `STAGESELECT → HUB` の行は消す（シーンを切り替えないため）。⑩ は `STAGEPLAY → STAGESELECT`（ストライプで覆い、開く側は `kRevealByScene`＝HubScene が真っ暗から起動を演じる）

**緑を光らせる方法（17 番 §5.1「マテリアルに発光が無い」への答え）**
- エンジンのマテリアルに**発光（emissive）**を足す：`Material` の使っていない欄 `terrainPadding` を `emissive` にする（CB は 256B のまま）。Object3D の PS で、ライティングのあとに足す（既定 0 なので他のモデルは変わらない）
- ブルームは「光らせたい物だけを発光 RT に描く」方式なので、発光する submesh だけを発光 RT に描き直すパスを足す（ID パスと同じく深度テストだけ、書き込みなし）
- どの部品を光らせるかは `.mat` を変えず、**実行時にマテリアル名で指定**（`CP_Glow`・`CP_Light`・`CP_Screen` など。値は `Hub.json`）
- 文字・線の発光：`TextRenderer` に発光の層を足す（文字と塗りつぶしの四角を発光 RT にも描く）
- シーンの口：`Scene` に「発光 RT に描く物」を足し、`Game.cpp` の発光パスから呼ぶ。発光する物が無いフレームは今までどおりパスごと飛ばす
- **コクピットの灯り（ポイントライト）と光る部位（操縦桿の輪・ボタン・ペダルの帯・壁のモニター）の色は表示板の色に連動**する：UNLOCK の間は赤とピンクの間、LOCKED で緑（2026-10-13 ユーザー決定。`cockpitLighting` の `followSign` / `lampFollowSign`）

### C で作ったもの（2026-10-13 完了。ビルド・実機確認済み）

**エンジン**
- `Material::emissive`（旧 `terrainPadding`）。rgb＝発光、w＝1 でベースカラーのテクスチャを掛ける（文字を描いた板の文字だけ光る）。Object3d / NoEnv / PBR / Terrain の PS がライティングのあとに足す
- `Material::dissolveEnable = 2`（`kDissolveHexScreen`）：画面座標の六角形のディゾルブ（`Dissolve.hlsli` の `DissolveHexScreen`）。欄の読み替えは `ApplyDissolve` のコメント（進み＝`dissolveProgress`、六角形の大きさ＝`dissolveNoiseScale`、中心＝`dissolveHeightMin/Max`、帯の幅＝`dissolveEdgeWidth`、ばらつき＝`dissolveNoiseWeight`、光る色＝`dissolveEdgeColor`）。`ApplyDissolve` は画面座標も受け取る形に変えた
- 発光パス：`Object3DManager` に発光用のルートシグネチャと PSO（`Object3d.VS` ＋新しい `WriteEmissive.PS`、出力は `BloomEffect::kFormat`、加算、深度テストだけ）。`Object3DInstance::DrawBloomPass(dxCore, 倍率, includeAll)` / `ModelInstance::DrawBloomPass`・`SetEmissiveByMaterialName`・`ClearEmissive`
- `Scene::HasBloomSources` / `DrawBloomSources`。`Game.cpp` の発光パスは「エフェクト・シーン・文字の発光の層」のどれかがあれば走る
- `TextRenderer`：層を 3 つに（通常 / 発光 `DrawTextGlow`・`DrawRectGlow`・`FlushGlow` / 画面の外 `BeginOffscreen`〜`FlushOffscreen`）。インスタンスバッファは層ごとに区画を分けた（同じフレームに何度描いても上書きし合わない）。画面サイズの CB はルート定数に替えた。`DrawRect`（塗りつぶしの四角）・`SetTransform`（UI を潰す拡大縮小）
- `TextureManager::RegisterExternalTexture` / `UnregisterExternalTexture`（RenderTexture をモデルのテクスチャとして名前で引く）

**ゲーム**（`Game/Scene/Hub/`）
- `CockpitReveal`：起動とシャットダウンの時間軸（灯り・六角形・ラジアルブラー・背景と文字の出・LOCK）。`Flicker` は蛍光灯のようなチカチカ
- `CockpitLighting`：緑のポイントライト 2 つ・光る部位（`CP_Glow` / `CP_Light` / `CP_Screen`）・外を映す部位（`CP_Screen` / `CP_Frame` / `BZ_Navy` / `HT_*`）。座席・操縦桿・ペダルは残る
- `HatchSign`：宙に浮く表示板。RenderTexture（1024×256）に文字・「/」を並べた縞・枠・バーコードを描き、タイトルのロゴの板ポリ（`logo_plane.mesh`、共有なので終わりに発光を戻す）に貼る
- `CockpitConsole`：文字だけのステージ選択（上下の枠の線・点を並べた円の計器・飾りの文字・メニューの枠と項目）。シャットダウンはブラウン管のように潰れて点になる
- `HubScene`：状態（待機 / 乗り込み / コクピット / 戻る〔仮〕）と入口（`Entry::Temple` / `Entry::Cockpit`）。`SceneFactory` の `STAGESELECT` は `HubScene(Entry::Cockpit)`。`StageSelectScene` は消した
- `HubBoardingSequence`：真っ暗にする黒い板（blackout）をやめ、`changeSceneTime` を `endTime`（コクピットへ移る時刻）に
- `VerticalMenu`：項目の位置と文字列を返す口（見た目を自前で描くため）
- `SceneRoutes.h`：`HUB ↔ STAGESELECT` を消し、`kStageSelectReveal` を `None`（`kRevealByScene`）に。`STAGESELECT → TITLE`（白フェード）・`HUB → STAGEPLAY`（ストライプ）を足した
- 調整値はすべて `Hub.json`（`cockpitReveal` / `cockpitLighting` / `hatchSign` / `cockpitConsole` / `returnFadeSeconds`）。ImGui の「Hub Tuning」に Boot / Shutdown のボタン
