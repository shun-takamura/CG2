# 10. 水面反射（平面リフレクション）

> **目的: ゲーム内の低空飛行時の水面と、タイトル画面の水面を、同じ実装（プリセット切替）で表現する。**
> ビジュアルの理想は映画「すずめの戸締まり」のポスター風（空と雲を映す浅い水面）。
> 雲は `9_CloudRendering.md` の成果（雲・スカイキューブ）を反射に再利用する。

最終更新: 2026-10-04

---

## 0. 実装背景・課題・選定理由（就活で語る要点）

### 0.1 実装背景（何を実装したかったのか）

- 3Dレールシューティングの**低空飛行シーンで水面を出し、空と雲を映す**ことで、動画映えする画を作りたい。
- **タイトル画面**も同じ水面で作れば、道や柱などの専用アセットを作らずに、「動きのある画」（水面のさざ波・雲の流れ）を出せる。
- 同じ水面を、**ゲーム内は疾走感、タイトルは落ち着き**と、見せ方を変えて使い回したい。
- **ボス戦もタイトルとほぼ同じ場所**（石畳・薄い水の層・フィールドの囲い）にして、世界の一貫性を出したい。環境は共通化して使い回す。
- ジャスト回避の分身やプレイヤー、扉（開始演出）が水面に映ることで、**ライティング・シャドウの技術アピール**にもなる。

### 0.2 課題（現状できる実装方法だと、どういう面でダメなのか）

| 手法 | 課題 |
|---|---|
| **レイトレーシング（DXR）** | 反射は最も正確だが、BVH構築・更新、ヒット点のシェーディング、ノイズ除去が必要で**作業コストが高い**。現状は、ジャスト回避の分身のアニメーションでさえ重くて実現できておらず、**DXRを載せる余裕がない** |
| **SSR（スクリーンスペース反射）** | 画面外や物の裏側は映らない。さらに水面が映すのは主に**空**で、空には深度（当たる面）がないため、**常にフォールバックが必要**になる |
| **静的キューブマップ（焼き込み）** | 負荷はほぼ0だが、**動く物（プレイヤー・敵・扉）が映らない**。撮影位置や内容がずれると、別の景色が映り込む失敗（Rage 2の例）が起きる |
| **焼き込みの2D画像** | カメラが動くと反射像が水面の上を滑って見える。雲が動くタイトルでも不自然 |
| **素直な平面リフレクション** | 正確だが、シーンを**もう一度描く**ので、そのまま描くとシーン描画が最大で2倍になる |

### 0.3 選定理由（選択肢がある中で、なぜそれを選んだか）

**採用: 平面リフレクション＋空は直接評価（スカイキューブ）＋反射カメラの描画距離を絞る＋プリセット切替**

| 判断 | 理由 |
|---|---|
| 平面リフレクションを採用 | 水面は平面（1枚）なので手法が成立する。動く物が正しく映り、カメラが動いても破綻しない。DXRの実装コスト・SSRの空フォールバック問題を避けられる |
| 空・雲は「描かずに引く」 | 反射側で雲を再度レイマーチすると雲のコストが2倍になる。反射に映る雲は、さざ波で歪みぼける低周波な像なので、**スカイキューブ（G）で十分** |
| 描画距離を近距離に絞る | 反射側は、近くの物（プレイヤー・地形・扉）だけ描けば足りる。遠くはスカイキューブが代わりに映る。ドローコールと頂点数を減らせる |
| 半解像度で描く（ゲーム内） | ピクセル処理が約1/4。さざ波の歪みで多少ぼやけても気づかれず、むしろ疾走感の演出になる |
| プリセットで切替 | 実装は1つで、ゲーム内=疾走感、タイトル=落ち着きを、パラメータだけで使い分ける。エンジンのJSON駆動の流儀にも合う |
| 保留: SSPR | 平面専用のスクリーンスペース反射。再描画が不要で低コストだが、画面外の物が映らない。**平面リフレクションのコストが問題になった場合の代替案**として比較対象に残す |

## 1. 基礎知識

### 1.1 反射の基本

どの手法でも、最後に次の2つを掛ける。

- **フレネル**: 浅い角度で見るほど反射が強くなる（Schlick近似）。
- **さざ波による歪み**: 法線のXZ成分で、反射のサンプル位置をずらして揺らす。

### 1.2 平面リフレクションの仕組み

1. 水面の高さを基準に、**カメラを鏡像の位置に置く**（反射用のビュー行列を作る）。
2. その視点でシーンをもう一度描画し、RTに保存する。
3. 水面のシェーダで、そのRTを水面の**画面座標**で引く（歪みは法線で加える）。
4. 水面より下にある物が映らないように、**斜めのニアクリップ**を使う。

雲は、**カメラだけを鏡像**にして、雲の平面そのものは鏡像にしない（雲は水面より上にあるので、そのまま使える）。

### 1.3 コストの内訳と軽減策

| 要素 | 内容 | 削り方 |
|---|---|---|
| ドローコール（CPU） | 反射用にもう一度描画命令を出す | 映る物にタグを付けて絞る |
| 頂点処理 | 反射側の視錐台内の頂点変換 | LOD、絞り込み |
| ピクセル処理 | ライティング・PBR | **低解像度化が最も効く**、軽量シェーダ |
| シャドウ | 影マップの再生成 | 光は同じなので**メインのシャドウマップを共用（再生成不要）** |
| ポストエフェクト | ブルーム等 | 反射側では省く |

- ファークリップを短くする、水面が映っているときだけ描く、更新を2フレームに1回にする、も有効。
- 目安（実測前）: 全解像度・絞りなしで、シーンコストの5〜10割増し。半解像度・絞りありで、1〜2割増し。

## 2. 設計

### 2.1 反射RTの構成

反射RTの中身を次の順で作る。

1. **スカイボックス**を、反射カメラの視点で描く
2. **雲の代替**を描く（スカイキューブ G、またはノイズ平面 F）
3. **反射用の描画距離内の物**だけを、不透明で描く（プレイヤー、近くの地形、敵、扉）
4. 描画距離の端は**フォグで空の色へ溶かす**

### 2.2 描画距離の端の繋ぎ（注意点）

- 反射側の描画距離で切った先は空になる。**切れ目でフォグが空の色と一致していないと、物が不自然に途切れて見える。**
- 本編のフォグと**同じ色・同じ設定**に揃える。
- 本編の空と反射の空は**同じスカイキューブ／同じ雲の関数**を使い、必ず一致させる。

### 2.3 ゲーム内とタイトルのプリセット

| | ゲーム内（疾走感） | タイトル（落ち着き） |
|---|---|---|
| 反射RTの解像度 | 1/2〜1/4 | 等倍 |
| 反射の描画距離 | 近距離のみ | 遠くまで（扉・遠景まで映す） |
| さざ波 | 振幅大・周波数高い・速く流れる | 振幅小・周波数低い・ゆっくり |
| 反射のぼかし | 強め。**進行方向に引き伸ばす**（モーションブラー風） | 弱め。近くはくっきり、遠くほどぼやける（コンタクトハードニング） |
| 雲の反射 | スカイキューブG（ぼかして軽量） | 質を上げる（必要ならレイマーチ） |

- ゲーム内の低解像度＋速い波紋は、**ちらつき（シマー）**が出やすい。バイリニアで引き、軽いぼかしを掛ける。
- 疾走感は、**プレイヤーの速度に応じて波紋の流れる速度と伸びを変える**と効果的。

プリセットは、エンジンのJSON駆動に合わせて次のパラメータで持つ。

```
WaterReflectionPreset
  - resolutionScale      (0.25〜1.0)
  - reflectionFarClip    (m)
  - fogFadeStart / End
  - cloudReflectionSource (SkyCube / Raymarch)
  - rippleAmplitude / rippleFrequency / rippleSpeed
  - blurAmount / motionStretch
```

### 2.4 水面の動き

- **土台**: ノーマルマップの2層スクロール＋フレネル。
- **波紋シミュレーション**（2D波動方程式をピンポンRTで解く）:
  - タイトルで「クリックした位置から波紋が広がり、それを合図に扉が開く」演出。
  - ゲーム内で、低空飛行の航跡や、ジャスト回避の分身が水面に触れた波紋。
  - 実装が小さい。
- 浅い水の見た目は、床の質感を薄く屈折させて透かし、反射とフレネルでブレンドする（すずめ風）。
- 太陽のきらめきは、さざ波のノーマルに対するスペキュラで出す。

### 2.5 演出面

- 扉は「水面に立つ扉」にして、クリックで光が溢れて開き、パルテナ式のステージ突入につなげる（開始演出のモチーフと一貫）。
- 扉は反射を見せるため**実ジオメトリ**にする案（推奨）。
- 光条は既存のCSMをレイマーチでサンプルして作る（シャドウマップの技術アピール）。
- 補助: ブルーム、レンズフレア、グレイン、カラーグレーディング、浮遊物、カメラのゆっくりしたドリー。

### 2.6 ボス戦での利用

ボス戦は、タイトルと同じ石畳・薄い水の層・フィールドの囲いを共有する。

- **ゲーム内用プリセットの初適用の場**になる（低解像度・近距離のみ・進行方向のぼかし）。プレイヤーとボスが動く環境で、疾走感の設計を確かめる。
- **動く物が反射に映る**: プレイヤー・ボス・弾を反射RTの対象にタグ付けし、コストを実測する。
- **囲いがあることで、映る静的な物の範囲が決まる**ので、反射カメラの描画距離（`reflectionFarClip`）を囲いの大きさに合わせられ、コストの見積もりが立てやすい。囲い自体を反射に映すかは未決。
- **波紋をプレイヤー・ボスの動きと連動**させると映えるが、波紋シミュレーション（Step 4）が必要になる。
- 環境（石畳・水・囲い）はシーンに直書きせず、タイトルとボス戦で共有する単位に切り出す（`9_CloudRendering.md` のフェーズ2-a）。
- 水底の影（CSM共有）は実装済みなので、囲いの影も落とせる。
