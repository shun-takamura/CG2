# 23. クリア演出とリザルト

ボスを倒してからリザルト画面を閉じるまでの流れ。要素別コンテスト「クリア演出」向け。

**状態**：2026-11-12 仕様を決めた。A（リザルト画面）は 2026-11-15 ビルド・実機 OK。**締切 11/17**。

- 悪い例：いきなりタイトルやステージ選択へ飛ぶ
- 良い例：クリアの達成感を盛り上げる演出があり、リザルト画面で記録と報酬を見せる

---

## 0. 決まったこと（2026-11-12 ユーザー決定）

| 項目 | 決定 |

## 1. 流れ（完成形）

```
ボスの HP が 0
 → [B] ヒットストップ → スロー → 寄るカメラ → 崩れて爆発
        └ この中の 1 コマを UI なしで撮る（§3）
 → [B] STAGE CLEAR の表示
 → [D] 自機が羽根を開いて羽ばたき、上へ飛んでいく → 見上げるカメラ → 光 → 白
 → [A] リザルト画面（背景＝撮った 1 枚）
 → 決定でステージ選択へ（今と同じ。18 番 ⑦）
[E]（コンテストの後）低空飛行から少しずつ不穏に → 谷で雨 → 撃破で雲が割れて晴れる
```

今の流れ（`BossStagePart::BeginClear/UpdateClear`）：撃破 → 1.5 秒 → STAGE CLEAR を 0.5 秒で出す → 3 秒 → ストライプで `RESULT`。B・D でここを置き換える。

## 2. A リザルト画面

アイスボーンのクエストクリア画面の配置に合わせる。画面は UI 座標（1600×900、`GetUIWidth/Height`）。

| 場所 | 中身 |
|---|---|
| 背景 | 撃破の瞬間の 1 枚（§3）を画面全体に。少し暗くして文字を読みやすくする。**無いとき（F2 のデバッグ遷移など）は仮の背景**（暗い単色＋ぼかした色の帯など）で必ず成り立つようにする |
| 左上 | ステージ名・難易度（純度 n.n）・クリアタイム（`mm' ss" cc`）・スコア・撃破数 |
| 右上 | 獲得したエーテルの合計 |
| 右のパネル上段「ステージ報酬」 | 素材のマス（アイコン＋個数）。1 マスずつ順に出て数え上がる（今の数え上げの流用） |
| 右のパネル中段「部位破壊報酬」 | 守護機の腕甲など。壊していなければ空のマス |
| 右のパネル下段「説明」 | 左右（`MenuLeft/Right`）で選んだ素材の名前・説明・レア度・今回の数 |
| 下 | 操作の案内：「決定：ステージ選択へ」「（ボタン）：背景を見る」 |

- **背景を見る**：押している間（または切り替え）UI を全部隠して、撮った 1 枚だけを見せる
- 数え上げの途中で決定 → 最後まで飛ばす。もう一度でステージ選択へ（今と同じ）
- 出し方：背景がゆっくり寄る（わずかなズーム）→ 左上 → 右のパネルの順に出す

### 2.1 実装の前に片付けること

| 項目 | 内容 |
|---|---|
| 部位破壊報酬を分けて数える | 今の `LootLedger::Add(itemId, count)` は出どころを持たない。部位破壊の分を別に数える口を足す（`BossStagePart` の `lootDrops_.DropFrom("boss_arm", ...)` の流れ） |
| アイコン | まだ無い。コンテストでは色付きの図形（今の印の延長）。後で画像に差し替えられる作りにする |
| 説明・レア度 | `Loot.json` の素材の定義に説明文とレア度を足す（`LootCatalog` で読む） |
| クリアタイム | ステージ開始からボス撃破まで（ポーズ中は止める）。ボス戦からのリトライは 22 番 §4 の集計に合わせて、その回の分だけ |
| ステージ名 | ステージ選択の表示名をどこが持っているかを A のチャットで確かめる |

**A でやったこと（2026-11-12、2026-11-15 ビルド・実機 OK）**
- 部位破壊：`LootLedger::Add(itemId, count, LootSource)`。`LootSource::PartBreak` の素材は部位破壊の分にも数える（合計は `GetItemCount`、分けた数は `GetStageItemCount` / `GetPartBreakItemCount`）。`LootDrops::DropFrom(prefab, pos, source)` が拾うまで出どころを持ち、`BossStagePart` の腕は `PartBreak` で渡す。腕のエーテルは合計にだけ入る
- 説明・レア度：`Loot.json` の items と ether に `description`（`\n` で改行）・`rarity`（1〜5）。`LootItemDef::description / rarity`
- クリアタイム：`StagePlayScene::Update` のスタート演出の後で UI の時間（実時間）を足す。ポーズ中・スタート演出中は手前で return するので足さない。撃破（`ConsumeBossDefeated`）で止める。`Initialize` で 0 に戻す＝ボス戦からのリトライはその回の分だけ
- ステージ名：持っているのはコクピットのメニューの文字 `"ステージ1"`（`CockpitConsole.cpp`）だけ。`StagePlay.json` は Debug の保存で丸ごと書き直されるので置かない。`StageClearRecord` の既定値 `"ステージ1"`（ユーザー決定。名前が決まったらそこを直す）
- アイコン：`ResultScene::DrawItemIcon` の色付きの四角。画像ができたらこの関数だけ差し替える
- 背景を見る：キャンセル（BackSpace / B）で UI を隠す ↔ 戻す切り替え。隠している間は決定でも戻る。左右（`MenuLeft/Right`）でマスを選ぶ

**実機を見て変えたこと（2026-11-12 ユーザー）**
- マスは十字キーの上下左右とマウスで選ぶ（上下は空の段を飛ばして近い列へ。いちばん下はパネルの「ステージ選択へ」）。乗せたら選び、クリックで決定
- 右上は**所持エーテル**（`EtherState`。無限の扱いの間は 99,999）。獲得エーテルは左上の記録の下へ
- **素材を売る**：マスで決定 → 売る数の小窓 → 決定で売る。小窓は **↑↓ で売る数（1 個ずつ、数の上下の ▲▼ をクリックでも）・←→ で［売る］［やめる］を選び、決定で選んだほう**。キャンセルはいつでもやめる。マウスはボタンに乗せて選び、クリックで実行（2026-11-14 ユーザー：←→ が数に取られて［やめる］へ行けなかったため。最初の「↑↓ で 10 個ずつ」は廃止）。売値は `Loot.json` の `sellPrice`（歯車 10・かけら 30・腕甲 100・核 150）。売った分は `EtherState::AddHand` で所持へ足す（無限の扱いはそのまま、所持の横に「+N」）。素材の数はこの画面の表示だけ減らし、売りきったマスは詰める
- ステージ選択へは「ステージ選択へ」の決定・クリックか Esc／Start

## 3. 撃破の瞬間のキャプチャ（A と B の受け渡し）

A と B を同時に進めても衝突しないよう、受け渡しの口をここで決めておく。

- **置き場**：`Game/Score/StageClearRecord.h/.cpp`（2026-11-12 A で作成。ステージ名・クリアタイム・キャプチャの有無を持つシングルトン）
- **画像**：シーンの切り替えをまたいで残る RT を 1 枚。撮るのは B、読むのは A
  - A は `HasCapture()` を見る。無ければ仮の背景（§2）。有ればテクスチャ名で `SpriteInstance` を作って画面全体に描く（スプライトは名前で SRV を引くので、SRV の番号に加えて名前も受け取る）
  - B は撮ったら RT を `TextureManager::RegisterExternalTexture(名前, resource, srvIndex)` で登録し、`StageClearRecord::SetCapture(名前, srvIndex, 幅, 高さ)` で「有る」にする。幅・高さは画像の画素数（描画解像度）。RT と SRV の寿命は B の持ち主が持つ
  - ステージの開始とリトライで「無い」に戻すのは、A が `StagePlayScene::Initialize` に入れた `StageClearRecord::ResetForNewRun()` が済ませている（B は呼び直さなくてよい。画像の解放だけ B で）
- **既存の仕組み**：`PostEffect::CaptureSceneForDisruptor`（シーン RT → `captureRT_` へのコピー）と `ScreenWaterSurface`（シーン RT の `CopyResource`）がある
  - ただしディスラプターのコピーは**ポストエフェクトの前**の絵。リザルトの背景は**ポストエフェクト（ブルーム・色調）の後、UI の前**の絵が欲しい → どこで撮るかは B で決める
  - `captureRT_` はディスラプターが使うので、**別の RT を持つ**（シーンの切り替えで消えない所＝`PostEffect` など、エンジン側）
  - エンジン（`GameEngine/`）を変えたら ArcanaEngine への同期が要る（メモ arcana_engine_repo）
- 描画解像度（既定 1920×1080、`GetRenderWidth/Height`）と UI 座標（1600×900）は違うので、A は UI 座標の画面全体に引き伸ばして描く

## 4. 各要素の中身

### B 撃破の瞬間（STAGE CLEAR の表示を含む）

- ヒットストップ（数フレーム止める）→ スロー（`TimeGroup::World`）→ ボスへ寄るカメラ → 崩れて爆発（今の `BreakAll`・死亡エフェクトを使う）
- 撮るコマ：止まった瞬間か、爆発がいちばん大きい瞬間。UI（HP バー・レティクル・拾った物の表示・STAGE CLEAR）を描かない状態で撮る
- STAGE CLEAR の表示を作り込む（今は文字のフェードだけ）
- 撃破の後は被弾しない・敵の弾は消す（今と同じ）

### D 飛び立ち

- 自機の羽根を開いて（Deploy）羽ばたき、上へ飛んでいく。カメラは下から見上げる → 光（ブルーム・まぶしさ）→ 白 → リザルト
- クリップは作ってある物（Stand/Ignite/Catapult/Launch/Fly・羽根の Deploy/Stow、メモ player_mech_model）を流用する。羽ばたきなど新しいクリップは余ったら作る（8 番 #24「勝利／クリア」）
- 白からリザルトへの切り替えはストライプをやめて白でつなぐ（`SceneRoutes` の STAGEPLAY → RESULT）
- 空は今のボス戦の空。E ができたら晴れた空に差し替える

### E 天気（コンテストの後）

- 低空飛行から少しずつ雲を厚く・暗く → 谷で雨 → ボス戦は曇り → 撃破で雲が割れて光が差し、晴れる
- 段取りはステージ演出なのでここか 11 番に書く（9 番などの技術の設計書には書かない）
