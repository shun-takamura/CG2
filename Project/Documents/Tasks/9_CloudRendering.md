# 9. 雲の描画（レイマーチング）

> **目的: ゲーム本編（ステージ）で使う雲の基盤を作る。** タイトル画面は再利用先の一つ（水面反射は別ファイル `10_WaterReflection.md` で扱う）。
> 評価は「動画映え＋コード品質」。**雲は一度作れば本編・タイトルの両方で使えるため、コストパフォーマンスが高い。**

最終更新: 2026-10-04

---

## 0-1. 実装背景・課題・選定理由（就活で語る要点）

### 実装背景（何を実装したかったのか）

- 3Dレールシューティングで、**雲海の上を飛び、雲の中を抜ける**演出を、動画映えする形で入れたい。
- 敵が雲の中から現れる、プレイヤーの弾が雲に干渉する、といった**ゲームプレイと雲の絡み**も作りたい。
- 雲は一度作れば、**ゲーム本編・タイトル・水面の反射**（スカイキューブ経由）に再利用できるため、コストパフォーマンスが高い。

### 課題（現状できる実装方法だと、どういう面でダメなのか）

| 手法 | 課題 |
|---|---|
| **スプライト／パーティクル雲** | 近距離で重なりが50〜100枚に跳ね上がり**オーバードロー**が急増。半透明のソートが必要（加算合成だと白く飽和）。近づくと貼り紙感。ファークリップで板が切れる。**雲抜けと連続しない** |
| **フルボリューム（Nubis/HZD式）** | 品質は最高だが、64〜128ステップ＋光側マーチで**重い**。TAA基盤や締切（12月末）、1面集中の制約に対して**実装・調整コストが大きすぎる** |
| **ノイズ平面のみ** | 軽いが平面的で、**雲を抜けられない** |
| **焼き込み（スカイキューブのみ）** | 静的で、動かない・抜けられない |

### 選定理由（選択肢がある中で、なぜそれを選んだか）

**採用: ゼノブレイド2式（CEDEC 2018）のレイマーチングから始め、実測しながら足す**

| 判断 | 理由 |
|---|---|
| ゼノブレ2式（2Dノイズ×高さ勾配、打ち切り） | 実績がある。2Dノイズ1枚＋数ステップの打ち切りで**軽い**。雲海を見下ろす用途に一致。3Dノイズや光側マーチが不要 |
| 段階的に育てる方針 | 同じ「2Dノイズ＋高さ勾配」の土台のまま、3D侵食ノイズ・打ち切り廃止で軽量ボリューム（B'）へ拡張できる。**症状を見て部品を足す**ので手戻りが少ない |
| 実ゲーム内でPEPPERを見ながら実装 | 「作って測って選んだ」という根拠を数字で語れる。スプライトとの比較も実測で確認する |
| 低解像度・深度合成を最初から入れる | 後付けだとパス構成の組み替えになる。深度合成で、敵が雲から出てくる・物が雲に隠れる表現が成立する |
| 遠景はノイズ平面、雲抜けはフォグ＋ポストと併用 | 全域を高品質マーチにせず、見える範囲に応じてコストを配分する |

## 0-2. 方針（決定事項）

1. **まずゼノブレイド2式（CEDEC 2018）のレイマーチングを既存ステージに実装して試す。** 実ゲーム内でPEPPERの数値を見ながら、足りない要素を足していく。
2. 「のっぺりする → ライティング/ノイズ追加」「重い → 低解像度化・遠景を軽量手法へ」のように、**症状から部品を足す**進め方にする。
3. **最初から入れておく構造は3つだけ**（後付けだとパス構成の組み替えになる）:
   - 低解像度RTに描いて拡大する構造
   - 不透明物の深度で止める
   - PEPPERの計測区間
4. 雲は `StagePlayScene` に直書きせず**専用クラスに切り出す**（`componentization_policy` 準拠）。
5. 遠景はノイズ平面（軽量）、近景〜雲抜けはレイマーチ。雲抜けは「フォグ＋ポスト」との組み合わせも検討。

## 1. 基礎知識

### 1.1 レイマーチング（ボリューム型）

各ピクセルからレイを飛ばし、雲層の範囲だけ一定間隔で進みながら「その点の濃さ」を調べて積み上げる。

1. 画面の各ピクセルからカメラのレイを1本飛ばす
2. レイと雲層（下面・上面）の交点を解析的に求め、その区間だけ進む
3. 各点で雲の濃さを関数で求める
4. 濃さに応じて透過率を減らし、色を足す（Beer-Lambert: `透過率 = exp(-濃さ×距離)`）
5. 透過率がほぼ0、または不透明物の深度に達したら終了

雲の中に入ると早く止まるため、**雲の中は重くならない**。重いのは雲の縁・薄い部分（長距離を進む）。

### 1.2 ゼノブレ2式の式（スライドより）

```
濃さ   = clamp((雲海の最高点 - レイの高さ) / 雲海の深さ, 0, 1)    // 上0 → 下1
透明度 = clamp((ノイズ × 濃さ − 補正値) × 乗算値, 0, 1)
透明度が0を超えた点で雲あり（打ち切り）
```

- 補正値: この値未満を切り捨てて穴・縁を作るしきい値
- 乗算値: 縁のくっきり度
- **ノイズが効く理由**: ノイズが無いと高さだけで濃さが決まり、平らな霧の層になる。ノイズは水平位置ごとに値が違うので、ノイズが大きい所は高い位置から雲に当たり（盛り上がる）、小さい所は低い位置まで下りないと当たらない（へこむ）。上面が凹凸になる。
- ノイズの種類: **Perlin**（滑らかな大きなうねり）＋**Worley**（丸い塊）を合成する。
- ノイズが形を持っているので、少ないステップで当たり判定するだけで雲らしく見える（軽量化にも効く）。

### 1.3 ノイズ・共通部品

| 部品 | 内容 |
|---|---|
| Perlin noise | 滑らかな勾配ノイズ |
| Worley noise | セルラーノイズ。反転すると丸いモコモコ |
| fBm | 周波数2倍・振幅1/2で重ねる |
| 高さ勾配 | 高度から密度（下が濃く上が薄い） |
| ray-slab交差 | レイと雲層の交点を解析的に求める |
| Beer-Lambert | 透過率の式 |
| ブルーノイズ＋TAA | 開始位置ジッタ＋時間平均で少ステップでも滑らかに |
| 深度合成 | 不透明物の深度でマーチを止め、αブレンドで重ねる |

### 1.4 低解像度描画・深度合成

- **低解像度**: コストはピクセル数に比例。1/2解像度でコスト約1/4、1/4解像度で約1/16。雲は柔らかい対象なので目立ちにくい。小さいRTに描いて、最後に画面サイズへ拡大して重ねる。
- **深度合成**: 不透明物（敵・地形・機体）の深度までで積分を止める。**敵が雲の中から出てくる**、扉や機体が雲に隠れる、といった前後関係が正しくなる。

## 2. 手法の比較（A〜G）

| # | 手法 | 見た目 | コスト | 雲を抜ける | 向く用途 |
|---|---|---|---|---|---|
| A | **ゼノブレ2式**（2Dノイズ×高さ勾配、打ち切り） | 雲海の上面。塗り調 | 低（8〜24ステップ） | × | 雲海・中景 |
| B | **フルボリューム**（3Dシェイプ＋侵食＋天気マップ＋光側マーチ） | 立体的で内部が透ける | 高（64〜128＋光6タップ） | ◎ | 近景・雲突入 |
| B' | **軽量ボリューム**（2D天気マップ＋高さ勾配＋3D侵食1枚、光2タップ） | Bの8割 | 中 | ○ | 本命候補（雲抜け） |

| G | **焼き込みスカイキューブ** | 静的 | 極低 | × | 最遠景・反射・IBL |

### 2.1 各手法の基礎技術

- **A**: ray-slab交差、2D合成ノイズ、高さ勾配、閾値打ち切り
- **B**: 球殻交差、3Dノイズ（Perlin-Worley 128³ / Worley 32³）、天気マップ、Beer-Lambert、Henyey-Greenstein位相関数、Powder効果、光側マーチ
- **B'**: Aの高さ勾配＋2D天気マップ＋Bの簡略版（3D侵食1枚、光2タップ、24〜48ステップ、距離LOD）
- **C**: パララックスオクルージョンマッピング（視差）、ハイトマップ。Aとノイズ資産を共用できる
- **D**: ビルボード、ソフトパーティクル、法線の偽装によるライティング、ソート
- **E**: Bのシェーダでの多視点焼き込み、フリップブック、視点ブレンド
- **F**: 平面へのレイ交差、ノイズスクロール、2〜3層のパララックス、フォグ
- **G**: キューブマップRT、畳み込み（IBL用）。A/B'の出力の焼き込み先

### 2.2 A・B'・Cは同じ土台

A・B'・Cは「2Dノイズ＋高さ勾配」を共有するので、**1つのシェーダの距離LOD**として連続的に切り替えられる（近い=B'、中=A、遠=F）。ゼノブレ式は「B'の遠距離版」として使う。

## 3. 判断の記録

### 3.1 ゼノブレ式（A）と通常（B/B'）の違い

| | 通常（B / B'） | ゼノブレ式（A） |
|---|---|---|
| 雲の捉え方 | 体積（中身がある） | ほぼ表面（上面の形） |
| ノイズ | 3D | 2D（水平位置のみ） |
| レイの進み方 | 最後まで進んで濃さを足し続ける | 当たったら打ち切る |
| ステップ数 | 64〜128 | 8〜24 |
| 内部の表現 | 光が透ける・内部に影 | 中身は無い |
| 強み | 立体感・透け感・雲に入れる | 軽い |
| 弱み | 重い | 中に入れない |

用途の違いであって優劣ではない。**見下ろす・見渡すならA、雲の中を抜けるなら通常方式。** Aから始めて、必要に応じて3Dノイズ追加・打ち切り廃止で育てる。

### 3.2 スプライト大量配置 vs レイマーチ（概算・要実測）

前提: 1080p、画面下半分を手前〜ファークリップ（既定5000m）まで雲海で埋める、ミドル級GPU。**数字は桁の目安で実測値ではない。**

| | スプライト（重なり10〜20/px） | レイマーチ（1/4解像度・32ステップ） | ゼノブレ式A（1/4解像度・12ステップ） |
|---|---|---|---|
| 処理量 | 約1,000〜2,000万フラグメント | 約210万サンプル（光2タップ込みで約600万） | 約80万サンプル |
| GPU時間の目安 | 約0.5〜2ms | 約0.5〜2ms | 約0.2〜0.5ms |
| VRAM | 数MB | 10〜20MB | 数MB |

- この規模では**スプライトとレイマーチは同じ桁**。VRAMは誤差。
- スプライトは**近距離で重なりが50〜100枚に跳ね上がる**と急に重くなる。レイマーチは近づいても一定。
- インスタンシングで軽くなるのはCPU側（ドローコール）で、**ピクセル処理（オーバードロー）は変わらない**。
- スプライトの品質上の制約: 半透明のソートが必要（加算合成のままだと白く飽和）、近づくと貼り紙感、ファークリップで板が切れる、雲抜けと連続しない。
- **使い分け**: 雲海・雲抜け=レイマーチ、雲海の上に散らす雲塊=スプライト/Impostor、局所の煙=既存パーティクル。

### 3.3 半透明スプライトの深度書き込みの罠（実験で確認済み）

Planeに貼ったスモークが、加算合成でも前面の薄い部分が奥をえぐった → **深度書き込みが有効**で、透明ピクセルも深度を書いていたため。**半透明は深度書き込みOFF・テストON**にすると解消（確認済み）。

### 3.4 雲抜けの案

| 案 | 内容 | 評価 |
|---|---|---|
| 筒の壁面にマーチ | 通過経路の内側だけ簡易マーチ | レールなので作り込めるが、入口の繋ぎ目と筒の形が見えないよう注意 |
| フォグ＋ポスト | 雲に入ったらカメラ位置の濃さで指数フォグ＋流れるもや＋粒子＋周辺減光 | 最安で意外と効く |
| **組み合わせ（推奨）** | 接近=レイマーチ雲、突入の瞬間にフォグを立ち上げ、内部はマーチ精度を落とす、出口でフォグを晴らす | 通過ルートは固定なので雲の配置は手で作り込める |

### 3.5 弾道で雲が薄くなり、時間で戻る（干渉表現）

**可能。** 雲の濃さの計算に、「攪乱マップ」を引き算で加える。

- **攪乱マップ**: 雲の位置（XZ）に対応する2Dテクスチャ（RT）。値が大きいほど、そこの雲を薄くする。
- **書き込み**: 弾の位置（軌跡は線分・カプセル）を、毎フレーム攪乱マップにスタンプする。
- **回復**: 毎フレーム、マップの値を少しずつ減衰させる。**攪乱が消える＝雲が濃く戻る。**
- **濃さへの反映**: ゼノブレ式の透明度の計算に、攪乱を引く。
  `透明度 = clamp((ノイズ × 濃さ − 補正値 − 攪乱) × 乗算値, 0, 1)`
- 風で雲が流れているなら、攪乱マップも風の分だけスクロールさせると、弾道の穴が雲と一緒に流れる。

| 案 | 内容 | 評価 |
|---|---|---|
| **① 攪乱マップ（2D RT）** | 上記の方式。減衰で回復 | **推奨**。ゼノブレ式の2Dノイズと相性がよく、弾の数に依らず一定コスト。水面の波紋シミュレーション（ピンポンRT）と同じ仕組みを流用できる |
| ② 弾のリストを直接評価 | シェーダ内で全ステップ、近い弾までの距離から薄くする | 弾が数十発程度なら簡単。弾が増えると比例して重い |
| ③ 3Dボリュームテクスチャ | 高さ方向も含めて攪乱を持つ | 精度は高いが、メモリと更新が重い。当面は不要 |

- 制約: 2Dマップは上から見た平面なので、**高さ方向の細かい穴**は表現できない。雲の全層に対して穴が空く見た目になる（筒状に貫通）。高さ範囲を持たせたい場合は、攪乱に高さのオフセットを持たせる案を検討する。
- 攪乱マップの範囲は、プレイヤー周辺のみでよい（リングバッファ／プレイヤー追従）。

### 3.6 遠景の雲の方式選定（ノイズ平面加工の亜種）

> 用語: 手法A〜G（§2）とは別に、この節の「案A／案B」は**遠景の雲だけの二択**。案Aは、手法F（ノイズ平面加工）の亜種にあたる。

**経緯**

1. **当初の計画は手法F（ノイズ平面加工）**: 遠景の雲は、ノイズを加工した平面で軽く表現する想定だった。
2. **別案の発案**: 雲だけのスカイボックスをゲーム側のスカイボックスに重ね、ディゾルブのしきい値を一定範囲（clamp）で上下させて形を変え、雲とマスクを別方向にゆっくりスクロールし、縁のαを下げて薄い部分を作る。
   - 水面反射は、すでにスカイボックス（キューブマップ）を反射方向で引く構造があるため、**この案ならキューブマップのまま水面に映せて実装コストが安い**と考えた。
   - この案は、ゼノブレ式の式（補正値＝しきい値、乗算値＝縁のやわらかさ）を、時間でしきい値を動かして適用する形と等価。
3. **そのままでは実装できなかった**: 動かす（ディゾルブ・スクロール）ので水面側でも毎フレーム評価が要る点に加え、**雲だけのシームレスなキューブマップ（HDRI相当）を描く手段がない**ことが大きな壁になった。
4. **結論**: 発案の中身（ディゾルブ、2枚の別方向スクロール、縁のα下げ、既存スカイボックスへの重ね描き）は活かしつつ、キューブマップをやめて**2Dノイズの平面投影にした＝ノイズ平面加工の亜種**。当初の手法Fの延長に戻りつつ、発案のアニメーション手法を取り込んだ形。

**候補（二択）**

| | 案A: 平面投影（2Dテクスチャ） | 案B: キューブマップを回転 |
|---|---|---|
| スクロール | 任意方向にそのまま可能 | 方向ベクトルの回転で代用（Y軸回りが基本） |
| 継ぎ目 | なし（タイル） | **シームレスなキューブマップ（HDRI相当）を自作する必要** |
| 水平線に向かう遠近感 | 自動で出る | 焼き込み時に作り込む必要 |
| 既存の2Dノイズの流用 | 可（近景のゼノブレ式と共用） | 不可 |
| 水面反射 | 同じ関数を水面PSでも評価（水面位置が必要） | 同じ関数を水面PSでも評価（方向のみ） |
| 向く用途 | ノイズで作る雲 | 手描きの雲 |

**決定: 案A（平面投影）＝ノイズ平面加工の亜種**

案Bは、発案の時点で想定していた「キューブマップのまま水面に映す」構成で、水面反射のコストは最も安い。しかし、**シームレスなHDRI相当のキューブマップを描けない**ため採用できなかった。

選定理由:
1. **HDRI（シームレスなキューブマップ）を描く手段が不要。** 必要な素材はタイル可能な2Dノイズだけで、座標の折り返し（`座標 mod 周期`）で計算できる。生成は、ツールで1回焼く／起動時にGPUで生成、のどちらでもよい。
2. **近景のゼノブレ式と、2Dノイズ・式・パラメータ（補正値/乗算値/風）・レイと平面の交点計算を共有できる。** 遠景は「ステップ0回で上面の1点だけ評価」と見なせるため、距離切替で境目が出にくい。
3. スクロールを任意方向にでき、継ぎ目がなく、水平線への遠近感が自動で出る。
4. 空の背景は**既存スカイボックスをそのまま使い**、PS内で合成する（背景を描き直さない）。

受け入れるデメリット:
- 水面PSに**反射を起こした水面のワールド位置**を渡す必要がある（案Bは方向のみで足りる）。
- 水平線付近は交点が遠くなりUVが大きく動くため、**ちらつき対策（ミップ／距離フェード）が要る**。`reflectDir.y` の下限0.02は維持する。

**実装方針**
- 雲の関数を共通 `.hlsli` に置き（例: `CloudSky(origin, dir, time)`）、`Skybox.PS` と `WaterSurface.PS` の両方から呼ぶ。描画パス・RTは増やさない。
- 合成は各PSの内側で `lerp(空, 雲色, α)`（`Skybox.PS` は不透明出力のため、別パスのアルファブレンドにしない）。水面側は反射RTのα=0（空）の部分に雲を合成する。
- 定数バッファ（時間・しきい値範囲・縁の幅・スクロール速度）は空側と水面側で**同じ値**を渡す。`Skybox` の `Material` はpaddingが3 floatだけなので拡張が要る。
- テクスチャのレジスタは **t5以降**（t2=PBR法線、t3=シャドウは予約済み）。
- ディゾルブの動かし方: しきい値は**周波数が割り切れない2本のサイン波**の合成で動かす（全体が同期して「呼吸」しないように）。形用とマスク用を別方向にスクロール。縁は `smoothstep(閾値, 閾値+幅, 値)` で落とし、縁の帯の値で色も少し変える。
- IBLが必要になった場合も、雲を重ねた空を**実行時にキューブマップへ焼く**（手作業のHDRIは不要）。

案Bを採らなかった主因は、シームレスなキューブマップの用意（HDRI相当）と、水平線の遠近感の焼き込みが必要になること。手描きの雲を使いたくなった場合は、案Bを再検討する。

### フェーズ3: シューティング（遠景＋レイマーチ）

#### 構成の決定（2026-10-09、ユーザー決定）

- **雲海の層は Y 300〜850**（最高点 850・下面 300＝約 61 秒で抜ける。11 §3.0）。
- **一帯はゼノブレ式**で埋める。**降下の線のまわりは円柱にくり抜いて空洞**にし、円柱の壁もゼノブレ式で描く。**入口（上面との交点）と出口（下面との交点）の近くだけ B'**。空洞の中のフォグ（雲の中の演出）は後でやる。
- 形は 1 本の濃さの式（`CloudRaymarch.hlsli` の `CloudOver`）を全部の描き方で共有する。**ゼノブレ2式そのまま**：`濃さ = clamp((最高点 − y) / 雲海の深さ)`、`透明度 = clamp((ノイズ × 濃さ − 補正値) × 乗算値)`。
  - ノイズは `noiseFloor..1` に寄せてから掛ける（補正値 < noiseFloor なら帯の底で必ず雲＝隙間から未ロードの地上が見えない）。下面は `bottomFade` で丸める。
  - くり抜き：レールの 48〜66 秒を 16 点の折れ線で拾い（`RailStagePart::SampleCameraPathAtSec`）、半径 `shaftRadius` をノイズで揺らす。
- 歩き方：**上から見下ろす時は「最高点〜帯の底（最高点 − 深さ）」だけを等間隔に 24 歩**。帯の底より下は詰まった雲として止める（縦穴の上だけは穴の底へ等比で歩き続ける）。雲の層の中（縦穴）からは 1 歩目 4m の等比。
- 透明度：当たった点の値（ゼノブレ式）に奥の 3 歩を重ねる（縁は半透明・中身は不透明）。乗算値は 2 で柔らかめ。
- **初版（2026-10-09）は「ガビガビ」だった（実機）。原因と直し**：① 掛け算の式を引き算＋短い勾配（160m）＋深い所の埋めに書き換えていた → 垂直な崖と平らな台地。ゼノブレの掛け算に戻した ② 当たった後に 2 分探索＋25m 奥で透明度を取っていた → ほぼ不透明で硬い ③ 下面 300m・最大 20km まで等比で歩いていた → 遠くで 1 歩数百 m の段と縞 ④ TAA なしでジッタ → ざらつき（`jitter` 既定 0）⑤ 1/4 解像度 → 1/2 に。煙っぽさ用の追加ノイズ（資料の「ノイズ計算を追加し煙感を」）は未実装。
- **2 回目も実機で「ぜんぜんだめ」（横縞・のっぺり・白飛び）→ CPU 版（同じ式を numpy で描く。`tools/Python/preview_cloud_raymarch.py`：`--pitch` / `--eye` / `--set key=value`、Tuning の raymarchClouds を読む）で再現してから詰めた**：① 等間隔の歩幅で当たった歩の位置をそのまま使っていた → 横縞。前の点との線形補間で交点を出す ② 大きい形 3200m＋細部 700m は 50m 上から見ると大きすぎて平ら → 大きい形 1800m＋もこもこ（ドーム、cloud_moko_height.dds を t3 に）500m を 0.55 で混ぜる ③ 太陽が高い（仰角約 55°）と太陽側 1 タップの遮りがほぼ効かず真っ白 → 上面を高さ場 H = 最高点 − 深さ×補正値/ノイズ と見て、ノイズの勾配から法線（ラップ 0.3）＋谷の暗さ（こぶの高さの範囲の下ほど暗い）④ 奥の重ねが 6m 刻みでは半透明すぎて空が透けた → 30m 刻み。既定値：深さ 160 / 補正値 0.22 / 乗算値 3 / noiseFloor 0.3 / 影色（線形）0.10, 0.22, 0.52。
- **3 回目（2026-10-10 実機）：真下はもこもこで良いが、水平方向は線が走ってギザギザ**。斜めのレイは等間隔の 1 歩が百 m 以上になり、輪郭が歩幅で階段になっていた（CPU 版で再現）。上面を高さ場 H として**高さ場トレース**（面との高さの差 ÷（下向きの傾き＋面の最大傾斜 traceSlope 0.35）だけ進む＝飛び越えない、48 歩）に変更。縦穴に当たったら穴の底へ等比で歩き続ける。等間隔の歩き・帯の底で止める処理は廃止。
- **4 回目（2026-10-10 実機）：形はまあまあ、ただ全体が水色**。空気遠近が下向きのレイの方向で cubemap を引いて下半分の青を拾っていた → 水平線（dir.y を 0.02 以上に）の色へ寄せる。既定値も白寄りに（影色 0.30, 0.38, 0.55 / valley 0.7 / haze 3000〜15000m・最大 0.5）。
- **5 回目（2026-10-10 実機）：まだ青い。こぶの上が青く下が白い（太陽は上なので逆のはず）**。陰影ではなく透け：透明度をレイの向きに奥を見て決めていたので、水平に近い視点でこぶの上の縁をかすめる所が半透明になり、止めたレイの後ろ（cubemap の水平線より下の濃い青）が透けていた（CPU 版で背景を青にして再現）。→ 透明度は**面の高さから真下へ**雲の中を測る。遠くのフェードも透明にせず水平線の空の色へ溶かし、最大距離まで当たらなかった下向きのレイは水平線の色で埋める。
- **6 回目（2026-10-10 実機 GIF）：雲を抜ける所で画面がほぼ真っ白**。原因 2 つ（CPU 版に縦穴とレール上のカメラ `--at-sec` を足して確認）：① 縦穴の壁・下面も上を向いた面として照らしていた → `GetSurfaceFrame`：壁は中心線へ向く法線＋深いほど暗い（`shaftDarkness`）、下面は下向き（`undersideBright`）。透明度も法線の逆（雲の中）へ測る ② B' が帯より下の詰まった中身まで積み上げ、模様の無い白い壁になっていた → B' は面の前後 ±`fringeWidth` の縁だけを 3D ノイズでちぎって積み上げ、中身に入ったらゼノブレ式の面に切り替える（入口・出口のもわもわ）。残り：壁がのっぺり（揺れのノイズが縦筋）・穴の縁が透ける・降下中のラジアルブラー・プレイヤーが白くて雲に埋もれる。
- **7 回目（実機）：降下中に何も見えない（画面全体が灰色一色・プレイヤーも見えない）**。縦穴を `Initialize` でレールの初期化直後に拾っていたが、その時点のレールは既定の仮の形で、本物（シーン JSON の CameraPath）はその後のシーン読み込みで差し替わる → 穴が降下ルートとずれ、カメラが雲の中身を突っ切っていた。`StagePlayScene::RebuildCloudShaft()` を `OnAfterSceneLoad` の `RebindCameraPath` の直後で呼ぶ（自動再読み込みでも追従）。CPU 版はシーン JSON のレールを直接読むので再現しなかった。
- **8 回目（実機）：縦穴の中に雲感が無い（しっくいの洞窟）・上から穴が丸見え** → ユーザー方針「穴を隠すために高品質のレイマーチを使う」。① **ふた**：くり抜きを上面から `capTop` 60m・下面から `capBottom` 100m の間は空けない（下は bottomFade 40m に食われるので厚め）→ 上からは普通の雲海 ② **B' は中身も積み上げる**（ふたの中・縦穴の中は重み 1、入口・出口の 80〜250m で切り替え）。濃さ = 面の濃さ × saturate((3D ノイズ − erosion 0.5) × 4)＝塊と隙間がはっきり分かれる。勾配ノイズ 2 オクターブは 0.41〜0.59 に固まるので ×4.6 で 0..1 に広げる（`kErosionContrast`、CPU 版で分布を測定）。光側の消散 ×4（`lightExtinction`）。CPU 版に B' と 3D ノイズ（シェーダと同じ成分 −1..1 の勾配）を足して確認。残り：壁の見た目・縦穴の奥の中心の点・全体の灰青み・重さの計測・ラジアルブラー。
- **9 回目（実機）：まだ上から穴が分かる・穴の壁が良くない**（ユーザーがゼノブレ2の資料「雲海に穴を空けて」「雲海を縦にも配置可能に」を提示）。① ふたを最高点から測っていた → 上面が低い所で穴が開いた。**天井＝その場所の上面 − capTop** に。さらに透明度を奥へ測るとふたを突き抜けて穴が透けた → **面に当たったら不透明**（遠くは水平線の色へ溶かす）。② 壁を「半径をノイズで揺らした円柱」にしていた → しっくいの筒。**穴の外側の雲を雲海の式で 3 方向に作る**（`HoleOver`）：壁＝中心線から外へ濃い横向きの雲海（ノイズは ZY/XY 面を壁の向きで混ぜる＝継ぎ目なし）、天井＝上ほど濃い下向き、床＝下ほど濃い上向き。穴の中のノイズは `shaftNoiseScale` 0.25 倍に細かく。縦穴のまわりの法線は濃さの式の中心差分。旧パラメータ（壁の揺れ・ふたのぼかし・透明度の奥行き）は廃止。
- **10 回目（実機）：穴は隠せた。ふたの色が少し違う／抜ける前に白い板**。ふた＝穴の陰影（深さの暗さ・傾きの法線）を上面にまで掛けていた → 天井より下だけに。白い板＝穴の床の上面が B' の範囲（300m）の外で硬い面として太陽に照らされていた（川の白飛びとは別）→ `volumeRange` 500m で床まで B'、穴の暗さは天井→床の深さで（床で最大、`shaftDarkness` 0.6）。床は B' で塊と隙間に崩れるので、抜ける前から下が透けて見え始める。
- **11 回目（実機コマ送り）：ふたは完璧。ただ下を向いた後に画面が白いもやで覆われ、通り抜けてる感が無くなった（前の円柱の方が見通し・敵の視認性が良く、邪魔なのは板だけ）** → `volumeRange` を 300m に戻し、縦穴の中の B' は `volumeShaftWeight` 0.5（手前 150m＝壁の手前のもやだけ）。板は床の陰影（深いほど暗い）で消す。床に 150m まで近づいてから床のふたのもやを抜ける。
- **12 回目（パルテナと比較）：抜け切る前の真っ白が長い（58.25→61.75 秒で約 3.5 秒）＋白いプレイヤーが同化して味気ない** → 下のふた 100→35m・bottomFade 40→15m・縦穴の中の B' 0.5→0.2（手前 60m）・入口/出口の B' 切り替え 80〜250→40〜120m で白い区間を約 1 秒に。雲の中の明るさの下限 `ambientStrength` 0.35→0.15・powder 4→6 で塊の奥を灰青に沈める。床が薄くなり、抜ける前に雲の切れ間から下界が見える。保留（演出の担当）：プレイヤーの輪郭線（Scene::AddHighlight＋MaskedOutline）、降下中のラジアルブラー（RadialBlurEffect）。
- **13 回目（実機）：降下開始で床から地形が透ける・56 秒ごろまだらなノイズ・60〜64 秒が真っ白**。① 床の式が「床の高さから下へ capDepth で濃く」だったので、ふた 35m < capDepth 60m で濃さが足りず隙間だらけ → 床の高さより下は詰まった雲、こぶは上へ capDepth で盛り上がる形に ② B' の塊の縁が硬い（erosionSharp 4→2） ③ 60〜64 秒の白は**雲ではなく区間 `CloudLayer`（54〜66 秒）のフォグ**（近 20m／遠 220m／濃さ 2。レイマーチ前の雲の中の仮表現）。雲を抜けた後も地形・水面を白く塗っていた → L5（区間の担当）へ。
- **14 回目（実機）：底は良い。4 秒の真っ白を 0.5 秒くらいに** → ① 区間 `CloudLayer` のフォグを LowAltitude と同じ値に（ユーザー指示。11 §3.4 で L5 へ連絡） ② 床：詰まった雲 `capBottom` 35→10m、こぶ `floorDepth` 25m（天井の capDepth 60m と分けた）。カメラは毎秒約 75m 落ちるので白い区間 35m ≒ 0.5 秒 ③ 出口の B' の切り替えを入口と分けて `exitZoneInner/Outer` 0〜30m（入口は 40〜120m のまま）。CPU 版では 60〜60.9 秒が灰色の床、61.25 秒で抜ける。
- **15 回目（実機）：短くなった。床の切れ間が硬い円の縁** → `exitZoneOuter` 30→100m（床が B' のもやとしてほどけて消える。白い時間は延びない）。出口の「もわっ」はレイマーチでなくエフェクト（カメラの周りから煙の板を上へ流す）で出す方針（L7、未着手）。
- B' はカメラと入口・出口の距離で重み（`volumeZoneInner/Outer`）を CPU が決め、手前 `volumeRange × 重み` だけ積み上げて先はゼノブレ式で続ける（画面全体で同じ分岐＝ピクセルごとに割れない）。3D ノイズはまずシェーダの計算（勾配ノイズ 2 オクターブ）。
- 1/2 解像度（`resolutionScale`）の RGBA16F に乗算済みで描き、水面の後・Primitive の前に ONE / INV_SRC_ALPHA で重ねる。深度は PSR に遷移して読み、終わったら DEPTH_WRITE に戻して RT/DSV を貼り直す。
- 所有は `StageEnvironment`（遠景の雲と同じ。L5 が `GetCloudRaymarcher()->GetParams().opacity` で消す）。パラメータは `Tuning/StagePlay.json` の `raymarchClouds`、ImGui は「Raymarch Clouds」。
- 計測：区間 `CloudRaymarcher::March` / `::Composite`、起動引数 `--no-raymarch-clouds`、`run_cloud_bench.py --preset stage-raymarch`（0 / 53 / 60 秒で止めて雲海あり・なし）。
- 2026-10-09 実装（ビルド・実機未確認、シェーダは dxc 単体 OK）。ファイル：`GameEngine/Graphics/Cloud/CloudRaymarcher.*`、`Resources/Shaders/Cloud/CloudRaymarch.hlsli`・`CloudRaymarch.PS.hlsl`・`CloudComposite.PS.hlsl`。
