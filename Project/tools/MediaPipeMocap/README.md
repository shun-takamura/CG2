# MediaPipeMocap

> **このフォルダについて**
> MediaPipeMocap は本エンジンとは独立した単体プロジェクトです。
> 本体リポジトリ: https://github.com/shun-takamura/MediaPipeMocap
> ここに置いてあるのはソースのスナップショット（実行ファイルは容量の都合で未同梱）。
> 本エンジンとは glTF / `.skel`+`.anim` 経由で繋がります。

Web カメラや動画ファイルから MediaPipe Pose で人の動きを推定し、
ボーンアニメーションとして書き出すスタンドアロンツール。

外部の3DCGツール（Blender等）や各種ゲームエンジンにそのまま持っていける
標準形式（glTF）で出力するので、特定のエンジンに依存しません。

## ダウンロード

- **Windows・すぐ使いたい方**: [Releases](https://github.com/shun-takamura/MediaPipeMocap/releases) から `MediaPipeMocap-win.zip`
  をダウンロードして展開し、`MediaPipeMocap.exe` を実行（Python不要）
  - 展開先に **`MediaPipeMocap-blender-addon.zip`** が同梱されています。
    Blender アドオン版を使う場合はこれをそのままインストールしてください
- **ソースから実行したい方**: 下記「セットアップ」を参照

## セットアップ

**対応 Python バージョン: 3.9〜3.13**（mediapipe が対応している範囲。
最新すぎる Python だと mediapipe の wheel がまだ無いことがあるので、
`pip install` が失敗する場合は 1 つ前のバージョンを試してください）。

```
pip install -r requirements.txt
python main.py
```

または `run.bat` をダブルクリック（`py` ランチャーがあれば `py -3`、無ければ
`python` を自動的に使う）。

※ 複数の Python がインストールされている環境で `pip install` した Python と
実行する Python が食い違うと、mediapipe が見つからずエラーになります。
起動時にエラーダイアログが出た場合は、そこに表示される `sys.executable` を
確認してください。
※ 初回実行時に姿勢推定モデル (`models/pose_landmarker_full.task`, 約9MB) を
自動ダウンロードする。

## 使い方

1. 入力ソースを選ぶ
   - **Web カメラ**: 「検出」でカメラを列挙してから選択 →「録画開始」→ 動く →
     「停止」（またはプレビューで Q キー）
   - **動画ファイル**: ファイルを選んで「処理開始」（全フレーム自動処理。
     途中で「停止」を押せばそこまでのフレームで打ち切れる）
2. 出力形式を選んで「保存…」
   - **glTF (.gltf + .bin + .png)** — 汎用。Blender や各種エンジンで読める。
     棒人間の代用スキンメッシュを同梱するので、そのままスキニング再生できる。
   - **PRISMEngine (.skel + .anim)** — PRISMEngine のネイティブ形式を直接出力。
     メッシュは含まない。

## Blender 連携

このツールには2種類のBlender連携があります。

### A. スタンドアロンアプリ → Blenderへ送信

キャプチャ結果やリターゲット結果を、保存せずワンクリックで Blender に
インポートして確認できます。メイン画面／リターゲット画面の
**「Blenderで確認」** ボタンを押すだけです。

- **Blender を開いていない場合**: アプリが自動で Blender を起動して
  インポートします（アドオンの事前インストールは不要）。
- **いつも開いている Blender に送りたい場合**（任意）: 下記Bのアドオンを
  一度インストールしておくと、起動中の Blender セッションへ直接送れます。

送信のたびに前回のプレビューは自動で置き換わり、ボーンの向きも
自動補正（Bone Dir: Fortune）されるので、巨大な球は表示されません。

Blender が標準以外の場所にインストールされている場合は、`settings.json` の
`blender_path` に `blender.exe` のフルパスを指定してください。

### B. Blenderアドオン — キャプチャ・リターゲットをBlender内で完結

スタンドアロンアプリを使わず、**Blenderのビューポート内でキャプチャからリターゲットまで完結**できます。

**導入**:
1. `MediaPipeMocap-blender-addon.zip` を、Blender > 編集 > プリファレンス >
   アドオン > 右上「インストール」からインストールして有効化
   （zip の入手先: `MediaPipeMocap-win.zip` を展開したフォルダの中、
   または [Releases](https://github.com/shun-takamura/MediaPipeMocap/releases)、ソースからなら `python build_addon.py` で生成）
2. 有効化直後は依存関係（mediapipe / opencv-python）が未インストールです。
   同じ Preferences 画面に出る **「依存関係をインストール」** ボタンを押す
   （数分かかります。Blender内蔵Pythonへ、Program Files を汚さずに
   個別インストールするので管理者権限は不要です）

**使い方**（3Dビューポートのサイドバー「MoCap」タブ）:
- **Webカメラでキャプチャ**: 「Webカメラで開始」→ ビューポート右下に
  プレビュー（骨格オーバーレイ付き）が表示される → 「停止」（または ESC）
- **動画ファイルでキャプチャ**: 動画ファイルを「MoCap」パネル上に
  ドラッグ&ドロップするだけ
- 停止すると自動で `rig.solve()` → シーンへ棒人間として直接インポートされます
  （ネットワーク不要）。同時に `.mocapdata.json` も一時フォルダに保存され、
  後述のリターゲットや、スタンドアロンアプリ側での再利用もできます
- **シーン内リターゲット**: 「MoCap」パネルのリターゲット欄で、
  ターゲットのアーマチュア（シーン内の既存モデル）を選択し、ソース
  （直前のキャプチャ or `.mocapdata.json`）とバインドポーズ（T/A/補正なし）を
  指定して「リターゲット実行」。Blender標準のキーフレームとして
  直接アーマチュアへ焼き込まれます

  **ボーンマッピング**:
  - **「名前から推測」** ボタンでボーン名から自動割当（Mixamo標準リグなら21個全て埋まります）
  - 推測できない独自の命名規則のリグでも、**21ジョイントの表から手動で割り当て**られます
    （各行のドロップダウンで検索・選択。空欄なら未割当＝そのボーンは動きません）
  - 各行の **ひねり補正** で、曲がる方向がおかしいボーンを個別に調整できます
  - **保存 / 読込** でマッピングを `.retarget.json` として再利用できます
    （スタンドアロンアプリと同じ形式なので相互に使い回せます）

## リターゲット（キャラクターモデルへの適用）

キャプチャした動きを、ボーン入りのキャラクターモデル（.gltf）に転写できます。

1. キャプチャ後（または「保存…」で出力される `.mocapdata.json` を後から読み込んで）、
   メイン画面の「リターゲット…」を押す
2. ターゲットモデルの `.gltf` を読み込む（Blender で
   「glTF Separate (.gltf + .bin)」形式でエクスポートしたもの。.glb は非対応）
3. 「名前から推測」でマッピング候補を出し、内容を確認・修正する
   （Mixamo 標準リグなら 21 ジョイント全て自動で埋まります）
4. 出力形式を選ぶ:
   - **.anim 単体** — PRISMEngine 向け。ターゲットの既存 .skel と組で使う
   - **統合 .gltf** — モデルのメッシュ・マテリアルごと 1 セット出力。
     Blender や他エンジンにそのまま持っていける

補足:
- **ターゲットモデルのバインドポーズ**を選択できます:
  - **Tポーズ**（Mixamo・UE系など、腕が真横）— 既定
  - **Aポーズ**（VRoid系など、腕が斜め下）— 腕下げ角度を指定（既定45°）
  - **補正なし** — 動画の最初のフレームの姿勢をモデルのバインドに直接対応させる
    （撮影開始時にモデルと同じポーズを取れる場合向け）
- マッピングは「マッピング保存…」で `<モデル名>.retarget.json` として保存でき、
  同じモデルを読み込むと自動で読み込みを提案します
- 未割当のボーン（指など、ソース側に対応が無い部位）はバインドポーズのまま
  固定されます（壊れない・意図した挙動）
- ボーンのロール軸がズレて曲がる方向がおかしい場合は、各行の「ひねり補正°」で
  ボーン軸まわりの回転角を手動調整してください
- ルート移動量はソース（メートル）とターゲットのスケール差を
  Hips↔Head 距離比で自動補正します（手動上書き可）

## キーフレーム削減

モーキャプは全フレームにキーが打たれるため、そのままだとポーズの手直しが
困難です（1フレーム直しても隣のキーに戻される）。**補間で再現できる不要な
キーだけを自動削除**して、編集しやすくできます。

- **許容誤差（度）** を指定すると、「その角度以内の差なら補間で代用できる」
  キーを削除します。動きの激しい区間はキーが残り、静止・等速の区間は大きく減ります
- 実測例: 許容誤差 1° で **4326 → 1378 キー（約32%）** に削減、
  元の動きからのズレは最大 1.3° 程度

使える場所:
- **Blenderアドオン**: 「シーン内リターゲット」の *キーを削減する* オプション、
  または「キー削減」ボタン（既存アクションに後から適用。リターゲット済みに限らず使えます）
- **スタンドアロンアプリ**: メイン画面の *キー削減* チェック（glTF/.anim 出力に適用）、
  リターゲット画面にも同様のオプション

補足:
- クォータニオンを4成分まとめて1つの回転として評価します。Blender標準の
  デシメートはF-Curveのチャンネルを独立に間引くため、w/x/y/zがバラバラに
  削られて微妙な揺れが出ることがありますが、その問題が起きません
- 削減したキーは**リニア補間**になります（既定のベジェはキー間で
  オーバーシュートし、実際の誤差が指定値の2〜3倍に膨らむため）
- `.mocapdata.json`（リターゲット用の中間データ）は**削減されません**。
  後からリターゲットする際は常に元の精度で計算されます

## PRISMEngine への取り込み（glTF 経由・推奨）

1. 出力した `<name>.gltf` / `<name>.bin` / `white.png` を
   `CG2_0_1/Project/Assets/Models/Mocap/<name>/` にコピー
2. `cd Project && python tools/Python/cook_assets.py`
3. `Resources/Models/Mocap/<name>/` に `.mesh` / `.skel` / `.mat` / `.anim` が生成される
4. `AnimatedModelInstance` で通常のアニメーション付きモデルとして読み込める

## スケルトン構成（21 ジョイント）

```
Hips ─ Spine ─ Chest ─ Neck ─ Head
  │              ├─ LeftClavicle ─ LeftShoulder ─ LeftElbow ─ LeftWrist
  │              └─ RightClavicle ─ RightShoulder ─ RightElbow ─ RightWrist
  ├─ LeftUpLeg ─ LeftKnee ─ LeftAnkle ─ LeftToe
  └─ RightUpLeg ─ RightKnee ─ RightAnkle ─ RightToe
```

Neck / Clavicle は MediaPipe に対応ランドマークが無いため、Chest から
鼻・肩ランドマークへの内分点として合成している（`rig.py` の
`NECK_LERP_T` / `CLAVICLE_LERP_T`）。実測ではない近似値。

## 制約・コツ

- **バインドポーズ = 録画の最初のフレーム**。録画開始時は正面を向いて
  手足を軽く広げて立つ（A ポーズ気味）ときれいに出ます。
- 単眼カメラ推定のため **ひねり（twist/roll）は取れません**。
  ボーン方向の一致（swing）のみ再現します。胴体（Hips/Chest）だけは
  左右の肩・腰のラインから向きを推定するためひねりも入ります。
- 深度（前後方向）の精度は粗めです。カメラに対して大きく前後する動きは
  ブレやすいので、Blender 等での事後調整を想定してください。
- 全身がフレームに収まっていないフレームは自動でスキップされます。
- プレビューウィンドウは端をドラッグしてリサイズ・移動できます。位置とサイズは
  自動保存され、次回も同じ状態で開きます。

## 開発者向け: exe ビルド

```
pip install -r requirements.txt
pip install pyinstaller
python build_exe.py
```

`dist/MediaPipeMocap/` にフォルダ一式（exe + DLL + モデル保存用ディレクトリ）
が生成される。配布時はこのフォルダごと zip にする。

`--onedir` 形式を採用している（`--onefile` は毎回一時フォルダへ展開されるため、
姿勢推定モデルの自動ダウンロード先が実行のたびに変わってしまい相性が悪い）。
